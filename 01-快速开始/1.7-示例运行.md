# 1.7 示例运行

## 1. 前置条件

按 [1.6 构建编译](1.6-构建编译.md) 完成 SDK 源码获取和基础环境配置。以下命令在 K1 设备上执行，SDK 目录以 `~/spacemit_robot` 为例。

语音交互功能需搭配音频输入与输出设备使用，例如 USB 麦克风和扬声器。使用摄像头实时检测时，还需连接摄像头并提供可用的图形显示环境。

新开终端后，先在 SDK 根目录加载环境并选择 K1 方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

以下以视觉目标检测为例，演示编译与运行流程。

### 2.1 一键编译

```bash
cd ~/spacemit_robot/components/model_zoo/vision
mm
```

### 2.2 快速运行

在视觉组件目录下载模型和测试资源：

```bash
bash examples/yolov8/scripts/download_models.sh
bash scripts/download_assets.sh
```

示例配置默认使用 `num_threads: 8`。K1 使用 4 个推理线程，运行前修改配置；Python 与 C++ 共用该 YAML，无需重新编译。推理线程数不代表设备的 CPU 总核数。

```bash
sed -i.bak 's/num_threads: 8/num_threads: 4/' \
    examples/yolov8/config/yolov8.yaml
```

`sed -i.bak` 会将修改前的配置保存为同名 `.bak` 文件。运行检测：

```bash
yolov8 examples/yolov8/config/yolov8.yaml
```

程序在终端打印检测结果，并将标注图像保存为当前目录下的 `result.jpg`。

（可选）使用摄像头进行实时检测。先查看设备：

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video20 -D
```

`v4l2-ctl` 由 `v4l-utils` 软件包提供。以下以 `/dev/video20` 为例，确认该节点的 **Device Caps** 包含 `Video Capture`，并将 `20` 替换为实际摄像头编号；仅支持 `Metadata Capture` 的节点不能用于图像采集。

```bash
yolov8 examples/yolov8/config/yolov8.yaml --use-camera --camera-id 20
```

按 `q` 退出，按 `s` 保存当前帧。该示例会创建 OpenCV 窗口，需在图形桌面终端运行；通过 SSH 运行时，PC 需有可用的 X 服务，并从 PC 使用 `ssh -Y <用户名>@<K1_IP>` 建立 X11 转发连接，再加载 SDK 环境。`DISPLAY` 由 SSH 自动设置。

## 3. 语音交互

本节以 Omni Agent 为例，演示语音交互功能的编译与运行。采用本地 Qwen2.5 LLM、SenseVoice 语音识别和 Matcha-TTS 中英双语合成。

### 3.1 一键编译

在 SDK 根目录加载环境并选择 K1 方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

K1 本地语音交互使用 SenseVoice 的 CPU 后端。在 `application/native/omni_agent/src/engine_init.cpp` 的 `initASR(...)` 中，将以下配置放在 `AsrConfig::Preset(engine)` 成功读取之后、创建 `AsrEngine` 之前。源码中已有该配置时无需重复添加。

```cpp
if (engine == "sensevoice") {
    asr_config.provider = "cpu";
}
```

此配置仅指定 SenseVoice 的推理后端；本地 LLM 仍使用 llama.cpp 的 SpaceMIT 后端。配置完成后执行编译：

```bash
m
cd application/native/omni_agent
mm --with-deps
```

`m` 构建当前 K1 方案选中的组件；`mm --with-deps` 补充构建 Omni Agent 及其声明的依赖。生成的 `voice_chat` 安装到 `output/staging/bin`，加载 SDK 环境后可直接调用。

### 3.2 快速运行

下载模型资源：

```bash
mkdir -p ~/.cache/models/llm
cd ~/.cache/models/llm
# 示例下载 Qwen2.5 0.5B 模型
wget -nc https://archive.spacemit.com/spacemit-ai/model_zoo/llm/qwen2.5-0.5b-instruct-q4_0.gguf
```

启动 LLM 服务，K1 使用 4 个推理线程：

```bash
llama-server -m ~/.cache/models/llm/qwen2.5-0.5b-instruct-q4_0.gguf -t 4 --port 8080
```

保持该终端运行，等待模型加载完成。在 K1 的另一个终端重新加载 SDK 环境：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

检查服务状态和模型名称：

```bash
curl http://localhost:8080/health
curl http://localhost:8080/v1/models
```

`/health` 返回 `{"status":"ok"}` 后启动语音对话；`--model` 应与 `/v1/models` 中的模型 ID 一致：

```bash
voice_chat --llm-url http://localhost:8080 \
    --model qwen2.5-0.5b-instruct-q4_0.gguf \
    --tts matcha:zh-en --asr-engine sensevoice
```

SenseVoice、Silero VAD 和 Matcha-TTS 会检查本地模型缓存，缺少资源时自动下载，首次启动需保持网络可用。初始化完成并显示“等待语音输入”后，即可对着麦克风说话；按 `Ctrl+C` 退出。

上述命令使用默认音频设备。需要指定设备或调整采样格式时，先查看列表：

```bash
voice_chat --list-devices
```

根据实际设备的输入、输出编号和支持格式添加音频参数。例如，输入设备 `0` 支持 16 kHz 单声道、输出设备 `1` 支持 48 kHz 双声道时，可使用：

```bash
voice_chat --llm-url http://localhost:8080 \
    --model qwen2.5-0.5b-instruct-q4_0.gguf \
    --tts matcha:zh-en --asr-engine sensevoice \
    --input-device 0 --output-device 1 \
    --capture-rate 16000 --capture-channels 1 \
    --playback-rate 48000 --playback-channels 2
```

设备编号可能随插拔或重启变化，应以设备列表为准。使用结束后，在 LLM 服务终端按 `Ctrl+C` 停止服务。
