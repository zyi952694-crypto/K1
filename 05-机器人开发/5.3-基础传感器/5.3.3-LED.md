# 基础传感器 · LED

## 1. 模块概述

- 主要功能：LED 模块位于机器人开发层的基础传感器能力中，对下封装 `components/peripherals/led` 用户态 LED 组件，对上提供 ROS 2 节点 `led_node`。模块用于统一控制板载 sysfs 指示灯和 SPI WS2812 灯带，并向上层提供颜色、亮度、常亮、闪烁和呼吸三类控制能力。
- 规格或特性：命令输入为 `peripherals_led_node/msg/LedCommand`，默认话题 `/led/command`；状态输出为 `peripherals_led_node/msg/LedState`，默认话题 `/led/state`。当前支持 `mode=0/1/2`，分别表示 `STATIC / BLINK / BREATH`；节点默认以 `50 ms` 周期调用底层 `led_tick()`，以 `100 ms` 周期发布状态；单个节点可同时管理多路 LED，支持 `generic` 和 `spi` 两种传输类型。状态话题使用 `reliable + transient_local` QoS，新订阅者启动后可立即拿到最近状态。

## 2. 环境准备

### 前置条件

- 运行环境：K1 MUSE Pi Pro 开发板，Bianbu 2.3.5，Linux 6.6.63，ROS 2 Humble；
- 硬件与连接：板载 sysfs 指示灯（如 `sys-led`）或 SPI WS2812 灯带。K1 MUSE Pi Pro 的 SPI3 需启用后才会出现 `/dev/spidev3.0`，具体配置参考 [6.2.9 LED](../../../06-进阶开发/6.2-外设与驱动/6.2.9-LED.md)；
- 工具与权限：访问 `/dev/spidev*` 或 `/sys/class/leds/*` 需要权限，如权限不足使用 `sudo`。

### 构建编译

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-minimal

cd ~/spacemit_robot/middleware/ros2/peripherals/led

```

构建完成后产物位于：

```text
~/spacemit_robot/output/staging/lib/peripherals_led_node/led_node
~/spacemit_robot/output/staging/share/peripherals_led_node/params/led_node.yaml
```

### K1 参数配置

K3 默认参数使用 `generic` 的 `sys-led`，K1 若使用 WS2812 灯带需要改为 `spi` 配置。在参数文件目录创建 `led_node_k1.yaml`：

```yaml
led_node:
  ros__parameters:
    frame_id: "led"
    command_topic: "led/command"
    state_topic: "led/state"
    tick_period_ms: 50
    publish_period_ms: 100
    publish_on_command: true
    publish_on_startup: true

    led_ids: [0]
    transports: ["spi"]
    names: ["ws2812_strip"]

    spi_dev_paths: ["/dev/spidev3.0"]
    spi_num_leds: [4]
    spi_speed_hz: [6400000]
    spi_reset_bytes: [80]
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `led_ids` | 逻辑 LED ID，必须唯一 |
| `transports` | 传输类型，`"generic"`（sysfs）或 `"spi"`（WS2812） |
| `names` | 设备名，用于日志和 sysfs 匹配 |
| `generic_sysfs_names` | sysfs LED 名称，对应 `/sys/class/leds/` 下的目录名 |
| `generic_active_levels` | sysfs LED 有效电平，`0` 或 `1` |
| `spi_dev_paths` | SPI 设备节点，如 `/dev/spidev3.0` |
| `spi_num_leds` | 灯珠数量（WS2812 串联颗数） |
| `spi_speed_hz` | SPI 时钟频率，WS2812 通常用 `6400000` |
| `spi_reset_bytes` | 复位字节数，通常 `80` |

使用板载 sysfs LED（`sys-led`）时，改用下面配置：

```yaml
    led_ids: [0]
    transports: ["generic"]
    names: ["sys-led_1"]
    generic_sysfs_names: [""]
    generic_active_levels: [0]
```

## 3. 示例使用（从 0 跑通）

### 3.1 启动 LED 节点并观察状态

**步骤 1**：加载运行环境。

```bash
source /opt/ros/humble/setup.bash
source ~/spacemit_robot/output/staging/setup.bash
```

**步骤 2**：启动 LED 节点。

```bash
ros2 run peripherals_led_node led_node \
  --ros-args \
  --params-file ~/spacemit_robot/output/staging/share/peripherals_led_node/params/led_node_k1.yaml
```

预期现象：

```text
[INFO] [led_node]: led_node ready: command_topic=led/command state_topic=led/state leds=1 tick_period_ms=50 publish_period_ms=100
```

**步骤 3**：另开终端订阅状态话题。

```bash
source ~/spacemit_robot/output/staging/setup.bash
ros2 topic echo /led/state
```

预期输出（初始关闭状态）：

```yaml
header:
  frame_id: led
led_id: 0
r: 0
g: 0
b: 0
brightness: 0
mode: 0
is_on: false
---
```

### 3.2 控制常亮颜色

发送常亮红灯命令：

```bash
ros2 topic pub --once /led/command peripherals_led_node/msg/LedCommand \
  "{header: {frame_id: 'led'}, led_id: 0, r: 255, g: 0, b: 0, brightness: 128, mode: 0, period_ms: 0, on_ms: 0, count: 0}"
```

预期现象：灯带变为红色，`/led/state` 同步更新：

```yaml
led_id: 0
r: 255
g: 0
b: 0
brightness: 128
mode: 0
is_on: true
```

发送常亮绿灯命令：

```bash
ros2 topic pub --once /led/command peripherals_led_node/msg/LedCommand \
  "{header: {frame_id: 'led'}, led_id: 0, r: 0, g: 255, b: 0, brightness: 128, mode: 0, period_ms: 0, on_ms: 0, count: 0}"
```

预期现象：灯带变为绿色，状态中 `g=255`。

### 3.3 控制闪烁与呼吸

闪烁命令（5 次白色闪烁，周期 1000 ms，亮 200 ms）：

```bash
ros2 topic pub --once /led/command peripherals_led_node/msg/LedCommand \
  "{header: {frame_id: 'led'}, led_id: 0, r: 255, g: 255, b: 255, brightness: 255, mode: 1, period_ms: 1000, on_ms: 200, count: 5}"
```

呼吸命令（蓝色呼吸，周期 2000 ms）：

```bash
ros2 topic pub --once /led/command peripherals_led_node/msg/LedCommand \
  "{header: {frame_id: 'led'}, led_id: 0, r: 0, g: 0, b: 255, brightness: 128, mode: 2, period_ms: 2000, on_ms: 0, count: 0}"
```

预期现象：灯带进入闪烁或呼吸效果，`/led/state` 中 `brightness` 和 `is_on` 随状态机变化。

## 4. 应用开发

上层应用通过 `/led/command` 发布 `peripherals_led_node/msg/LedCommand` 控制 LED，通过 `/led/state` 订阅 `peripherals_led_node/msg/LedState` 获取当前状态。

**LedCommand 字段**：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `led_id` | `int32` | 目标 LED ID |
| `r` / `g` / `b` | `uint8` | RGB 颜色分量，0~255 |
| `brightness` | `uint8` | 亮度，0~255 |
| `mode` | `uint8` | `0=STATIC 1=BLINK 2=BREATH` |
| `period_ms` | `uint32` | 闪烁/呼吸周期（ms） |
| `on_ms` | `uint32` | 闪烁模式下点亮时长（ms） |
| `count` | `uint32` | 闪烁次数，`0` 表示无限 |

**LedState 字段**：`led_id`、`r`、`g`、`b`、`brightness`、`mode`、`is_on`。

注意点：SPI 实现会把整条灯带刷成同一种颜色和亮度，不支持按单颗灯珠分别控制；闪烁模式下状态亮度在 `255/0` 间切换，命令中的 `brightness` 不参与闪烁亮度计算。

## 5. 调试指南

- 节点启动报 `led alloc failed`：检查 `spi_dev_paths` 指向的设备节点是否存在（`ls -l /dev/spidev*`），以及 `transports` 是否与实际硬件匹配；
- WS2812 不亮：先跑底层测试确认硬件通路 `test_led_ws2812 /dev/spidev3.0 4 grb 6400000 80`，再排查 ROS 2 参数；
- `/led/state` 无数据：确认订阅端 QoS 与发布端兼容，状态话题使用 `transient_local`，可在节点启动后再订阅；
- 颜色不对：WS2812 常见 `grb` 顺序问题，底层测试程序支持 `grb` / `rgb` 参数，ROS 2 节点使用默认顺序。

## 6. 常见问题

- `No such file or directory` 打开 `/dev/spidev2.0` 失败：K3 默认参数是 `spidev2.0`，K1 需要改为实际存在的 `spidev3.0`；
- 灯带只亮第一颗：`spi_num_leds` 配置的颗数小于实际串联颗数，按实际灯珠数修改；
- 灯带颜色跳动或闪烁不稳：降低 `spi_speed_hz` 或增大 `spi_reset_bytes`。
