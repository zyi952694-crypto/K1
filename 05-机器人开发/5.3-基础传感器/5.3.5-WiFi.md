# 基础传感器 · WiFi

## 1. 模块概述

- 主要功能：WiFi 模块位于机器人开发层的基础传感器能力中，对下封装 `components/peripherals/wifi` 基于 NetworkManager 的 WiFi 组件，对上提供 ROS 2 节点 `wifi_node`。模块用于统一管理 STA 模式下的扫描、连接、断开和状态广播，并向上层提供 WiFi 当前连接状态和扫描结果。
- 规格或特性：当前节点采用"状态话题 + 命令服务"的混合接口。状态输出为 `peripherals_wifi_node/msg/WifiStatus`，默认话题 `/wifi/status`；扫描结果输出为 `peripherals_wifi_node/msg/WifiScanResults`，默认话题 `/wifi/scan_results`；连接服务为 `peripherals_wifi_node/srv/WifiConnect`，默认服务 `/wifi/connect`；断开服务为 `std_srvs/srv/Trigger`，默认服务 `/wifi/disconnect`；扫描服务为 `peripherals_wifi_node/srv/WifiScan`，默认服务 `/wifi/scan`。默认状态发布周期为 `2000 ms`，默认不启用周期扫描。

## 2. 环境准备

### 前置条件

- 运行环境：K1 MUSE Pi Pro 开发板，Bianbu 2.3.5，Linux 6.6.63，ROS 2 Humble；
- 依赖：底层依赖 NetworkManager（`nmcli`），系统默认已安装；
- 工具与权限：节点通过 `nmcli` 调用 NetworkManager，需要具备 WiFi 管理权限，通常以 root 或具备 NM 权限的用户运行。

### 构建编译

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-minimal

cd ~/spacemit_robot/middleware/ros2/peripherals/wifi
mm
```

构建完成后产物位于：

```text
~/spacemit_robot/output/staging/lib/peripherals_wifi_node/wifi_node
~/spacemit_robot/output/staging/share/peripherals_wifi_node/params/wifi_node.yaml
```

### 参数配置

K1 与 K3 使用相同的默认参数文件，无需修改：

```yaml
wifi_node:
  ros__parameters:
    frame_id: "wifi"
    status_topic: "wifi/status"
    scan_topic: "wifi/scan_results"
    connect_service: "wifi/connect"
    disconnect_service: "wifi/disconnect"
    scan_service: "wifi/scan"
    enable_on_startup: true
    auto_reconnect: true
    status_period_ms: 2000
    scan_period_ms: 0
    scan_on_startup: false
    scan_max_results: 32
    scan_ssid: ""
```

## 3. 示例使用（从 0 跑通）

### 3.1 启动 WiFi 节点并观察连接状态

**步骤 1**：加载运行环境。

```bash
source /opt/ros/humble/setup.bash
source ~/spacemit_robot/output/staging/setup.bash
```

**步骤 2**：启动 WiFi 节点。

```bash
ros2 run peripherals_wifi_node wifi_node \
  --ros-args \
  --params-file ~/spacemit_robot/output/staging/share/peripherals_wifi_node/params/wifi_node.yaml
```

预期现象：

```text
[INFO] [wifi_node]: wifi_node ready: status_topic=wifi/status scan_topic=wifi/scan_results connect_service=wifi/connect disconnect_service=wifi/disconnect scan_service=wifi/scan status_period_ms=2000 scan_period_ms=0
```

**步骤 3**：另开终端订阅状态话题。

```bash
source ~/spacemit_robot/output/staging/setup.bash
ros2 topic echo /wifi/status --once
```

预期输出（已连接时）：

```yaml
header:
  frame_id: wifi
mode: 1
connected: true
ssid: JDSK
rssi_dbm: 25
secure: 4
bssid:
- 44
- 167
- 158
- 19
- 66
- 35
ip_addr:
- 10
- 0
- 90
- 238
---
```

### 3.2 扫描周边 AP

调用扫描服务：

```bash
source ~/spacemit_robot/output/staging/setup.bash
ros2 service call /wifi/scan peripherals_wifi_node/srv/WifiScan "{}"
```

预期输出（节选）：

```text
response:
peripherals_wifi_node.srv.WifiScan_Response(success=True, message='ok', total_results=5,
results=[WifiScanResult(ssid='JDSK', freq=5320, rssi_dbm=25, secure=4), ...])
```

也可以订阅扫描结果话题：

```bash
ros2 topic echo /wifi/scan_results
```

### 3.3 连接到指定 AP

调用连接服务：

```bash
ros2 service call /wifi/connect peripherals_wifi_node/srv/WifiConnect \
  "{ssid: 'MyAP', password: 'MyPassword'}"
```

断开当前连接：

```bash
ros2 service call /wifi/disconnect std_srvs/srv/Trigger "{}"
```

## 4. 应用开发

上层应用通过订阅 `/wifi/status` 获取连接状态，通过调用 `/wifi/connect` 和 `/wifi/disconnect` 管理连接，通过 `/wifi/scan` 触发扫描。

**WifiStatus 字段**：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `mode` | `int32` | `0=DISABLED 1=STA` |
| `connected` | `bool` | 是否已连接 |
| `ssid` | `string` | 当前连接的 SSID |
| `rssi_dbm` | `int32` | 信号强度（dBm） |
| `secure` | `int32` | 安全类型 |
| `bssid` | `uint8[]` | AP MAC 地址 |
| `ip_addr` | `uint8[]` | 本机 IP 地址 |

注意点：节点通过 NetworkManager 管理 WiFi，因此 `nmcli` 和 ROS 2 节点共享同一个连接状态；`auto_reconnect=true` 时节点会在断线后自动重连上一个已知网络；状态发布周期为 `status_period_ms`，调高此值可减少 CPU 占用。

## 5. 调试指南

- 节点报 `wifi init failed`：确认 NetworkManager 服务正在运行（`systemctl status NetworkManager`）；
- 扫描结果为空：确认 wlan0 处于启用状态（`nmcli device`），信号较弱区域可能扫描到更少 AP；
- 连接服务返回失败：确认 SSID 和密码正确，可先用 `nmcli device wifi connect` 手动验证。

## 6. 常见问题

- `scan_period_ms=0` 时默认不启用周期扫描，需要手动调用 `/wifi/scan` 服务或设置非零值；
- SoftAP 配网模式（`linkd`）需要另一台设备连接热点后访问配网页面，在以 `wlan0` 作为管理链路的环境下启动前须确保有带外恢复方式。
