# 媒体传输 · 编码

## 1. 模块概述

- 主要功能：将原始视频帧压缩为 H.264/H.265/MJPEG 码流，用于网络传输或存储。
- 规格或特性：
  - 支持编码格式：H.264（AVC）、H.265（HEVC）、MJPEG。
  - 支持 NV12 输入，使用 K1 内置硬件编码器。
  - 提供码率、帧率、GOP 等配置接口。
- 相关目录：`components/multimedia/mpp`，基于 MPP 框架。

## 2. 环境准备

### 前置条件

- 硬件与连接：K1 开发板，系统已安装对应的编解码驱动。
- 依赖与外部资源：MPP 库、`libv4l2_linlonv5v7_codec2.so` 插件。
- 工具与权限：具备编解码设备及 DMA heap 的访问权限。
- 本节使用 SDK 自带的测试文件，不需要连接摄像头或显示器；查看画面可在装有播放器的电脑上进行。

### 构建编译

SDK 源码获取和基础编译环境配置参考 [1.7-构建编译](../../01-快速开始/1.7-构建编译.md)。以下在开发板上编译，SDK 路径及 `lunch` 目标按实际环境选择：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
cd components/multimedia/mpp
mm
```

测试程序位于 `output/build/cmake/pkgs/components_multimedia_mpp/test/`。本文使用当前 SDK 的 `test_venc` 工具及 `VENC_*` 通道接口。

## 3. 示例使用（从 0 跑通）

### 3.1 命令行编码测试（文件到文件）

使用 MPP 自带的 `test_venc` 工具，将 NV12 原始帧编码为压缩码流。

**前置**：已完成 MPP 编译，并在开发板终端加载上述 SDK 环境。

**步骤 1**：进入 SDK 目录，拷贝测试文件，然后进入测试程序目录。

```bash
cd ~/spacemit_robot
cp components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv \
  output/build/cmake/pkgs/components_multimedia_mpp/test/
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**步骤 2**：运行 H.264 编码。

```bash
./test_venc --test format \
  -i ./vi_phy0_last_frame.yuv \
  -W 1920 -H 1080 -c h264 -n 1 -o ./enc_out
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `--test format` | 运行编码格式测试 |
| `-i` | 输入 NV12 文件路径 |
| `-W`、`-H` | 图像宽度、高度，需与输入文件一致 |
| `-c` | 编码格式：`h264`、`h265`、`mjpeg` |
| `-n` | 编码帧数 |
| `-o` | 此测试模式下为输出前缀，自动添加格式后缀 |

预期日志包含 `[PASS] format suite` 和 `[DONE] all selected suites passed`，当前目录生成非空文件 `enc_out.h264`。

将 `-c h264` 改为 `-c h265` 或 `-c mjpeg`，分别生成 `enc_out.h265`、`enc_out.mjpeg`。

> 输入文件为 1920×1080 的 NV12 单帧，大小应为 `1920 × 1080 × 3 / 2 = 3110400` 字节，不能直接替换为 JPEG 图片。

**步骤 3**：验证输出码流。

将文件复制到安装了 FFmpeg 的电脑，使用 `ffplay` 查看：

```bash
ffplay enc_out.h264
```

也可在已安装 FFmpeg 的开发板或电脑上检查编码格式、分辨率及帧数：

```bash
ffprobe -v error -select_streams v:0 -count_frames \
  -show_entries stream=codec_name,width,height,nb_read_frames \
  -of json ./enc_out.h264
```

预期为 `h264`、`1920×1080`、`nb_read_frames=1`。硬件解码验证见 [解码](5.4.2-解码.md)。

### 3.2 H.264 编码 API 调用示例

完整示例使用 SDK 已有的 `components/multimedia/mpp/test/venc/test_venc.c`。以下为核心调用片段；输入帧的 VB 缓冲区分配、循环取流及异常清理参考完整示例，应用中应检查各 API 的返回值。

**步骤 1**：初始化系统、缓冲区及编码模块。

```c
#include "sys/sys_api.h"
#include "sys/vb_api.h"
#include "venc/venc_api.h"

SYS_Init();
VB_Init();
VENC_Init();
```

**步骤 2**：设置编码参数，创建并启用通道。

```c
VencChnAttr attr = {0};
attr.eCodecType = MPP_STREAM_CODEC_H264;
attr.eInputPixelFormat = MPP_PIXEL_FORMAT_NV12;
attr.u32Width = 1920;
attr.u32Height = 1080;
attr.u32Align = 16;
attr.u32FrameRate = 30;
attr.u32Bitrate = 4000000;
attr.u32Gop = 30;
attr.eRcMode = VENC_RC_MODE_CBR;
attr.eFrameBufMode = VENC_FRAME_BUF_DMABUF_EXTERNAL;

VENC_CreateChn(0, &attr);
VENC_EnableChn(0);
```

**步骤 3**：送入已准备好的原始帧。

```c
/* input_frame 为已分配并填充 NV12 数据的 VideoFrameInfo。 */
S32 ret = VENC_SendFrame(0, &input_frame, 1000);
```

**步骤 4**：获取码流，处理后释放。

```c
StreamBufferInfo stream = {0};
ret = VENC_GetStream(0, &stream, 1000);
if (ret == 0) {
    /* 将 stream.pu8Addr 指向的 stream.u32Size 字节保存或发送。 */
    VENC_ReleaseStream(0, &stream);
}
```

送帧和取流需配合进行，输入结束后继续取出剩余码流。处理完成后依次停用、销毁通道，释放应用持有的 VB 缓冲区，再退出模块：

```c
VENC_DisableChn(0);
VENC_DestroyChn(0);
/* 按完整示例释放输入缓冲区及缓冲池。 */
VENC_Exit();
VB_Exit();
SYS_Exit();
```

## 4. 应用开发

- **对外 API 或接口形态**：
  - 头文件：`components/multimedia/mpp/include/venc/venc_api.h`。
  - 库名：`libmpp.so`。
  - 主要 API：`VENC_Init()`、`VENC_CreateChn()`、`VENC_EnableChn()`、`VENC_SendFrame()`、`VENC_GetStream()`、`VENC_ReleaseStream()`、`VENC_DisableChn()`、`VENC_DestroyChn()`、`VENC_Exit()`。
- **调用方式与注意点**：
  - 先初始化 SYS、VB、VENC，再创建和启用编码通道。
  - 输入帧的像素格式、宽高、stride 和缓冲区信息需与配置一致，缓冲区管理参考 `file_source_create()`、`file_fill_frame()`。
  - 每次成功获取码流后，必须调用 `VENC_ReleaseStream()`；释放后不能继续访问其数据。
  - 连续编码需处理送帧背压及取流超时，退出前排空剩余输出。
- **参考示例路径**：`components/multimedia/mpp/test/venc/test_venc.c`；实现位于 `components/multimedia/mpp/mpi/venc/venc.c`。

## 5. 调试指南

- 码流验证：使用 `ffprobe` 检查格式、分辨率、帧数，使用 `ffplay` 查看画面。
- 连续编码：以下使用测试程序内置的合成图像，生成 60 帧 H.264 码流：

```bash
./test_venc --test param -W 1920 -H 1080 \
  -c h264 -n 60 --rc cbr --bitrate 4000000 \
  -o ./motion_h264.h264
```

`--test param` 的 `-o` 是完整文件路径，与 `--test format` 的前缀规则不同。验证 H.265 时，将 `-c` 改为 `h265`，输出路径改为 `./motion_h265.h265`。

- 接口检查：运行 `./test_venc --test api`，预期为 `[PASS] api suite`。该测试主动触发部分错误路径，应结合最终结果判断。
- 性能分析：区分图像生成、文件读写、送帧和取流耗时；异步送帧调用耗时不等于完整编码延迟。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 找不到测试程序 | MPP 未构建，或 SDK 版本与命令不一致 | 完成模块 `mm` 编译，确认测试目录中存在 `test_venc` |
| 编码初始化失败 | 插件、驱动或设备访问权限异常 | 检查 `libv4l2_linlonv5v7_codec2.so`、编解码设备和 DMA heap |
| 输出文件名称与预期不同 | 将输出前缀当成完整文件名 | `format` 模式使用 `-o ./enc_out`，由工具添加后缀 |
| 码流无法播放或画面异常 | 输入格式、宽高、stride 不匹配 | 使用 SDK 配套 NV12 文件验证，再检查实际输入参数 |
| 连续编码停止输出 | 未及时取流或释放码流 | 处理背压，每次成功取流后调用 `VENC_ReleaseStream()` |
