# 媒体传输 · 解码

## 1. 模块概述

- 主要功能：将 H.264/H.265/MJPEG 压缩码流还原为视频帧，用于显示或后续图像处理。
- 规格或特性：
  - 支持解码格式：H.264（AVC）、H.265（HEVC）、MJPEG。
  - 使用 K1 内置硬件解码器。
  - 本节使用 NV12 输出，测试程序可将解码帧保存为原始 YUV 文件。
- 相关目录：`components/multimedia/mpp`，基于 MPP 框架。

## 2. 环境准备

### 前置条件

- 硬件与连接：K1 开发板，系统已安装对应的编解码驱动。
- 依赖与外部资源：MPP 库、`libv4l2_linlonv5v7_codec2.so` 插件。
- 工具与权限：具备编解码设备及 DMA heap 的访问权限。
- 本节使用 SDK 自带的压缩文件，不需要连接摄像头或显示器；查看画面可在装有播放器的电脑上进行。

### 构建编译

SDK 源码获取和基础编译环境配置参考 [1.6-构建编译](../../01-快速开始/1.6-构建编译.md)。以下在开发板上编译，SDK 路径及 `lunch` 目标按实际环境选择：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
cd components/multimedia/mpp
mm
```

测试程序位于 `output/build/cmake/pkgs/components_multimedia_mpp/test/`。已按 [编码](5.4.1-编码.md) 完成 MPP 编译时，可复用构建结果。本文使用当前 SDK 的 `test_vdec` 工具及 `VDEC_*` 通道接口。

H.265 文件解码需使用包含文件尾帧处理修复的 SDK；更新相关源码后需重新执行 `mm`。

## 3. 示例使用（从 0 跑通）

### 3.1 命令行解码测试（文件到文件）

使用 MPP 自带的 `test_vdec` 工具，将压缩码流解码为 NV12 原始帧。

**前置**：已完成 MPP 编译，并在开发板终端加载上述 SDK 环境。

**步骤 1**：进入 SDK 目录，拷贝测试文件，然后进入测试程序目录。

```bash
cd ~/spacemit_robot
cp components/multimedia/mpp/test/assets/1920x1080.jpg \
  output/build/cmake/pkgs/components_multimedia_mpp/test/
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**步骤 2**：运行 MJPEG 解码。

```bash
./test_vdec --test format -i ./1920x1080.jpg \
  -W 1920 -H 1080 -c mjpeg --output-format nv12 \
  -o ./dec_out_nv12.yuv
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `--test format` | 运行解码格式测试 |
| `-i` | 输入压缩码流文件路径 |
| `-W`、`-H` | 输入图像宽度、高度提示 |
| `-c` | 解码格式：`h264`、`h265`、`mjpeg` |
| `--output-format nv12` | 保存为 NV12 像素格式 |
| `-o` | 输出原始帧文件的完整路径 |
| `-n` | 目标解码帧数上限，默认 `0` 表示处理整个文件；当前版本的边界问题见第 6 节 |

预期日志包含：

```text
[decode] ./1920x1080.jpg decoded_frames=1 last 1920x1080
[PASS] format suite (1 case(s))
```

当前目录生成 `dec_out_nv12.yuv`，检查大小：

```bash
stat -c '%s' ./dec_out_nv12.yuv
```

1920×1080 NV12 单帧应为 `3110400` 字节。检查时应同时确认实际帧数和文件大小。

**步骤 3**：验证输出 YUV。

将文件复制到安装了 FFmpeg 的电脑，使用 `ffplay` 查看：

```bash
ffplay -f rawvideo -pixel_format nv12 -video_size 1920x1080 \
  ./dec_out_nv12.yuv
```

> 也可先按 [编码](5.4.1-编码.md) 生成 `enc_out.h264`，再运行以下命令验证硬件编解码闭环：

```bash
./test_vdec --test format -i ./enc_out.h264 \
  -W 1920 -H 1080 -c h264 --output-format nv12 \
  -o ./roundtrip_nv12.yuv
```

单帧输入应输出 1 帧，文件大小为 `3110400` 字节。

### 3.2 H.264 解码 API 调用示例

完整示例使用 SDK 已有的 `components/multimedia/mpp/test/vdec/test_vdec.c`。以下为核心调用片段；码流分帧、循环取帧、EOS 及异常清理参考完整示例，应用中应检查各 API 的返回值。

**步骤 1**：初始化系统、缓冲区及解码模块。

```c
#include "sys/sys_api.h"
#include "sys/vb_api.h"
#include "vdec/vdec_api.h"

SYS_Init();
VB_Init();
VDEC_Init();
```

**步骤 2**：设置解码参数，创建并启用通道。

```c
VdecChnAttr attr = {0};
attr.eCodecType = MPP_STREAM_CODEC_H264;
attr.eOutputPixelFormat = MPP_PIXEL_FORMAT_NV12;
attr.u32Width = 1920;
attr.u32Height = 1080;

VDEC_CreateChn(0, &attr);
VDEC_EnableChn(0);
```

**步骤 3**：送入已准备好的码流包。

```c
/* input_stream 为已填充的 StreamBufferInfo，包含码流地址、长度及编码格式。 */
S32 ret = VDEC_SendStream(0, &input_stream, 3000);
```

**步骤 4**：获取解码帧，处理后释放。

```c
VideoFrameInfo frame = {0};
ret = VDEC_GetFrame(0, &frame, 1000);
if (ret == 0) {
    /* 按 frame 中的像素格式、宽高和各平面 stride 处理图像。 */
    VDEC_ReleaseFrame(0, frame.ulBufferId);
}
```

输入结束后发送 EOS，并继续获取剩余帧。处理完成后释放全部输出帧，再依次退出：

```c
VDEC_DisableChn(0);
VDEC_DestroyChn(0);
VDEC_Exit();
VB_Exit();
SYS_Exit();
```

## 4. 应用开发

- **对外 API 或接口形态**：
  - 头文件：`components/multimedia/mpp/include/vdec/vdec_api.h`。
  - 库名：`libmpp.so`。
  - 主要 API：`VDEC_Init()`、`VDEC_CreateChn()`、`VDEC_EnableChn()`、`VDEC_SendStream()`、`VDEC_GetFrame()`、`VDEC_ReleaseFrame()`、`VDEC_DisableChn()`、`VDEC_DestroyChn()`、`VDEC_Exit()`。
- **调用方式与注意点**：
  - 先初始化 SYS、VB、VDEC，再创建和启用解码通道。
  - H.264/H.265 测试输入为 Annex B 裸码流，需包含对应参数集；MP4 等容器文件应先解封装。
  - `VDEC_SendStream()` 返回前需保持输入缓冲区有效；送流背压和超时需按返回值处理。
  - 每次成功获取帧后必须调用 `VDEC_ReleaseFrame()`，释放后不能继续访问该帧。
  - 保存 YUV 时按实际宽高、平面及 stride 逐行处理；测试程序的 NV12 文件已去除行对齐填充。
- **参考示例路径**：`components/multimedia/mpp/test/vdec/test_vdec.c`；实现位于 `components/multimedia/mpp/mpi/vdec/vdec.c`。

## 5. 调试指南

- 帧数据验证：检查 `decoded_frames` 和输出大小，再用 `ffplay` 查看画面。1920×1080 NV12 文件大小应为 `3110400 × 帧数` 字节。
- 连续解码：在测试程序目录使用 SDK 自带 H.264 码流：

```bash
./test_vdec --test format \
  -i ~/spacemit_robot/components/multimedia/mpp/test/assets/input.264 \
  -W 1920 -H 1080 -c h264 --output-format nv12 \
  -o ./h264_nv12.yuv
```

配套文件应输出 54 帧，大小为 `167961600` 字节。

- H.265 功能检查：使用 SDK 自带的 H.265 裸码流：

```bash
./test_vdec --test format \
  -i ~/spacemit_robot/components/multimedia/mpp/test/assets/input.265 \
  -W 1920 -H 1080 -c h265 --output-format nv12 \
  -o ./h265_nv12.yuv
```

配套文件应完整输出 54 帧，大小为 `167961600` 字节，日志包含 `decoded_frames=54 last 1920x1080`。

- 接口检查：运行 `./test_vdec --test api`，预期为 `[PASS] api suite`。该测试主动触发部分错误路径，应结合最终结果判断。
- 性能分析：分别统计送流、取帧及文件读写耗时；测试工具的取帧耗时统计不等于端到端解码延迟。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 找不到测试程序 | MPP 未构建，或 SDK 版本与命令不一致 | 完成模块 `mm` 编译，确认测试目录中存在 `test_vdec` |
| 解码初始化失败 | 插件、驱动或设备访问权限异常 | 检查 `libv4l2_linlonv5v7_codec2.so`、编解码设备和 DMA heap |
| YUV 无法正常显示 | 播放时的像素格式、宽高不匹配 | 按实际输出的 `nv12`、宽高设置播放器参数 |
| 输出为空但仍显示 `PASS` | 当前测试程序未将零帧输出判定为失败 | 同时核对 `decoded_frames` 和输出文件大小；若为 0，仍需排查输入码流与解码参数，不能仅凭 `PASS` 判定成功 |
| 设置 `-n 30` 却保存了 31 帧 | 当前测试程序在保存后检查帧数，结束阶段再次取帧时可能多保存一帧 | 不依赖该参数精确截取帧数；需在 `test/vdec/test_vdec.c` 的 `drain_available_frames()` 取帧前检查上限，修改后重新编译并验证 |
| 连续解码停止输出 | 未及时取帧或释放输出缓冲区 | 处理背压，每次成功取帧后调用 `VDEC_ReleaseFrame()` |
