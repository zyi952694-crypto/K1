# 2.3 系统升级

已有项目继续使用配套的 **Bianbu 2.2 / ROS2_LXQT** 和运行库。新 SDK 使用独立的 **Bianbu 2.3.5** 系统环境；新装系统见 [2.2 镜像烧录](2.2-镜像烧录/MUSE-Pi-Pro.md)。已有系统需要使用 2.3 系列的软件包时，再按本节升级。

以下以基于 Bianbu 2.2 的 ROS2_LXQT 为例，通过 Bianbu 2.3 系列软件源在线升级。该软件源提供 2.3.5 及后续 2.3.x 维护更新。

Bianbu 2.2 和 2.3 系列使用 Ubuntu 24.04 / `noble` 基础环境；Bianbu 3.0 使用 Ubuntu 25.04 / `plucky`。软件源、Python 二进制包和原生库需与目标系统配套，不混用不同主版本的依赖。版本说明见 [Bianbu 发布说明](https://www.spacemit.com/community/document/info?lang=zh&nodepath=software/SDK/bianbu/release_notes)。

旧 BROS 的 VAD、TTS 等预编译 C++ 节点需要配套的 `onnxruntime 1.2.2`。新 SDK 使用的 `spacemit-onnxruntime 2.0.3` 不能直接替换该库；保留这些应用的系统不要执行新 SDK 的运行库替换步骤。已经升级到 2.3.5 的设备也需保留旧应用所用的运行库，具体要求见 [BROS 安装](../05-机器人开发/5.1-系统准备/5.1.2-AI-Robot安装.md)。

## 1. 升级前准备

先在测试设备或备用存储上完成项目启动、模型运行和所用外设的检查，再升级已部署项目的设备。保留可恢复的原系统镜像，并备份项目、模型、应用配置和启动配置。升级期间暂停应用和 SDK 构建，保持稳定供电与网络连接。

查看当前系统版本，并备份 APT 配置与软件包清单：

```bash
cat /etc/os-release
sudo cp -a /etc/apt "/var/backups/apt-before-bianbu-upgrade-$(date +%Y%m%d-%H%M%S)"
dpkg-query -W > ~/packages-before-bianbu-upgrade.txt
apt-mark showhold
```

保留设备已有的内核版本固定配置，以及 ROS 软件源和 `/opt/bros` 环境。使用定制内核、设备树或外设驱动的项目，保留其配套版本。APT 配置和软件包清单不能替代可恢复的系统镜像。

## 2. 配置 Bianbu 2.3 软件源

编辑 `/etc/apt/sources.list.d/bianbu.sources`，将 Bianbu 系统仓库条目调整为以下配置。其他软件源条目保留：

```text
Types: deb
URIs: https://archive.spacemit.com/bianbu/
Suites: noble/snapshots/v2.3 noble-security/snapshots/v2.3 noble-updates/snapshots/v2.3 noble-porting/snapshots/v2.3 noble-customization/snapshots/v2.3 bianbu-v2.3-updates
Components: main universe restricted multiverse
Signed-By: /usr/share/keyrings/bianbu-archive-keyring.gpg
```

ROS2_LXQT 或已配置 ROS 软件源的系统，需保留 `noble-ros`。如果它原本与系统仓库共用一个 `Suites` 字段，在上面的 `Suites` 行末继续添加 `noble-ros`；如果是独立条目，保留原条目即可。

本节使用指定的 2.3 系列软件源。`do-release-upgrade` 可能选择新的主版本，不用于本节的 2.3.5 升级流程。软件源配置详见 [Bianbu 2.3 发布说明](https://www.spacemit.com/community/document/info?lang=zh&nodepath=software/SDK/bianbu/release_notes/bianbu_2.3.md)。

### 2.1 ROS2_LXQT 的软件源优先级

查看 `/etc/apt/preferences.d/` 中现有的源优先级。若 `noble-porting`、`noble-customization` 等厂商源的优先级已设为 `1100`，而 `bianbu-v2.3-updates` 仍使用默认优先级，为更新源设置相同优先级：

```bash
sudo tee /etc/apt/preferences.d/bianbu-v2-updates.pref > /dev/null <<'PREF'
Package: *
Pin: release o=Spacemit, n=bianbu-v2.3-updates
Pin-Priority: 1100
PREF
```

未设置这类高优先级规则的通用固件可跳过此步骤。保留原有的 `noble-ros` 优先级与内核固定规则。

## 3. 安装系统更新

更新软件包索引，查看候选版本和升级清单：

```bash
sudo apt-get -o APT::Update::Error-Mode=any update
apt-cache policy base-files
apt-get -s dist-upgrade
```

确认 `base-files` 的候选版本来自目标 2.3 系列源，并检查待升级、替换和移除的软件包。发行版本调整可能包含部分软件包的版本回退，按清单确认后先下载更新：

```bash
sudo apt-get --allow-downgrades --download-only dist-upgrade
```

下载完成后安装：

```bash
sudo apt-get --allow-downgrades --no-download dist-upgrade
```

安装过程中，涉及自行修改的配置文件时先查看差异，保留需要继续使用的本地设置。

安装结束后，检查是否还有未配置完成的软件包或依赖问题：

```bash
sudo dpkg --audit
sudo apt-get check
apt-get -s dist-upgrade
```

若还有待处理的软件包，继续完成升级；若使用了软件包锁定规则，保留相应的锁定项。处理完报错且升级清单中没有其他待处理项后，重启系统：

```bash
sudo reboot
```

## 4. 升级后继续开发

重新登录后查看系统版本和内核版本：

```bash
cat /etc/os-release
uname -r
```

系统版本应为 Bianbu 2.3.5 或后续 2.3.x 版本。使用固定内核配置的系统，内核版本可以与升级前相同。

系统升级与 AI 运行库迁移分别进行：更新 `python3-spacemit-ort` 不会自动将旧 C++ `onnxruntime` 包替换为 `spacemit-onnxruntime`。既有应用继续使用项目配套的模型、Python 环境和原生库；独立的新 SDK 环境按 [2.4 构建编译](2.4-构建编译.md)处理依赖。

## 5. LXQt 文件管理器软件包冲突

从旧 LXQt 系统升级时，若安装提示 `libfm-qt6-common` 或 `libfm-qt6-l10n` 与旧包发生文件覆盖冲突，先查看依赖修复清单：

```bash
apt-cache rdepends --installed libfm-qt-l10n
apt-get -s -f install libfm-qt-l10n- libfm-qt6-common libfm-qt6-l10n
```

确认没有其他已安装应用依赖旧语言包，且清单仅移除旧 `libfm-qt-l10n` 并完成相关组件替换后，执行：

```bash
sudo apt-get -f install libfm-qt-l10n- libfm-qt6-common libfm-qt6-l10n
sudo dpkg --audit
sudo apt-get check
```

修复完成后继续第 3 节的升级检查与重启步骤。
