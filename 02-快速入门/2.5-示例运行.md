# 2.5 示例运行

## 1. 前置条件

按 [2.4 构建编译](2.4-构建编译.md) 完成 SDK 源码获取和基础环境配置。SDK 目录为 `~/spacemit_robot`。

语音交互功能需搭配音频输入与输出设备使用，例如 USB 麦克风和扬声器。先按[麦克风](../06-系统与平台/6.3-多媒体/6.3.10-麦克风硬件调试说明.md)和[扬声器](../06-系统与平台/6.3-多媒体/6.3.11-扬声器硬件调试说明.md)说明连接设备、准备访问权限并完成录放音检查。使用摄像头实时检测时，还需连接摄像头并提供可用的图形显示环境。

首次构建前执行 `sudo apt update`，并按构建提示安装缺失的开发依赖。视觉组件需要 `spacemit-onnxruntime` 等 C++ 开发库；Omni Agent 还需要 PortAudio、重采样及 JSON 等开发包。依赖安装方式和旧版 ONNX Runtime 的处理见 [2.4 构建编译](2.4-构建编译.md#32-单组件编译)。

新开终端后，先在 SDK 根目录加载环境并选择方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

以下以视觉目标检测为例，演示编译与运行流程。

### 2.1 一键编译

先按 [2.10 视觉推理线程](2.10-SDK补丁.md#21-视觉推理线程)检查源码：含 `plan_session_configs` 的版本直接编译；旧版源码按该节检查并应用适用补丁。

编译组件：

```bash
cd ~/spacemit_robot/components/model_zoo/vision
mm
```

缺少依赖时按提示确认安装；需要自动接受安装时，将 `mm` 替换为 `AUTO_INSTALL_DEPS=yes mm`。GCC 13 编译若提示 `__fp16` 未定义，按 [2.4 常见问题](2.4-构建编译.md#6-常见问题)添加对应编译参数。

### 2.2 快速运行

先应用[视觉素材下载补丁](2.10-SDK补丁.md#222-视觉素材下载)，修正多级资源路径解析和失败下载的缓存处理：

```bash
cd ~/spacemit_robot
wget -O /tmp/vision-assets-download.patch \
    https://archive.spacemit.com/ros2/k1_sdk/patches/components/model_zoo/vision/vision-assets-download.patch && \
git -C components/model_zoo/vision apply --check /tmp/vision-assets-download.patch && \
git -C components/model_zoo/vision apply /tmp/vision-assets-download.patch
cd components/model_zoo/vision
```

在视觉组件目录下载模型和本例所需的测试图片：

```bash
bash examples/yolov8/scripts/download_models.sh
mkdir -p "$HOME/.cache/assets/image"
wget -O "$HOME/.cache/assets/image/006_test.jpg" \
    https://archive.spacemit.com/spacemit-ai/model_zoo/assets/image/006_test.jpg
```

在 `components/model_zoo/vision` 目录下，使用 SDK 配置 `examples/yolov8/config/yolov8.yaml` 运行检测：

```bash
yolov8 examples/yolov8/config/yolov8.yaml
```

程序在终端打印检测结果，并将标注图像保存为当前目录下的 `result.jpg`。

（可选）使用摄像头进行实时检测。先查看设备：

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video20 -D
```

`v4l2-ctl` 由 `v4l-utils` 软件包提供。以下以 `/dev/video20` 为例，确认该节点的 **Device Caps** 包含 `Video Capture`，并将 `20` 替换为实际摄像头编号；仅支持 `Metadata Capture` 的节点不能用于图像采集。

```bash
yolov8 examples/yolov8/config/yolov8.yaml --use-camera --camera-id 20
```

按 `q` 退出，按 `s` 保存当前帧。该示例会创建 OpenCV 窗口，需在图形桌面终端运行；通过 SSH 运行时，PC 需有可用的 X 服务，并从 PC 使用 `ssh -Y <用户名>@<K1_IP>` 建立 X11 转发连接，再加载 SDK 环境。`DISPLAY` 由 SSH 自动设置。

## 3. 语音交互

本节以 Omni Agent 为例，演示语音交互功能的编译与运行。采用 Qwen2.5 LLM（运行在局域网主机或云端）、板端 SenseVoice 语音识别和 Matcha-TTS 中英双语合成。

### 3.1 一键编译

先应用 ASR 后端配置补丁：

```bash
cd ~/spacemit_robot
wget -O /tmp/omni-asr-provider.patch \
    https://archive.spacemit.com/ros2/k1_sdk/patches/application/native/omni_agent/0001-omni_agent-add-optional-ASR-provider-override-CLI-as.patch && \
git -C application/native/omni_agent apply /tmp/omni-asr-provider.patch
```

在 SDK 根目录加载环境并选择方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

> **说明：ASR 推理后端**
>
> 同时运行本地 LLM 与 ASR 时，为 `voice_chat` 添加 `--asr-provider cpu`，将 SenseVoice 设置为 CPU 推理。Agent 服务的配置方法见 [4.5 Agent](../04-AI与算法/4.5-Agent.md)。

编译 Omni Agent 及其声明的 SDK 依赖：

```bash
cd ~/spacemit_robot/application/native/omni_agent
mm --with-deps
```

`mm --with-deps` 会先构建 `audio`、`audio_process` 及所需 Model Zoo 等组件，生成的 `voice_chat` 安装到 `output/staging/bin`。首次构建时按提示安装缺少的系统依赖；需要自动接受安装时执行 `AUTO_INSTALL_DEPS=yes mm --with-deps`。加载 SDK 环境后调用 `voice_chat`。

### 3.2 快速运行

列出音频输入和输出设备：

```bash
arecord -l
aplay -l
voice_chat --list-devices
```

如果已连接设备却提示权限不足或 `no soundcards found`，检查当前用户对 `/dev/snd` 的访问权限。需要通过 `audio` 组访问时，执行 `sudo usermod -aG audio "$USER"`，退出并重新登录，再加载 SDK 环境并重查设备。`voice_chat` 使用自己的设备索引，不能直接套用 `arecord`、`aplay` 的声卡编号。

LLM 服务运行在另一台主机上（PC 或服务器，下文记为 `<LLM_HOST>`），开发板通过局域网访问。在该主机上下载模型并启动 llama.cpp 服务（PC 上需先自行安装 llama.cpp）：

```bash
mkdir -p ~/.cache/models/llm
cd ~/.cache/models/llm
# 示例下载 Qwen2.5 0.5B 模型
wget -nc https://archive.spacemit.com/spacemit-ai/model_zoo/llm/qwen2.5-0.5b-instruct-q4_0.gguf
llama-server -m ~/.cache/models/llm/qwen2.5-0.5b-instruct-q4_0.gguf --host 0.0.0.0 --port 8080
```

也可以使用任意 OpenAI 兼容的云端服务。保持服务运行，在开发板上加载 SDK 环境，并检查服务状态和模型名称：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet

curl http://<LLM_HOST>:8080/health
curl http://<LLM_HOST>:8080/v1/models
```

`/health` 返回 `{"status":"ok"}` 后启动语音对话。将 `<MODEL_ID>` 替换为 `/v1/models` 返回的完整模型 ID；该值可能是模型文件的完整路径：

```bash
voice_chat --llm-url http://<LLM_HOST>:8080 \
    --model "<MODEL_ID>" \
    --tts matcha:zh-en --asr-engine sensevoice
```

SenseVoice、Silero VAD 和 Matcha-TTS 会检查本地模型缓存，缺少资源时自动下载，首次启动需保持网络可用。初始化完成并显示“等待语音输入”后，即可对着麦克风说话；按 `Ctrl+C` 退出。

上述命令使用默认音频设备。需要指定设备或调整采样格式时，根据 `voice_chat --list-devices` 的输入、输出编号和支持格式添加音频参数。例如，输入设备 `0` 支持 16 kHz 单声道、输出设备 `1` 支持 48 kHz 双声道时，可使用：

```bash
voice_chat --llm-url http://<LLM_HOST>:8080 \
    --model "<MODEL_ID>" \
    --tts matcha:zh-en --asr-engine sensevoice \
    --input-device 0 --output-device 1 \
    --capture-rate 16000 --capture-channels 1 \
    --playback-rate 48000 --playback-channels 2
```

设备编号可能随插拔或重启变化，应以设备列表为准。

> **在本地运行 LLM**
>
> LLM 也可运行在开发板上。先按 [4.4 LLM](../04-AI与算法/4.4-LLM.md)准备模型和 `llama-server`；采用该节的独立运行时时，需在启动服务的终端执行 `source ~/asr-runtime.sh`。确认 `command -v llama-server` 能找到命令后，在该终端启动 `llama-server -m ~/.cache/models/llm/qwen2.5-0.5b-instruct-q4_0.gguf -t 4 -tb 4 --port 8080`（使用 4 个推理线程）。`/health` 返回 `{"status":"ok"}` 后，将 `--llm-url` 改为 `http://127.0.0.1:8080`，按本地服务的 `/v1/models` 设置 `--model`，并追加 `--asr-provider cpu`。
