# 2.4 示例运行

## 1. 前置条件

按 [2.3 构建编译](2.3-构建编译.md) 完成 SDK 源码获取和基础环境配置。以下命令在 K1 设备上执行，SDK 目录以 `~/spacemit_robot` 为例。

语音交互功能需搭配音频输入与输出设备使用，例如 USB 麦克风和扬声器。使用摄像头实时检测时，还需连接摄像头并提供可用的图形显示环境。

新开终端后，先在 SDK 根目录加载环境并选择 K1 方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

以下以视觉目标检测为例，演示编译与运行流程。

### 2.1 一键编译

```bash
cd ~/spacemit_robot/components/model_zoo/vision
mm
```

### 2.2 快速运行

在视觉组件目录下载模型和测试资源：

```bash
bash examples/yolov8/scripts/download_models.sh
bash scripts/download_assets.sh
```

SDK 示例配置默认使用 `num_threads: 8`，K1 使用 4 个推理线程。为了不修改 SDK 文件，将配置复制到 SDK 外的 `~/k1_configs/`，只修改副本；Python 与 C++ 共用该 YAML，无需重新编译。推理线程数不代表设备的 CPU 总核数，K1 与 K3 的参数差异汇总见 [平台概览 · K1 与 K3 差异说明](../01-平台概览.md)。

```bash
mkdir -p ~/k1_configs
cp examples/yolov8/config/yolov8.yaml ~/k1_configs/yolov8.yaml
sed -i 's/num_threads: 8/num_threads: 4/' ~/k1_configs/yolov8.yaml
```

在视觉组件目录下运行检测，配置中的 `assets/...` 相对路径会按该目录解析：

```bash
yolov8 ~/k1_configs/yolov8.yaml
```

程序在终端打印检测结果，并将标注图像保存为当前目录下的 `result.jpg`。

（可选）使用摄像头进行实时检测。先查看设备：

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video20 -D
```

`v4l2-ctl` 由 `v4l-utils` 软件包提供。以下以 `/dev/video20` 为例，确认该节点的 **Device Caps** 包含 `Video Capture`，并将 `20` 替换为实际摄像头编号；仅支持 `Metadata Capture` 的节点不能用于图像采集。

```bash
yolov8 ~/k1_configs/yolov8.yaml --use-camera --camera-id 20
```

按 `q` 退出，按 `s` 保存当前帧。该示例会创建 OpenCV 窗口，需在图形桌面终端运行；通过 SSH 运行时，PC 需有可用的 X 服务，并从 PC 使用 `ssh -Y <用户名>@<K1_IP>` 建立 X11 转发连接，再加载 SDK 环境。`DISPLAY` 由 SSH 自动设置。

## 3. 语音交互

本节以 Omni Agent 为例，演示语音交互功能的编译与运行。采用 Qwen2.5 LLM（运行在局域网主机或云端）、K1 本地 SenseVoice 语音识别和 Matcha-TTS 中英双语合成。

### 3.1 一键编译

在 SDK 根目录加载环境并选择 K1 方案：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
```

> **K1 已知问题：SenseVoice 与本地 LLM 争用加速资源**
>
> SDK 中 SenseVoice 默认使用 SpaceMIT 推理后端。K1 上本地 LLM（llama.cpp）同样使用该后端，两者同时运行时 SenseVoice 初始化报 `tcm buffer alloc failed`，进程退出。当前 Agent 没有提供 ASR provider 的配置项或命令行参数，该问题已反馈 SDK 上游（K1-REP-AGENT-003 / VOICE-008），详见 [平台概览 · K1 与 K3 差异说明](../01-平台概览.md#8-已知问题与规避方式)。
>
> 本节不修改 SDK 源码，推荐把 LLM 服务放在 PC、服务器或云端（OpenAI 兼容接口），K1 只运行 VAD、ASR 和 TTS。必须在 K1 本地同时运行 LLM 时，参考 [4.5 Agent](../04-AI与算法/4.5-Agent.md) 中“本地临时补丁”的说明。
>
> 验证状态：K1 已验证“本地 LLM + SenseVoice CPU 后端（本地临时补丁）”的组合；“远程 LLM + SenseVoice 默认后端”的组合尚待在 K1 实机复测。

编译 Omni Agent：

```bash
m
cd application/native/omni_agent
mm --with-deps
```

`m` 构建当前 K1 方案选中的组件；`mm --with-deps` 补充构建 Omni Agent 及其声明的依赖。生成的 `voice_chat` 安装到 `output/staging/bin`，加载 SDK 环境后可直接调用。

### 3.2 快速运行

LLM 服务运行在另一台主机上（PC 或服务器，下文记为 `<LLM_HOST>`），K1 通过局域网访问。在该主机上下载模型并启动 llama.cpp 服务（PC 上需先自行安装 llama.cpp）：

```bash
mkdir -p ~/.cache/models/llm
cd ~/.cache/models/llm
# 示例下载 Qwen2.5 0.5B 模型
wget -nc https://archive.spacemit.com/spacemit-ai/model_zoo/llm/qwen2.5-0.5b-instruct-q4_0.gguf
llama-server -m ~/.cache/models/llm/qwen2.5-0.5b-instruct-q4_0.gguf --host 0.0.0.0 --port 8080
```

也可以使用任意 OpenAI 兼容的云端服务。保持服务运行，在 K1 上加载 SDK 环境，并检查服务状态和模型名称：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet

curl http://<LLM_HOST>:8080/health
curl http://<LLM_HOST>:8080/v1/models
```

`/health` 返回 `{"status":"ok"}` 后启动语音对话；`--model` 应与 `/v1/models` 中的模型 ID 一致：

```bash
voice_chat --llm-url http://<LLM_HOST>:8080 \
    --model qwen2.5-0.5b-instruct-q4_0.gguf \
    --tts matcha:zh-en --asr-engine sensevoice
```

SenseVoice、Silero VAD 和 Matcha-TTS 会检查本地模型缓存，缺少资源时自动下载，首次启动需保持网络可用。初始化完成并显示“等待语音输入”后，即可对着麦克风说话；按 `Ctrl+C` 退出。

上述命令使用默认音频设备。需要指定设备或调整采样格式时，先查看列表：

```bash
voice_chat --list-devices
```

根据实际设备的输入、输出编号和支持格式添加音频参数。例如，输入设备 `0` 支持 16 kHz 单声道、输出设备 `1` 支持 48 kHz 双声道时，可使用：

```bash
voice_chat --llm-url http://<LLM_HOST>:8080 \
    --model qwen2.5-0.5b-instruct-q4_0.gguf \
    --tts matcha:zh-en --asr-engine sensevoice \
    --input-device 0 --output-device 1 \
    --capture-rate 16000 --capture-channels 1 \
    --playback-rate 48000 --playback-channels 2
```

设备编号可能随插拔或重启变化，应以设备列表为准。

> **在 K1 本地运行 LLM**
>
> 不修改 SDK 时，K1 本地 LLM 不能与 SenseVoice 同时运行，但可以单独体验：`llama-server -m ~/.cache/models/llm/qwen2.5-0.5b-instruct-q4_0.gguf -t 4 -tb 4 --port 8080`（K1 使用 4 个推理线程），用法见 [4.4 LLM](../04-AI与算法/4.4-LLM.md)。
