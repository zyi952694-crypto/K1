# 4.1.1 ASR

## 1. 模块概述

ASR 组件提供统一的语音识别接口，负责把 16kHz 语音转换为文本。组件位于 `components/model_zoo/asr`，提供 C++ API、Python 绑定、文件识别 demo 和流式识别 demo，可被上层应用用作语音输入前端。

当前支持的后端：

| 后端 | 形态 | 典型用途 |
| --- | --- | --- |
| SenseVoice | 本地 ONNX，默认后端 | 中文/多语言离线识别，支持文件与流式 flush。 |
| Zipformer CTC | 本地 ONNX 流式模型 | 轻量流式识别场景。 |
| Qwen3-ASR 0.6B / 1.7B | `llama-server` 服务 | 通过 chat completions 接口进行离线语音识别。 |
| Fun-ASR Nano | `llama-server` 服务 | 通过 transcription 接口进行离线语音识别。 |
| Gemma4 ASR E2B | `llama-server` 服务 | 原语言转写，或将外语语音翻译为英文。 |

Qwen3-ASR、Fun-ASR Nano 和 Gemma4 ASR 都需要提交完整音频后再返回结果，不支持模型原生的有状态流式识别。服务端统一使用 `llama.cpp-tools-spacemit` 0.1.7 运行时，安装方式见 §3.6。

SenseVoice 和 Zipformer 均接入了本组件的 `Start()` / `SendAudioFrame()` / `Flush()` 流式接口，其中 Zipformer 是原生流式模型。

典型数据链路：

```text
WAV/麦克风 PCM -> 采样率与声道整理 -> ASR 后端 -> RecognitionResult 文本
```

主要目录：

| 路径 | 说明 |
| --- | --- |
| `components/model_zoo/asr/include/asr_service.h` | C++ 对外 API。 |
| `components/model_zoo/asr/src/` | ASR 引擎、配置、后端适配和模型下载逻辑。 |
| `components/model_zoo/asr/examples/asr_file_demo.cpp` | C++ 文件识别示例。 |
| `components/model_zoo/asr/examples/asr_stream_demo.cpp` | C++ 麦克风流式识别示例。 |
| `components/model_zoo/asr/python/` | Python 包 `spacemit_asr` 与示例。 |

## 2. 环境准备

### 前置条件

SDK 源码获取和基础编译环境配置统一参考 [2.3 构建编译](../../02-快速入门/2.3-构建编译.md)。

后续命令默认在 `spacemit_robot` SDK 根目录执行。

### 构建编译

语音组件使用 `target/k1-muse-pipro-ai-cubpet.json` 目标配置。系统缺少依赖时先安装：

```bash
sudo apt install libsndfile1-dev libfftw3-dev libcurl4-openssl-dev
```

在 SDK 根目录加载构建环境后编译 ASR：

```bash
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
cd components/model_zoo/asr
mm
```

新固件的系统 `onnxruntime` 为 1.2.2，SDK 的依赖检查会要求替换为 `spacemit-onnxruntime`，而 K1 软件源当前不提供该包。同时系统 GCC 13 未实现 `__fp16` 类型，而 ONNX Runtime 头文件在 `__riscv_zfh` 宏下会使用该类型，直接编译 zipformer 后端会报 `'__fp16' does not name a type`。这种情况下跳过依赖检查，并通过编译参数关闭该宏：

```bash
SROBOTIS_SKIP_DEPS_CHECK=1 mm -DCMAKE_CXX_FLAGS="-U__riscv_zfh"
```

流式示例和本文录音命令还依赖 audio 组件。如当前环境没有 `audio_demo`，继续编译 audio，并重新编译 ASR：

```bash
cd ../../multimedia/audio
mm
cd ../../model_zoo/asr
mm
```

SDK 集成构建会将 ASR 相关可执行程序和库安装到 `output/staging`。

需要 Python 示例时，可以在 SDK 根目录构建所有 Python wheel：

```bash
cd ../../..
m -py
```

也可以只在 ASR 组件目录构建当前组件的 Python wheel：

```bash
cd components/model_zoo/asr
mm -py
```

注意：`m -py` / `mm -py` 是构建 wheel，使用系统 Python 环境执行；不要在 `~/.comm-env` 中执行。`~/.comm-env` 只用于后面的 `pip install` 和运行 Python 示例。

运行 Python 示例前，先安装虚拟环境依赖，并创建、激活 `~/.comm-env`：

```bash
sudo apt install python3-venv python-is-python3 python3-pip
python3 -m venv ~/.comm-env
source ~/.comm-env/bin/activate
```

安装本地构建出的 ASR wheel：

```bash
python -m pip install output/wheels/components_model_zoo_asr/spacemit_asr-*.whl
```

Python 流式识别示例还依赖 audio 组件。先构建 audio wheel：

```bash
cd components/multimedia/audio
mm -py
cd ../../..
```

再安装：

```bash
python -m pip install output/wheels/components_multimedia_audio/spacemit_audio-*.whl
```

SenseVoice 默认模型路径为 `~/.cache/models/asr/sensevoice/`。程序首次运行时会检查模型，缺失时按组件下载逻辑准备。

## 3. 示例使用

### 3.1 录音并做文件识别

先查看当前可用的音频输入设备：

```bash
asr_stream_demo -l
```

K1 MUSE Pi Pro 实际使用时，根据设备枚举结果选择可用的输入设备。

使用 audio 组件录制 5 秒 16kHz 双声道 WAV：

```bash
audio_demo record test.wav \
    --duration 5 \
    --rate 16000 \
    --channels 2 \
    --device <device_id>
```

ASR 文件识别会将输入音频整理为模型所需格式后送入后端。

如果不想录音，也可以从公开音频资源目录下载本文使用的测试音频：

```bash
mkdir -p ~/.cache/models/assets/audio
cd ~/.cache/models/assets/audio

AUDIO_BASE=https://archive.spacemit.com/spacemit-ai/model_zoo/assets/audio

for file in \
    001_zh_daily_weather.wav \
    002_en_daily_weather.wav \
    003_zh_en_search.wav \
    004_zh_selling_sausages.wav
do
    wget -nc "$AUDIO_BASE/$file"
done
```

其中 `001` 至 `004` 用于常规转写和性能测试。

然后运行默认 SenseVoice 文件识别：

```bash
asr_file_demo ~/.cache/models/assets/audio/001_zh_daily_weather.wav
```

预期输出会打印引擎、语言、Provider、识别文本和 RTF，例如 `引擎类型: sensevoice`、`Provider: spacemit`、`文本:`。

### 3.2 Python 文件识别

确保已激活 `~/.comm-env`，并已安装 `spacemit-asr` 后运行：

```bash
cd components/model_zoo/asr/python/examples
python asr_file_demo.py ~/.cache/models/assets/audio/001_zh_daily_weather.wav
```

预期输出包含 ASR 版本、Provider、识别文本、音频时长、处理时间和 RTF。

### 3.3 Zipformer 文件识别

当前 Zipformer 后端在 K1 + SpaceMIT EP 下使用以下运行配置：

```bash
export SPACEMIT_EP_DISABLE_OP_TYPE_FILTER="Conv"
asr_file_demo ~/.cache/models/assets/audio/001_zh_daily_weather.wav --engine zipformer
```

### 3.4 C++ 流式识别

先查看输入设备：

```bash
asr_stream_demo -l
```

根据实际设备编号运行：

```bash
asr_stream_demo \
    -i <device_id> \
    -c 2 \
    -t 60 \
    -f 3 \
    -p spacemit
```

该示例从麦克风采集 16kHz/2ch 音频并整理为单声道，每 3 秒 flush 一次当前缓冲并通过回调输出最终文本。

运行时会出现 `实时识别结果`、`定时 Flush`、`[回调] 最终结果` 等日志。若默认设备不符合预期，使用 `asr_stream_demo -l` 查看设备列表，再通过 `-i <id>` 指定设备。

### 3.5 Python 流式识别

安装 `spacemit-asr` 与 `spacemit-audio` 后，可运行：

```bash
cd components/model_zoo/asr/python/examples
python asr_stream_demo.py -c 2 -d <device_id>
```

示例会采集双声道音频并整理为单声道，日志包含 Flush 和识别结果。

### 3.6 Qwen3-ASR 0.6B / 1.7B 服务识别

Qwen3-ASR 通过 `llama-server` 提供 OpenAI 兼容的 chat completions 接口。K1 软件源当前不提供 `llama.cpp-tools-spacemit`，使用 0.1.7 的 release 包部署运行时：

```bash
RUNTIME=~/.cache/releases
mkdir -p $RUNTIME/llama.cpp
cd $RUNTIME/llama.cpp
wget https://github.com/spacemit-com/llama.cpp/releases/download/v0.1.7/spacemit-llama.cpp.riscv64.0.1.7.tar.gz
tar -xzf spacemit-llama.cpp.riscv64.0.1.7.tar.gz
```

该运行时依赖 ONNX Runtime 1.24.2 与 `libspine_tcm` 3.0.0。系统自带库版本不满足要求，从软件源取出对应 deb 解压到本地目录，无需替换系统库：

```bash
cd $RUNTIME
wget https://archive.spacemit.com/bianbu/pool/main/s/spacemit-onnxruntime/spacemit-onnxruntime_2.0.3-bpo1_riscv64.deb
wget https://archive.spacemit.com/bianbu/pool/main/s/spacemit-tcm/spacemit-tcm_3.0.0-bpo1+2_riscv64.deb
dpkg-deb -x spacemit-onnxruntime_2.0.3-bpo1_riscv64.deb onnxruntime
dpkg-deb -x spacemit-tcm_3.0.0-bpo1+2_riscv64.deb tcm
```

把环境写入可复用脚本，后续每个后端启动前先 `source` 一次：

```bash
cat > ~/asr-runtime.sh <<'EOF'
export ASR_RT=$HOME/.cache/releases
export PATH=$ASR_RT/llama.cpp/spacemit-llama.cpp.riscv64.0.1.7/bin:$PATH
export LD_LIBRARY_PATH=$ASR_RT/llama.cpp/spacemit-llama.cpp.riscv64.0.1.7/lib:$ASR_RT/onnxruntime/usr/lib:$ASR_RT/tcm/usr/lib:/usr/lib
export SPACEMIT_MEM_BACKEND=POSIX
EOF
source ~/asr-runtime.sh
```

`SPACEMIT_MEM_BACKEND=POSIX` 是 K1 上的必要配置，内核未提供透明大页接口，默认的 `HPAGE` 后端在加载模型时报 `unable to allocate CPU_RISCV64_SPACEMIT buffer`。

准备模型：

```bash
mkdir -p ~/.cache/models/asr
cd ~/.cache/models/asr

# 按需下载 0.6B、1.7B 或两个模型
wget https://archive.spacemit.com/spacemit-ai/model_zoo/asr/qwen3-asr-0.6B-dynq-q40.tar.gz
tar -xzf qwen3-asr-0.6B-dynq-q40.tar.gz

wget https://archive.spacemit.com/spacemit-ai/model_zoo/asr/qwen3-asr-1.7B-dynq-q40.tar.gz
tar -xzf qwen3-asr-1.7B-dynq-q40.tar.gz
```

0.6B 启动时需显式设置音频编码器的 CPU 绑核。K1 共 8 个 CPU 核，LLM 线程使用 `-t 4 -tb 4`；使用 `-t 8` 会因 SpaceMIT 后端首选核数为 4 而绑核失败。

```bash
export SPACEMIT_EP_INTRA_THREAD_NUM=4
export SPACEMIT_EP_INTRA_THREAD_AFFINITY="0;1;2;3"

MODEL_DIR=~/.cache/models/asr/qwen3-asr-0.6B-dynq-q40
llama-server \
    -m "$MODEL_DIR/Qwen3-ASR-0.6B-text-q40.gguf" \
    --media-backend smt \
    --smt-config-dir "$MODEL_DIR" \
    --alias qwen3-asr \
    --host 127.0.0.1 --port 8063 \
    -t 4 -tb 4 -c 4096
```

1.7B 模型包的 `config.json` 在 `ep_config` 中内置 `SPACEMIT_EP_INTRA_THREAD_AFFINITY` 为 `8;9;10;11`，超出 K1 的 CPU 编号范围。删除该项，改由环境变量指定绑核后启动；模型配置与环境变量中的绑核列表会合并，两者同时存在时条目数超过线程数，报 `intra_thread_affinity size mismatch`。

```bash
MODEL_DIR=~/.cache/models/asr/qwen3-asr-1.7B-dynq-q40
python3 - "$MODEL_DIR/config.json" <<'EOF'
import json, sys
path = sys.argv[1]
with open(path) as f:
    config = json.load(f)
config.get("ep_config", {}).pop("SPACEMIT_EP_INTRA_THREAD_AFFINITY", None)
with open(path, "w") as f:
    json.dump(config, f, indent=2, ensure_ascii=False)
EOF

SPACEMIT_EP_INTRA_THREAD_NUM=4 \
SPACEMIT_EP_INTRA_THREAD_AFFINITY="0;1;2;3" \
llama-server \
    -m "$MODEL_DIR/Qwen3-ASR-1.7B-text-q40.gguf" \
    --media-backend smt \
    --smt-config-dir "$MODEL_DIR" \
    --alias qwen3-asr \
    --host 127.0.0.1 --port 8063 \
    -t 4 -tb 4 -c 4096
```

1.7B 的内存占用高于 0.6B，16G 内存配置下加载约需 60 秒。服务健康检查：

```bash
curl http://127.0.0.1:8063/health
```

在另一个终端调用：

```bash
asr_file_demo ~/.cache/models/assets/audio/001_zh_daily_weather.wav \
    --engine qwen3-asr \
    --endpoint http://127.0.0.1:8063/v1/chat/completions
```

> **说明**
>
> Qwen3-ASR 与本地 LLM 同时使用 SpaceMIT 推理后端时可能出现 `tcm buffer alloc failed`。需要同时运行时，参考 [4.5 Agent](../4.5-Agent.md) 的做法，ASR 改用 SenseVoice 并配置为 CPU provider。

### 3.7 Fun-ASR Nano 服务识别

Fun-ASR Nano 使用 `llama-server` 的 OpenAI 兼容 transcription 接口。按 3.6 节准备好运行时后，停止占用 8063 端口的其他服务，再下载模型：

```bash
mkdir -p ~/.cache/models/asr
cd ~/.cache/models/asr
wget https://archive.spacemit.com/spacemit-ai/model_zoo/asr/fun-asr-nano-2512-qq-q4km.tar.gz
tar -xzf fun-asr-nano-2512-qq-q4km.tar.gz
```

启动服务：

```bash
source ~/asr-runtime.sh
export SPACEMIT_EP_INTRA_THREAD_NUM=4
export SPACEMIT_EP_INTRA_THREAD_AFFINITY="0;1;2;3"

MODEL_DIR=~/.cache/models/asr/fun-asr-nano-2512-qq-q4km
llama-server \
    -m "$MODEL_DIR/qwen3-0.6b-q4km.gguf" \
    --media-backend smt \
    --smt-config-dir "$MODEL_DIR" \
    --alias funasr \
    --host 127.0.0.1 --port 8063 \
    -t 4 -tb 4 -c 4096 \
    --warmup --jinja
```

`llama.cpp-tools-spacemit` 0.1.1 及更早版本在初始化音频编码器时报 `Unexpected SMT audio ONNX IO signature`，无法加载 Fun-ASR Nano 的 ONNX 模型，需使用 0.1.7 及以上版本。

在另一个终端调用：

```bash
asr_file_demo ~/.cache/models/assets/audio/001_zh_daily_weather.wav \
    --engine funasr \
    --endpoint http://127.0.0.1:8063/v1/audio/transcriptions \
    --model funasr
```

Python 文件示例使用相同 endpoint：

```bash
python components/model_zoo/asr/python/examples/asr_file_demo.py \
    ~/.cache/models/assets/audio/001_zh_daily_weather.wav \
    --engine funasr \
    --endpoint http://127.0.0.1:8063/v1/audio/transcriptions \
    --model funasr
```

Fun-ASR Nano 当前只支持文件或整段 PCM 的阻塞识别，不支持 `Start()` / `SendAudioFrame()` / `Flush()` 形式的真流式识别。

### 3.8 Gemma4 ASR 转写与英文翻译

Gemma4 ASR 使用 `llama-server` 的 OpenAI 兼容 transcription 接口，同时支持原语言转写和外语语音转英文。按 3.6 节准备好 0.1.7 运行时后，停止占用 8063 端口的其他服务，再下载模型：

```bash
mkdir -p ~/.cache/models/asr
cd ~/.cache/models/asr
wget https://archive.spacemit.com/spacemit-ai/model_zoo/asr/gemma4-asr-E2B-q40.tar.gz
tar -xzf gemma4-asr-E2B-q40.tar.gz
```

启动服务：

```bash
source ~/asr-runtime.sh

MODEL_DIR=~/.cache/models/asr/gemma4-asr-E2B-q40
llama-server \
    -m "$MODEL_DIR/gemma-4-E2B-it-Q4_0-plproj-Q4_0-combined.gguf" \
    --media-backend smt \
    --smt-config-dir "$MODEL_DIR" \
    --host 127.0.0.1 --port 8063 \
    --alias gemma4-asr \
    -t 4 -tb 4 -c 4096 \
    --warmup --jinja --reasoning off \
    --no-cache-prompt
```

`--reasoning off` 用于确保输出 token 预算全部用于最终转写或译文，`--no-cache-prompt` 避免重复音频性能测试命中 prompt cache。Gemma4 ASR 要求 `llama.cpp-tools-spacemit` 0.1.7 及以上版本，0.1.1 在加载多模态投影层时因 `n_gpu_layers` 断言失败而中止。

服务健康检查通过后，在另一个终端执行：

```bash
curl http://127.0.0.1:8063/health

# 原语言转写
asr_file_demo ~/.cache/models/assets/audio/001_zh_daily_weather.wav \
    --engine gemma4-asr --task transcribe

# 日语语音翻译为英文
asr_file_demo ~/.cache/models/assets/audio/024_ja_funasr_sample.mp3 \
    --engine gemma4-asr --task translate
```

Python 示例使用相同的 engine 和 task：

```bash
python components/model_zoo/asr/python/examples/asr_file_demo.py \
    ~/.cache/models/assets/audio/024_ja_funasr_sample.mp3 \
    --engine gemma4-asr --task translate
```

`translate` 任务固定输出英文。Gemma4 ASR 只支持文件或整段 PCM 的阻塞请求，不支持 `Start()` / `SendAudioFrame()` / `Flush()` 形式的真流式识别。服务启动后的首个音频请求还会初始化动态 ONNX encoder session，性能评估应使用后续请求。

## 4. 应用开发

本章面向应用开发者，说明如何在自己的 C++ / Python 应用中集成 ASR 组件。完整接口以 `components/model_zoo/asr/include/asr_service.h` 为准；本节只介绍常用公开接口和典型调用方式。

ASR 的 C++ 入口是 `SpacemiT::AsrEngine`，Python 入口是 `spacemit_asr.Engine`。

### 4.1 接口说明

ASR 组件的核心入口是 `SpacemiT::AsrEngine`。应用侧通过该类创建引擎、配置后端和模型，并发起阻塞或流式识别请求。

#### 4.1.1 常用数据结构

| 类型 | 说明 |
| --- | --- |
| `AsrConfig` | 引擎配置。常用字段：`engine`、`model_dir`、`language`、`punctuation`、`sample_rate`、`provider`、`hotwords`、`hotword_boost`。可用 `Preset(name)` 创建预置配置。 |
| `Sentence` | 单句结果。字段 `text`、`begin_time`、`end_time`、`confidence`。 |
| `RecognitionResult` | 识别结果。提供 `GetText()`、`GetSentences()`、`IsSentenceEnd()`、`GetRTF()`、`GetAudioDuration()`、`GetProcessingTime()`、`IsEmpty()`、`GetRequestId()`。 |
| `AsrEngineCallback` | 流式回调基类。覆写 `OnOpen()`、`OnEvent(result)`、`OnComplete()`、`OnError(result)`、`OnClose()`。 |

#### 4.1.2 引擎初始化与预设

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `AsrEngine(engine, model_dir)` | 通过引擎名快速构造，模型路径为空时使用默认缓存路径。 | `engine`：sensevoice / zipformer / qwen3-asr；`model_dir`：可选模型目录。 | 引擎实例。 |
| `AsrEngine(AsrConfig)` | 使用完整配置构造。 | `config`：`AsrConfig` 实例。 | 引擎实例。 |
| `AsrConfig::Preset(name)` | 返回指定预设的 `AsrConfig`。 | `name`：sensevoice / zipformer。 | `AsrConfig`。 |
| `AsrConfig::AvailablePresets()` | 返回当前可用的预设名称列表。 | 无。 | `std::vector<std::string>`。 |
| `IsInitialized()` | 引擎是否成功初始化。 | 无。 | `bool`。 |
| `GetEngineName()` / `GetConfig()` | 获取当前引擎名 / 配置快照。 | 无。 | `string` / `AsrConfig`。 |

#### 4.1.3 阻塞识别

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `Call(file_path, phrase_id="")` | 识别 WAV/PCM 文件，内部完成解码与重采样。失败返回 `nullptr`。 | `file_path`：音频文件路径；`phrase_id`：可选请求标识。 | `shared_ptr<RecognitionResult>`。 |
| `Recognize(vector<int16_t>, sample_rate=16000)` | 识别内存中的 PCM16 单声道音频。 | `audio`：PCM16；`sample_rate`：采样率。 | `shared_ptr<RecognitionResult>`。 |
| `Recognize(vector<float>, sample_rate=16000)` | 识别 float32 PCM，幅度范围 `[-1.0, 1.0]`。 | 同上。 | `shared_ptr<RecognitionResult>`。 |

#### 4.1.4 流式识别

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `SetCallback(callback)` | 注册流式回调对象，必须在 `Start()` 之前调用。 | `callback`：`shared_ptr<AsrEngineCallback>`。 | 无。 |
| `Start(phrase_id="")` | 开始一次流式会话。 | `phrase_id`：可选请求标识。 | 无。 |
| `SendAudioFrame(data)` | 送入一帧 PCM 16kHz / 16bit / mono 数据。 | `data`：`vector<uint8_t>`。 | 无。 |
| `Flush()` | 立即识别当前缓冲并通过回调输出结果，会话不结束。 | 无。 | 无。 |
| `Stop()` | 结束本次流式会话并等待所有结果返回。 | 无。 | 无。 |

#### 4.1.5 运行时配置

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `SetLanguage(lang)` / `SetPunctuation(enabled)` | 运行时切换识别语言和标点开关。 | `lang`、`enabled`。 | 无。 |
| `SetHotwords(words, boost=1.0)` | 更新热词列表与权重。 | `words`、`boost`。 | 无。 |
| `LoadHotwordFile(path, default_boost=1.0)` | 从文件加载热词。 | `path`、`default_boost`。 | 无。 |
| `GetLastRequestId()` / `GetFirstPackageDelay()` / `GetLastPackageDelay()` | 获取请求标识和时延信息。 | 无。 | `string` / `int`。 |

### 4.2 C++ 调用示例

以下示例默认已完成 §2 构建；SenseVoice 模型位于 `~/.cache/models/asr/sensevoice/`。

#### 4.2.1 文件离线识别

适用场景：离线批量识别 WAV 文件、回归测试、固定音频回放。

调用步骤：

1. 用 `AsrConfig::Preset("sensevoice")` 创建预设配置，按需覆写 `language`、`punctuation`、`provider`。
2. 构造 `AsrEngine` 并通过 `IsInitialized()` 检查。
3. 调用 `Call(file_path)` 取回 `RecognitionResult`。
4. 用 `IsEmpty()` 判断后再读 `GetText()` 和 `GetRTF()`。

```cpp
#include <iostream>
#include <memory>
#include "asr_service.h"

int main() {
    SpacemiT::AsrConfig config = SpacemiT::AsrConfig::Preset("sensevoice");
    config.language = "zh";
    config.punctuation = true;
    config.provider = "spacemit";

    auto engine = std::make_shared<SpacemiT::AsrEngine>(config);
    if (!engine->IsInitialized()) {
        std::cerr << "ASR 引擎初始化失败" << std::endl;
        return 1;
    }

    auto result = engine->Call("test.wav");
    if (result && !result->IsEmpty()) {
        std::cout << "文本: " << result->GetText() << std::endl;
        std::cout << "音频: " << result->GetAudioDuration() << " ms"
                  << "  处理: " << result->GetProcessingTime() << " ms"
                  << "  RTF: " << result->GetRTF() << std::endl;
    }

    return 0;
}
```

完整版含命令行参数解析、多轮 warmup 和汇总统计，见 `components/model_zoo/asr/examples/asr_file_demo.cpp`。

#### 4.2.2 PCM 内存识别

适用场景：上游已经在内存中拿到 PCM，例如 audio 组件采集回调、网络推流或文件解码后，不希望再落盘成 WAV。

调用步骤：

1. 把上游 PCM 整理为 16kHz 单声道。多声道需先混音；非 16kHz 需先重采样。
2. 选择 `Recognize(vector<int16_t>)` 或 `Recognize(vector<float>)` 重载。
3. 处理返回的 `RecognitionResult`。

```cpp
#include <vector>
#include <iostream>
#include "asr_service.h"

void RecognizePcm(const std::vector<int16_t>& pcm_16k_mono) {
    SpacemiT::AsrEngine engine(SpacemiT::AsrConfig::Preset("sensevoice"));

    auto result = engine.Recognize(pcm_16k_mono, 16000);
    if (result && !result->IsEmpty()) {
        std::cout << result->GetText() << std::endl;
    }
}
```

float32 重载用法相同，幅度需归一化到 `[-1.0, 1.0]`：

```cpp
std::vector<float> pcm_float(pcm_16k_mono.size());

for (size_t i = 0; i < pcm_16k_mono.size(); ++i) {
    pcm_float[i] = pcm_16k_mono[i] / 32768.0f;
}

auto result = engine.Recognize(pcm_float, 16000);
```

#### 4.2.3 麦克风流式识别 + 回调

适用场景：实时识别、边录边出字幕、配合 VAD 做句末切分。

调用步骤：

1. 实现 `AsrEngineCallback` 子类，覆写 `OnEvent()` 处理中间/最终结果。
2. 构造引擎并 `SetCallback()`，再调用 `Start()`。
3. 将麦克风采集得到的 PCM 整理成 16kHz 单声道后，通过 `SendAudioFrame()` 送入。
4. 按定时或 VAD 触发 `Flush()`。
5. 退出前调用 `Stop()`。

```cpp
#include <iostream>
#include <memory>
#include "asr_service.h"

class StreamCallback : public SpacemiT::AsrEngineCallback {
public:
    void OnEvent(std::shared_ptr<SpacemiT::RecognitionResult> result) override {
        if (!result) return;

        const std::string text = result->GetText();
        if (text.empty()) return;

        if (result->IsSentenceEnd()) {
            std::cout << "[最终] " << text
                      << "  RTF=" << result->GetRTF()
                      << std::endl;
        } else {
            std::cout << "[中间] " << text << std::endl;
        }
    }

    void OnError(std::shared_ptr<SpacemiT::RecognitionResult> result) override {
        std::cerr << "[ASR] 错误: "
                  << (result ? result->GetText() : "unknown")
                  << std::endl;
    }
};
```

初始化：

```cpp
SpacemiT::AsrConfig config = SpacemiT::AsrConfig::Preset("sensevoice");
config.language = "zh";

auto engine = std::make_shared<SpacemiT::AsrEngine>(config);
auto callback = std::make_shared<StreamCallback>();

engine->SetCallback(callback);
engine->Start();
```

采集端得到整理后的 PCM 后：

```cpp
engine->SendAudioFrame(pcm_frame);
```

切句：

```cpp
engine->Flush();
```

退出：

```cpp
engine->Stop();
```

K1 麦克风实际使用时可能采用双声道采集，需要先混成单声道再送 ASR。完整采集、重采样和混音逻辑见 `components/model_zoo/asr/examples/asr_stream_demo.cpp`。

#### 4.2.4 热词加载

适用场景：识别专有名词、产品名、机器人指令等领域词。

调用步骤：

1. 构造时通过 `AsrConfig::hotwords` 配置热词，或运行时通过 `SetHotwords()` 切换。
2. 文件场景可使用 `LoadHotwordFile(path, default_boost)`。
3. 热词权重不宜设置过大，避免引入误识别。

```cpp
SpacemiT::AsrConfig config = SpacemiT::AsrConfig::Preset("sensevoice");
config.hotwords = {"SpacemiT", "进迭时空", "RISC-V"};
config.hotword_boost = 2.0f;

SpacemiT::AsrEngine engine(config);

engine.SetHotwords({"K1", "MUSE", "Pi Pro"}, 2.0f);
engine.LoadHotwordFile("hotwords.txt", 2.0f);

auto result = engine.Call("test.wav");
```

## 5. 调试指南

调试 ASR 时建议先固定输入音频，再分别确认模型、后端和采集设备状态：

- 用 `audio_demo play` 回放输入 WAV，确认音频非静音、采样率和声道数符合预期。
- 通过 `asr_stream_demo -l` 列出输入设备，确认麦克风设备索引后再指定 `-i <id>`。
- 性能评估以 warmup 后的正式结果为准，避免把模型加载时间计入稳定推理时延。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 首次识别很慢 | 模型加载和 warmup 被计入首次运行 | 使用 warmup 后的结果评估性能。 |
| 识别文本为空或很短 | 输入音频过短、静音或采样率不匹配 | 用 `audio_demo play` 回放，确认 WAV 为 16kHz 有声内容。 |
| 流式采集报设备错误 | 默认输入设备不符合预期 | 先运行 `asr_stream_demo -l`，再用 `-i <id>` 指定设备。 |
| Zipformer 运行异常 | 当前运行配置需要过滤 `Conv` | 设置 `SPACEMIT_EP_DISABLE_OP_TYPE_FILTER="Conv"`。 |
| Qwen3-ASR 启动报 `required 4, available 0` | 未指定 SMT AudioEncoder 的 CPU affinity | 设置 `SPACEMIT_EP_INTRA_THREAD_AFFINITY="0;1;2;3"`。 |
| `llama-server` 报 `exceeds perfer_core_ids size 4` 后中止 | LLM 线程数超过 SpaceMIT 后端首选核数 | 将 `-t`、`-tb` 改为 `4`。 |
| 1.7B 报 `Invalid intra_thread_affinity id 8` | 模型包内置的绑核编号超出 K1 的 CPU 范围 | 将模型 `config.json` 中该项改为 `0;1;2;3`。 |
| 1.7B 报 `intra_thread_affinity size mismatch: expected 4, got 8` | 模型配置与环境变量同时设置了绑核，条目被合并 | 删除模型 `config.json` 中 `ep_config` 的 `SPACEMIT_EP_INTRA_THREAD_AFFINITY`，改用环境变量指定。 |
| 加载模型报 `unable to allocate CPU_RISCV64_SPACEMIT buffer` | 默认 HPAGE 内存后端在 K1 上不可用 | 设置 `SPACEMIT_MEM_BACKEND=POSIX`。 |
| 加载模型报 `libspert.so.1: cannot open shared object file` 或 `VERS_1.24.2 not found` | release 包要求的 ONNX Runtime 与系统库版本不一致 | 按 3.6 节把 ONNX Runtime 1.24.2 与 `libspine_tcm` 解压到本地目录并加入 `LD_LIBRARY_PATH`。 |
| Fun-ASR Nano 报 `Unexpected SMT audio ONNX IO signature` | 运行时版本低于 0.1.7 | 升级到 0.1.7 及以上版本。 |
| Gemma4 加载报 `GGML_ASSERT(params.n_gpu_layers < 0) failed` | 运行时版本低于 0.1.7，不支持多模态投影层 | 升级到 0.1.7 及以上版本。 |
| 编译 zipformer 报 `'__fp16' does not name a type` | GCC 13 未实现 `__fp16`，ONNX Runtime 头文件在 `__riscv_zfh` 下使用该类型 | 使用 `SROBOTIS_SKIP_DEPS_CHECK=1 mm -DCMAKE_CXX_FLAGS="-U__riscv_zfh"` 编译。 |
| 报 `tcm buffer alloc failed` | ASR 与 LLM 同时占用 SpaceMIT 后端 TCM 资源 | ASR 改用 SenseVoice CPU provider，或分时运行。 |
