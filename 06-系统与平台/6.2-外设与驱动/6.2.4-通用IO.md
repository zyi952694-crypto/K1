# 外设与驱动 · misc_io

## 1. 模块概述

- 主要功能：`misc_io` 模块位于 `components/peripherals/misc_io`，提供基于 Linux GPIO 的通用数字输入/输出封装，用于快速接入蜂鸣器、继电器、拨码开关、限位开关、简单数字传感器等零散 IO 外设。模块统一封装了 GPIO 打开、方向申请、电平读写、输入去抖和状态变化回调流程。  
- 规格或特性：对外以 `misc_io.h` + `libmisc_io.so` 形式提供 C 接口；依赖 `libgpiod` 访问 `/dev/gpiochip*`；兼容 `libgpiod` v1/v2；支持输入和输出两种方向、`active high/active low` 两种逻辑定义、去抖时间配置和回调触发；输入场景下 `misc_io_get()` 返回的是"当前是否 active"的逻辑值，不是原始电平值；v2 分支通过后台线程每 `10 ms` 轮询一次电平变化，v1 分支基于 `gpiod_line_event_wait()` 等待边沿事件。  
- 软件框图：见下图。  

![模块流程图](./assets/misc_io_framework.png)

## 2. 环境准备

### 前置条件

- 运行环境：K1 MUSE Pi Pro 开发板及配套 Linux 系统（Bianbu 2.3.5、Linux 6.6.63）。
- 硬件与连接：目标板需要暴露 Linux 可访问的 GPIO 控制器，并已连接好待测试的 IO 外设。调用者需要明确 `chip_name` 和 `line_offset`。K1 MUSE Pi Pro 的所有 GPIO 均位于 `gpiochip0`，`line_offset` 直接等于 GPIO 编号。
- 工具与权限：运行用户需要访问 `/dev/gpiochip*`；当设备节点权限受限时请使用 `sudo`。排查问题时建议准备 `gpioinfo`、`gpiodetect`、`gpioget`、`gpioset` 等工具，用于确认 line 是否存在、是否被占用以及原始电平状态。

### K1 MUSE Pi Pro 接线

K1 MUSE Pi Pro 的排针 GPIO 与按键部分共用，可复用按键测试的接线。下表中的物理针脚号指排针位置，GPIO 编号指 Linux GPIO 逻辑编号，两者不是同一套编号。针脚定义参考 [K1 MUSE Pi Pro 用户指南](https://github.com/spacemit-com/docs-product/blob/main/zh/k1_series/k1_muse_pi_pro/pi_pro_user_guide.md)。GPIO 输入使用 3.3 V 电平；不要向 GPIO 输入端接入 5 V。

| 功能 | 排针物理针脚 | Linux GPIO | 方向 |
| --- | ---: | ---: | --- |
| 输入触发 / 读取 | 22 | GPIO49 | 输入 |
| 输出控制 | 26 | GPIO50 | 输出 |
| GND | 20 或 25 | GND | — |

接线方式：

~~~text
物理针脚 22（GPIO49） ── 测试线 ── GND（物理针脚 20 或 25）
物理针脚 26（GPIO50） ── 测试线 ── GND（物理针脚 20 或 25）
~~~

使用杜邦线模拟输入触发时，将 GPIO49 线的自由端与 GND 短暂接触再松开即可产生上升沿。GPIO50 作为输出使用时不需要外接 GND，程序直接控制其电平。

## 3. 示例使用（从 0 跑通）

本节为读者**按步骤复现**的主线：

K3 示例默认使用 `gpiochip2 + line_offset 19`，K1 MUSE Pi Pro 的 GPIO 全部位于 `gpiochip0`。运行前需要按实际接线修改演示程序配置。

### 3.1 修改示例源码

打开示例源码：

```bash
cd ~/spacemit_robot
nano components/peripherals/misc_io/example/test_misc_io.c
```

需要修改三处：

**修改 1：`test_trigger()` 的 GPIO 配置**

将 `line_offset` 改为 K1 的 GPIO49：

```c
int test_trigger(void)
{
    struct misc_gpiod_ctx ctx = {
        .chip_name = "gpiochip0",
        .line_offset = 49,    // K1: GPIO49（物理针脚 22）
    };
```

**修改 2：`test_get_io()` 的 GPIO 配置**

将 `line_offset` 从默认的 61 改为 K1 的 GPIO49：

```c
int test_get_io(void)
{
    struct misc_gpiod_ctx ctx = {
        .chip_name = "gpiochip0",
        .line_offset = 49,    // K1: GPIO49（物理针脚 22）
    };
```

**修改 3：`test_set_io()` 的 GPIO 配置**

将 `line_offset` 从默认的 9 改为 K1 的 GPIO50：

```c
int test_set_io(void)
{
    struct misc_gpiod_ctx ctx = {
        .chip_name = "gpiochip0",
        .line_offset = 50,    // K1: GPIO50（物理针脚 26）
    };
```

**修改 4：`main()` 增加命令行参数选择**

将 `main` 函数改为通过 `argv[1]` 选择运行哪个测试，方便一次编译跑全部三种测试：

```c
int main(int argc, char **argv)
{
    const char *mode = (argc > 1) ? argv[1] : "trigger";
    if (strcmp(mode, "get") == 0)
        test_get_io();
    else if (strcmp(mode, "set") == 0)
        test_set_io();
    else
        test_trigger();

    return 0;
}
```

修改完成后重新编译：

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-minimal

cd ~/spacemit_robot/components/peripherals/misc_io
mm -DBUILD_TESTS=ON
```

预期现象：构建成功结束，`output/staging/bin/test_misc_io` 已更新。

### 3.2 运行输入触发回调测试

```bash
sudo LD_LIBRARY_PATH=~/spacemit_robot/output/staging/lib \
  ~/spacemit_robot/output/staging/bin/test_misc_io trigger
```

> **说明**：`sudo` 不会继承当前 shell 的 `PATH` 和 `LD_LIBRARY_PATH`，因此需要显式指定库路径。如果已通过 `source build/envsetup.sh` 加载环境，也可以先确认 `test_misc_io` 是否在 PATH 中。

预期现象：程序进入常驻等待，不会立即退出。将 GPIO49 的测试线自由端短暂接触 GND 后松开，终端打印形如：

```text
[cb] count=2 ev=ACTIVE timestamp_us=1793239444562121
```

每次"接触→松开"会产生两个事件（INACTIVE 和 ACTIVE），`g_count` 对每个事件都自增，但仅在 `MISC_EV_ACTIVE` 时才打印，因此 `count` 每次跳 2 属于正常行为。多碰几次，`count` 依次递增。按 `Ctrl+C` 退出。

### 3.3 运行输入电平读取测试

```bash
sudo LD_LIBRARY_PATH=~/spacemit_robot/output/staging/lib \
  stdbuf -oL ~/spacemit_robot/output/staging/bin/test_misc_io get
```

预期现象：程序每秒打印一行 `get_value:1`（扩展板硬件上拉，未接 GND 时为高电平，`active_logic = MISC_ACTIVE_HIGH` 时逻辑值为 1）。若将 GPIO49 线碰 GND，应看到 `get_value:0`。程序持续 50 次后自动退出，或按 `Ctrl+C` 提前结束。

> **说明**：`stdbuf -oL` 强制行缓冲，确保输出不被管道缓冲延迟。

### 3.4 运行输出控制测试

```bash
sudo LD_LIBRARY_PATH=~/spacemit_robot/output/staging/lib \
  stdbuf -oL ~/spacemit_robot/output/staging/bin/test_misc_io set
```

预期现象：程序循环打印 `set hight` 和 `set low`，每次间隔 2 秒，共 10 次。GPIO50 对应的物理针脚 26 上可观察到电平交替变化。可通过以下命令交叉验证：

```bash
cat /sys/kernel/debug/gpio | grep "gpio-50"
```

程序运行时应看到 `gpio-50` 在 `out hi` 和 `out lo` 之间切换。

## 4. 应用开发

### 4.1 最简使用流程

```c
static void on_misc_event(struct misc_dev *dev, enum misc_event ev, void *args)
{
    (void)dev;
    (void)args;
    printf("event=%d\n", ev);
}

int main(void)
{
    struct misc_gpiod_ctx ctx = {
        .chip_name = "gpiochip0",
        .line_offset = 49,
        .consumer = "misc_demo",
    };

    struct misc_dev *dev = misc_io_alloc(MISC_TYPE_GENERIC, MISC_DIR_INPUT, &ctx);
    if (!dev) {
        return -1;
    }

    misc_io_config(dev, MISC_ACTIVE_HIGH, 50);
    misc_io_trigger(dev, on_misc_event, NULL);

    sleep(10);

    misc_io_free(dev);
    return 0;
}
```

### 4.2 主要 API 说明

**1. 设备创建与配置**
```c
// 创建设备
struct misc_dev *misc_io_alloc(enum misc_type type, enum misc_dir dir, void *hw_ctx);

// 配置 active 逻辑和去抖时间
void misc_io_config(struct misc_dev *dev, enum misc_logic active_logic, uint16_t debounce_ms);

// 释放设备资源
void misc_io_free(struct misc_dev *dev);
```

**2. 输入输出操作**
```c
// 写输出状态
int misc_io_set(struct misc_dev *dev, bool active);

// 读取当前逻辑状态
int misc_io_get(struct misc_dev *dev);
```

**3. 事件触发**
```c
// 启动输入监控并注册回调
void misc_io_trigger(struct misc_dev *dev, misc_cb_t cb, void *args);

// 输入事件回调原型
typedef void (*misc_cb_t)(struct misc_dev *dev, enum misc_event ev, void *args);
```

### 4.3 核心数据结构

**GPIO 上下文**
```c
struct misc_gpiod_ctx {
    const char *chip_name;
    unsigned int line_offset;
    const char *consumer;
};
```

**逻辑与事件枚举**
```c
enum misc_logic {
    MISC_ACTIVE_LOW = 0,
    MISC_ACTIVE_HIGH
};

enum misc_event {
    MISC_EV_ACTIVE = 0,
    MISC_EV_INACTIVE,
};
```

**设备句柄**
```c
struct misc_dev;
```

开发时需要注意：`misc_io_alloc()` 依赖 `chip_name` 和 `line_offset` 的正确板级映射；`misc_io_set()` 和 `misc_io_get()` 返回的是逻辑上的 active/inactive，不是 GPIO 原始电平；`misc_io_trigger()` 仅适用于输入方向，首次调用会启动后台线程；回调运行在模块内部线程上下文中，应避免阻塞和耗时 I/O。

**参考 demo 或示例路径**
```text
components/peripherals/misc_io/example/test_misc_io.c
components/peripherals/misc_io/src/misc_io.c
```

## 5. ROS 2 节点

SDK 同时提供 ROS 2 节点 `peripherals_misc_io_node`，通过 YAML 参数文件配置。节点采用发布/订阅模型：命令话题控制输出 IO，状态和事件话题上报输入 IO 状态变化。

### 5.1 构建节点

```bash
cd ~/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-minimal

cd ~/spacemit_robot/middleware/ros2/peripherals/misc_io
mm
```

构建完成后，节点安装至 `output/staging/lib/peripherals_misc_io_node/misc_io_node`，参数文件模板位于 `output/staging/share/peripherals_misc_io_node/params/misc_io_node.yaml`。

### 5.2 K1 参数配置

K3 默认参数使用 `gpiochip2 + line_offset 19`，K1 需要改用 `gpiochip0` 并按实际接线设置 `line_offset`。在 `output/staging/share/peripherals_misc_io_node/params/` 目录下创建 K1 适配参数文件 `misc_io_node_k1.yaml`：

```yaml
misc_io_node:
  ros__parameters:
    command_topic: "misc_io/command"
    state_topic: "misc_io/state"
    event_topic: "misc_io/events"
    frame_id: "misc_io"
    publish_period_ms: 100

    # K1 MUSE Pi Pro: one input trigger + one output control
    io_ids: [0, 1]
    types: [3, 3]
    dirs: [0, 1]
    active_logics: [1, 1]
    debounce_mss: [20, 0]
    chip_names: ["gpiochip0", "gpiochip0"]
    line_offsets: [49, 50]
    consumers: ["status_input_0", "control_output_0"]
    io_names: ["status_input_0", "control_output_0"]
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `io_ids` | 逻辑 IO ID，必须唯一 |
| `types` | 设备类型，`0=GENERIC 1=BUZZER 2=RELAY 3=SWITCH 4=SENSOR` |
| `dirs` | 方向，`0=INPUT 1=OUTPUT` |
| `active_logics` | 有效电平，`0=ACTIVE_LOW 1=ACTIVE_HIGH` |
| `debounce_mss` | 去抖时间（ms），主要对输入 IO 有意义 |
| `chip_names` | GPIO 芯片名，K1 统一为 `gpiochip0` |
| `line_offsets` | GPIO line offset，K1 等于 GPIO 编号 |
| `consumers` | libgpiod consumer 名字，可选 |
| `io_names` | 仅用于日志打印，可选 |

## 6. 调试指南

- 如果 `misc_io_alloc()` 失败，优先检查 `chip_name`、`line_offset` 和 `/dev/gpiochip*` 权限，并确认该 GPIO 没有被其他进程占用。可通过 `cat /sys/kernel/debug/gpio | grep "gpio-49"` 查看 GPIO 是否已被申请（`unused` 表示未被占用，有 consumer 名字表示已被占用）。  
- 如果输入电平变化了但没有回调，优先核对设备方向、`active_logic` 和 `debounce_ms`，必要时结合 `gpioinfo` / `gpioget` 交叉验证。  
- 如果 `misc_io_get()` 的结果和原始电平相反，先确认它返回的是逻辑上的 active/inactive，而不是 GPIO 原始高低电平。  
- `sudo` 运行时 `LD_LIBRARY_PATH` 不会自动继承，需要显式指定：`sudo LD_LIBRARY_PATH=/root/spacemit_robot/output/staging/lib <command>`。  
- 如果程序输出被管道缓冲截断，使用 `stdbuf -oL` 强制行缓冲。  

## 7. 常见问题

- `misc_io_alloc()` 返回 `NULL`：通常是 `chip_name`、`line_offset` 不正确，或 GPIO line 已被占用。  
- `misc_io_set()` 返回负值：通常是句柄无效，或当前设备是输入方向，不能执行输出写入。  
- `misc_io_get()` 返回值和原始电平相反：这是因为它返回的是 active/inactive 逻辑值，不是原始 GPIO 电平。  
- `test_misc_io` 运行报 `libmisc_io.so: cannot open shared object file`：`sudo` 不继承 `LD_LIBRARY_PATH`，需显式指定库路径。  
- 上一个 `test_misc_io` 进程未退出导致后续 `misc_io_alloc()` 失败：先 `pkill test_misc_io` 再重试。
