# 6.1.1 系统控制

## 1. 模块概述

系统控制模块位于 `components/system/sys`，向应用层提供系统电源模式管理、看门狗喂狗和唤醒源配置能力。

模块对外以 `sys.h` + `libsys.a` 形式提供 C 接口。`SYS_MODE_ACTIVE`、`SYS_MODE_IDLE`、`SYS_MODE_SENSOR_OFF` 三种工作模式在 K1 上可直接验证，其余模式涉及系统挂起与关机，不在本文范围内。

| 模式 | 行为 |
| --- | --- |
| `SYS_MODE_ACTIVE` | CPU governor 设为 `performance`，网卡保持启用 |
| `SYS_MODE_IDLE` | CPU governor 设为 `powersave`，网卡保持启用 |
| `SYS_MODE_SENSOR_OFF` | 同 IDLE，并预留传感器下电逻辑 |

调用 `sys_set_mode()` 前会依次执行已注册的钩子函数，任一钩子返回非 0 则中止切换。切换成功后 `sys_get_mode()` 返回新模式值。

除模式管理外，模块还提供：

- 网络唤醒（WoL）：通过 `ethtool` ioctl 设置网卡 Wake-on-LAN
- GPIO 唤醒：通过 `/sys/class/gpio` 导出引脚并配置 `edge` 触发沿
- 系统信息：读取 CPU 温度（`/sys/class/thermal`）、ADC 原始值（IIO sysfs）和 NTC 温度

相关目录结构：

| 路径 | 职责 |
| --- | --- |
| `components/system/sys/include/sys.h` | 对外公开的模式枚举、钩子原型和 API 声明 |
| `components/system/sys/src/sys.c` | 模式切换、唤醒源和系统信息的具体实现 |
| `components/system/sys/test/test_sys.c` | 官方测试用例 |
| `components/system/sys/CMakeLists.txt` | 构建配置，`BUILD_SYS_TESTS` 控制是否编译测试 |
| `components/system/sys/README.md` | 模块说明与使用示例 |

## 2. 环境准备

### 前置条件

- 运行环境：Bianbu 2.3.x（K1 Muse Pi Pro），CMake ≥ 3.16，GCC 13.2
- 依赖：标准 C 库、`libm`
- 权限：模式切换中的 governor 设置、GPIO 导出需 root

K1 Muse Pi Pro 上相关 sysfs 节点：

| 项目 | 路径 | 说明 |
| --- | --- | --- |
| thermal zone | `/sys/class/thermal/thermal_zone0`、`thermal_zone1` | 类型分别为 `cluster0_thermal`、`cluster1_thermal` |
| GPIO 控制器 | `/sys/class/gpio/` | 提供 `gpiochip0`、`gpiochip512` |
| IIO 设备 | `/sys/bus/iio/devices/iio:device0` | 提供 `in_voltage0~5_raw` |
| CPU 调频 | `/sys/devices/system/cpu/cpu0/cpufreq/` | 支持 `powersave`、`performance` 等 governor |

### 构建编译

方式 1：独立编译

```bash
cd components/system/sys
cmake -S . -B build -DBUILD_SYS_TESTS=ON
cmake --build build -j$(nproc)
```

方式 2：SDK 集成编译

```bash
source build/envsetup.sh
cd components/system/sys
mm
```

产物为 `build/libsys.a` 与 `build/test_sys`；SDK 编译时安装到 `output/staging/{lib,include}`。

只编译库、不编译测试：

```bash
cmake -S . -B build -DBUILD_SYS_TESTS=OFF
cmake --build build -j$(nproc)
```

## 3. 示例使用

保存为 `sys_demo.c`：

```c
#include <sys.h>
#include <stdio.h>
#include <stdlib.h>
#include <assert.h>

static int hook_called = 0;

int on_mode_change(enum sys_mode mode, void *ctx)
{
    printf("  [hook] target=%d ctx=%s\n", mode, (char *)ctx);
    hook_called++;
    return 0;
}

int block_hook(enum sys_mode mode, void *ctx)
{
    (void)mode;
    (void)ctx;
    return -1;
}

int main(void)
{
    printf("=== sys test ===\n");

    printf("\n[1] Mode switching\n");
    assert(sys_get_mode() == SYS_MODE_ACTIVE);
    assert(sys_set_mode(SYS_MODE_IDLE) == 0);
    assert(sys_get_mode() == SYS_MODE_IDLE);
    assert(sys_set_mode(SYS_MODE_SENSOR_OFF) == 0);
    assert(sys_get_mode() == SYS_MODE_SENSOR_OFF);
    assert(sys_set_mode(999) == -1);
    sys_set_mode(SYS_MODE_ACTIVE);
    printf("    PASSED\n");

    printf("\n[2] Hook registration\n");
    hook_called = 0;
    sys_register_hook(on_mode_change, "ctx1");
    sys_register_hook(on_mode_change, "ctx2");
    assert(sys_set_mode(SYS_MODE_IDLE) == 0);
    assert(hook_called == 2);
    sys_set_mode(SYS_MODE_ACTIVE);
    printf("    PASSED\n");

    printf("\n[3] Hook blocking\n");
    sys_register_hook(block_hook, NULL);
    assert(sys_set_mode(SYS_MODE_IDLE) != 0);
    printf("    PASSED\n");

    printf("\n[4] GPIO wakeup\n");
    assert(sys_enable_wakeup_gpio(-1, false) == -1);
    assert(sys_enable_wakeup_gpio(49, true) == 0);
    printf("    PASSED\n");

    printf("\n[5] CPU temperature\n");
    float t = 0.0f;
    assert(sys_get_cpu_temperature(NULL) == -1);
    assert(sys_get_cpu_temperature(&t) == 0);
    printf("    CPU: %.2f C\n", t);
    printf("    PASSED\n");

    printf("\n[6] ADC and NTC\n");
    int raw = 0;
    float ntc = 0.0f;
    assert(sys_get_adc_value(-1, &raw) == -1);
    assert(sys_get_adc_value(1, NULL) == -1);
    assert(sys_get_adc_value(1, &raw) == 0);
    assert(sys_get_ntc_temperature(1, &ntc) == 0);
    printf("    ADC ch1: %d, NTC: %.2f C\n", raw, ntc);
    printf("    PASSED\n");

    printf("\n=== all passed ===\n");
    return 0;
}
```

编译并运行：

```bash
cd components/system/sys
gcc -O2 -o /tmp/sys_demo sys_demo.c build/libsys.a -I include -lm
sudo /tmp/sys_demo
```

其中 `-I include` 指向模块头文件目录，`build/libsys.a` 是上一节编译产出的静态库。

各项说明：

| 测试项 | 现象 |
| --- | --- |
| 模式切换 | governor 在 `powersave` 与 `performance` 之间切换，`sys_get_mode()` 返回值同步更新；传入 999 返回 -1 且模式不变 |
| 钩子注册 | 注册两个钩子后触发一次切换，两个钩子都被调用，`hook_called` 为 2 |

| GPIO 唤醒 | 非法引脚 -1 返回错误；GPIO49 成功导出并配置为 `active_low` |

## 4. 应用开发

### 4.1 最简使用流程

```c
#include <sys.h>
#include <stdio.h>

static int on_mode_change(enum sys_mode target, void *ctx)
{
    printf("mode -> %d\n", target);
    return 0;
}

int main(void)
{
    sys_register_hook(on_mode_change, NULL);

    if (sys_set_mode(SYS_MODE_IDLE) != 0) {
        return -1;
    }

    printf("current mode = %d\n", sys_get_mode());

    sys_set_mode(SYS_MODE_ACTIVE);
    return 0;
}
```

编译：

```bash
gcc -O2 -o demo demo.c build/libsys.a -I include -lm
```

### 4.2 主要 API

**模式管理**

```c
int sys_set_mode(enum sys_mode mode);   // 切换模式，返回 0 成功
enum sys_mode sys_get_mode(void);       // 读取当前模式
void sys_register_hook(sys_hook_t hook, void *ctx);  // 注册切换钩子
```

`sys_hook_t` 原型为 `int (*)(enum sys_mode target_mode, void *ctx)`，返回非 0 会阻止本次切换。

**唤醒源**

```c
int sys_enable_wakeup_net(bool enable);                 // 网络唤醒
int sys_enable_wakeup_gpio(int gpio, bool active_low);  // GPIO 唤醒
```

`sys_enable_wakeup_gpio()` 的 `active_low` 为 `true` 时把 `edge` 配成 `falling`（低电平触发），为 `false` 时配成 `rising`（高电平触发）。

**系统信息**

```c
int sys_get_cpu_temperature(float *temp);               // 读 thermal zone，返回摄氏度
int sys_get_adc_value(int channel, int *value);         // 读 in_voltageN_raw
int sys_get_ntc_temperature(int channel, float *temp);  // ADC 值按 B 常数换算温度
```

`sys_get_cpu_temperature()` 只匹配 `type` 以 `cluster` 开头的 thermal zone。K1 的两个 zone 类型分别是 `cluster0_thermal` 和 `cluster1_thermal`，均满足条件。

`sys_get_ntc_temperature()` 使用固定参数换算：`ADC_REF = 1.8V`、`R_REF = 10kΩ`、`B = 3380`、`T0 = 25°C`、`ADC_SCALE = 0.7326`。若实际硬件分压电阻或 NTC 型号不同，需相应调整这些宏。

### 4.3 可调宏

在 `src/sys.c` 顶部：

| 宏 | 默认值 | 用途 |
| --- | --- | --- |
| `MAX_SYS_HOOKS` | 100 | 最大钩子数量 |
| `DEFAULT_NET_DEVICE` | `eth0` | 网络唤醒目标网卡 |
| `ADC_REF` | 1.8 | ADC 参考电压 |
| `R_REF` | 10.0 | 分压电阻（kΩ） |
| `B_CONST` | 3380.0 | NTC B 常数 |
| `ADC_SCALE` | 0.7326 | ADC 计数到电压的换算系数 |

网络唤醒内部使用 `DEFAULT_NET_DEVICE`，默认值为 `eth0`。K1 有线网卡名为 `end0`，需将该宏改为 `end0` 后重新编译才能对 K1 生效。

## 5. 调试指南

查看当前 CPU governor：

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

查看可用 governor：

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors
```

K1 输出为 `conservative ondemand userspace powersave performance schedutil`。

查看温度：

```bash
for z in /sys/class/thermal/thermal_zone*; do echo -n "$z: "; cat $z/type; cat $z/temp; done
```

查看 ADC 原始值：

```bash
cat /sys/bus/iio/devices/iio:device0/in_voltage1_raw
cat /sys/bus/iio/devices/iio:device0/in_voltage1_scale
```

查看 GPIO 唤醒配置：

```bash
cat /sys/class/gpio/gpio49/edge
cat /sys/class/gpio/gpio49/direction
```

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Network control may require root privileges` | `ip link` 需要 root | 用 `sudo` 运行 |
| `Invalid system mode: 999` | 传入的模式值超出枚举范围 | 使用 `sys.h` 中定义的 `SYS_MODE_*` 常量 |
| `Invalid GPIO pin: -1` | GPIO 编号非法 | 传入板卡上实际可用的 GPIO 编号 |
| `No ADC raw node in_voltageN_raw found` | IIO 设备无对应通道 | 先 `ls /sys/bus/iio/devices/iio:device0/` 确认可用通道号 |
| `No CPU thermal zone with type prefix cluster found` | thermal zone 的 `type` 不以 `cluster` 开头 | 确认 `cat /sys/class/thermal/thermal_zone*/type` 的输出 |
| NTC 温度明显偏离实际 | 分压电阻或 NTC 型号与宏定义不符 | 按实际硬件修改 `ADC_REF`、`R_REF`、`B_CONST`、`ADC_SCALE` |
| 钩子返回非 0 导致切换失败 | 业务钩子主动阻断 | 检查钩子逻辑，确认返回值语义 |
