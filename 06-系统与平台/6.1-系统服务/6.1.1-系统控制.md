# 6.1.1 系统控制

## 1. 模块概述

系统控制模块位于 `components/system/sys`，向应用层提供模式管理和系统信息查询接口。

模块通过 `sys.h` 和 `libsys.a` 提供 C 接口，常用工作模式如下：

| 模式 | 行为 |
| --- | --- |
| `SYS_MODE_ACTIVE` | CPU governor 设为 `performance`，网卡保持启用 |
| `SYS_MODE_IDLE` | CPU governor 设为 `powersave`，网卡保持启用 |
| `SYS_MODE_SENSOR_OFF` | 同 IDLE，并预留传感器下电逻辑 |

调用 `sys_set_mode()` 前会依次执行已注册的钩子函数，任一钩子返回非 0 则中止切换。切换成功后 `sys_get_mode()` 返回新模式值。必需操作失败时返回非 0，并保留上次成功的模式；已执行的系统操作不自动回滚。

`sys_get_cpu_temperature()` 从 `/sys/class/thermal` 读取 CPU 温度。

相关目录结构：

| 路径 | 职责 |
| --- | --- |
| `components/system/sys/include/sys.h` | 对外公开的模式枚举、钩子原型和 API 声明 |
| `components/system/sys/src/sys.c` | 模式切换、唤醒源和系统信息的具体实现 |
| `components/system/sys/test/test_sys.c` | 官方测试用例 |
| `components/system/sys/CMakeLists.txt` | 构建配置，`BUILD_SYS_TESTS` 控制是否编译测试 |
| `components/system/sys/README.md` | 模块说明与使用示例 |

## 3. 示例使用

将以下代码保存为 `sys_demo.c`，读取当前模式和 CPU 温度：

```c
#include <sys.h>
#include <stdio.h>

int main(void)
{
    float temperature = 0.0f;
    printf("current mode = %d\n", sys_get_mode());
    if (sys_get_cpu_temperature(&temperature) != 0) {
        return 1;
    }
    printf("CPU: %.2f C\n", temperature);
    return 0;
}
```

编译并运行：

```bash
cd ~/spacemit_robot/components/system/sys
gcc -O2 -o /tmp/sys_demo sys_demo.c build/libsys.a -I include -lm
/tmp/sys_demo
```

## 4. 应用开发

### 4.1 模式切换钩子

注册钩子后，库在切换模式前调用钩子。以下回调返回非零值，阻止模式切换：

```c
#include <sys.h>
#include <stddef.h>

static int block_mode_change(enum sys_mode target, void *ctx)
{
    (void)target;
    (void)ctx;
    return -1;
}

int main(void)
{
    enum sys_mode before = sys_get_mode();
    sys_register_hook(block_mode_change, NULL);
    int result = sys_set_mode(SYS_MODE_IDLE);
    return result != 0 && sys_get_mode() == before ? 0 : 1;
}
```

### 4.2 主要 API

**模式管理**

```c
int sys_set_mode(enum sys_mode mode);   // 切换模式，返回 0 成功
enum sys_mode sys_get_mode(void);       // 读取当前模式
void sys_register_hook(sys_hook_t hook, void *ctx);  // 注册切换钩子
```

背光或看门狗设备不存在时跳过对应操作；设备存在但访问、配置或写入失败时，模式切换返回错误。

`sys_hook_t` 原型为 `int (*)(enum sys_mode target_mode, void *ctx)`，返回非 0 会阻止本次切换。

**系统信息**

```c
int sys_get_cpu_temperature(float *temp);               // 读 thermal zone，返回摄氏度
```

`sys_get_cpu_temperature()` 只匹配 `type` 以 `cluster` 开头的 thermal zone。两个 zone 类型分别是 `cluster0_thermal` 和 `cluster1_thermal`，均满足条件。

### 4.3 可调宏

在 `src/sys.c` 顶部：

| 宏 | 默认值 | 用途 |
| --- | --- | --- |
| `MAX_SYS_HOOKS` | 100 | 最大钩子数量 |
| `DEFAULT_NET_DEVICE` | `eth0` | 网络开关与网络唤醒的默认网卡；可被环境变量 `SYS_NET_DEVICE` 覆盖 |

以上宏为编译期常量。

## 5. 调试指南

查看当前 CPU governor：

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

查看可用 governor：

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_available_governors
```

输出示例为 `conservative ondemand userspace powersave performance schedutil`。

查看温度：

```bash
for z in /sys/class/thermal/thermal_zone*; do echo -n "$z: "; cat $z/type; cat $z/temp; done
```

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Network control failed` | `ip link` 执行失败，网卡名或权限不满足要求 | 检查 `SYS_NET_DEVICE`，用 `sudo` 运行 |
| `Invalid system mode: 999` | 传入的模式值超出枚举范围 | 使用 `sys.h` 中定义的 `SYS_MODE_*` 常量 |
| `No CPU thermal zone with type prefix cluster found` | thermal zone 的 `type` 不以 `cluster` 开头 | 确认 `cat /sys/class/thermal/thermal_zone*/type` 的输出 |
| 钩子返回非 0 导致切换失败 | 业务钩子主动阻断 | 检查钩子逻辑，确认返回值语义 |
