# 6.3.2 audio

## 1. 模块概述

`audio` 组件位于 `components/multimedia/audio`，基于 PortAudio 提供音频采集、播放、全双工 I/O、WAV 文件读写和重采样能力，可用于 ASR、TTS、VAD、语音控制等应用中的音频输入、输出和格式转换。

功能特性：

| 类别 | 支持 |
| --- | --- |
| 音频 I/O | 录音、播放、输入/输出设备枚举、全双工流。 |
| 数据格式 | PCM16 little-endian、WAV 文件。 |
| 重采样 | 线性重采样；可选 libsamplerate。 |
| API | C++ `audio_base.hpp`、`audio_duplex.hpp`、`audio_resampler.hpp`；Python 包 `spacemit_audio`。 |
| 示例 | C++ `audio_demo`、Python `python/examples/audio_demo.py`。 |

典型数据链路：

```text
麦克风/声卡 -> AudioCapture -> PCM/WAV/Resampler -> 业务模块
业务模块/WAV -> Resampler -> AudioPlayer -> 扬声器/声卡
```

主要目录：

| 路径 | 说明 |
| --- | --- |
| `components/multimedia/audio/include/audio_base.hpp` | `AudioCapture`、`AudioPlayer` 和全局配置。 |
| `components/multimedia/audio/include/audio_resampler.hpp` | C++/C 重采样接口。 |
| `components/multimedia/audio/include/audio_duplex.hpp` | 全双工音频接口。 |
| `components/multimedia/audio/examples/audio_demo.cpp` | C++ 命令行示例。 |
| `components/multimedia/audio/python/` | Python 包 `spacemit_audio` 和示例脚本。 |

## 2. 环境准备

### 前置条件

SDK 源码获取和基础编译环境配置统一参考 [1.7 构建编译](../../01-快速开始/1.7-构建编译.md)。完成 SDK 初始化后，回到本文继续执行“构建编译”。

后续命令默认在 K1 设备的 `spacemit_robot` SDK 根目录执行。

### 构建编译

系统缺少依赖时安装：

```bash
sudo apt install portaudio19-dev libasound2-dev libsndfile1-dev \
    libsamplerate0-dev alsa-utils pybind11-dev python3-build
```

在 SDK 根目录加载构建环境、选择 K1 target 并构建 audio：

```bash
cd /root/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
cd components/multimedia/audio
mm
```

构建完成后，C++ 示例安装到 `output/staging/bin/audio_demo`，Python 扩展安装到 `output/staging/lib/python/spacemit_audio`。需要构建 Python wheel 时，在系统 Python 环境中执行：

```bash
cd /root/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet
cd components/multimedia/audio
mm -py
```

注意：`m -py` / `mm -py` 用于构建 wheel，应在系统 Python 环境中执行；若已激活虚拟环境，先执行 `deactivate`。`~/.comm-env` 用于后面的安装和运行 Python 示例。

运行 Python 示例前，先安装虚拟环境依赖，并创建、激活 `~/.comm-env`；已有虚拟环境可直接激活：

```bash
sudo apt install python3-venv python3-pip
if [ ! -d "$HOME/.comm-env" ]; then
    /usr/bin/python3 -m venv ~/.comm-env
fi
source ~/.comm-env/bin/activate
```

然后二选一安装 Python 包。方式一，直接安装发布包：

```bash
python -m pip install spacemit-audio \
    --index-url https://git.spacemit.com/api/v4/projects/33/packages/pypi/simple
```

方式二，回到 SDK 根目录安装本地构建出的 wheel：

```bash
cd /root/spacemit_robot
python -m pip install output/wheels/components_multimedia_audio/spacemit_audio-*.whl \
    --index-url https://git.spacemit.com/api/v4/projects/33/packages/pypi/simple
```

wheel 必须与 K1 上的 CPython 版本和 RISC-V ABI 匹配。发布源未提供匹配包时，使用本机源码构建的 wheel。

也可直接使用 SDK 集成构建安装的 Python 扩展，在 SDK 根目录设置搜索路径：

```bash
cd /root/spacemit_robot
export PYTHONPATH="$PWD/output/staging/lib/python${PYTHONPATH:+:$PYTHONPATH}"
```

采用 staging 方式时，Python 版本须与构建扩展所用版本一致，每次新开终端需重新设置上述 `PYTHONPATH`。若使用虚拟环境，应先激活再设置路径。完成安装或路径配置后检查导入：

```bash
python3 -c "import spacemit_audio; print(spacemit_audio.get_config())"
```

## 3. 示例使用

### 3.1 列出设备

```bash
audio_demo list
arecord -l
aplay -l
```

`audio_demo list` 会分别列出输入和输出设备。后续录音、播放命令中的 `--device` 参数使用该程序列出的索引。设备索引由当前系统的设备枚举顺序决定，不同板卡或外接设备组合下可能不同。

### 3.2 录音

先按实际连接设备选择录音参数。以下以支持 48kHz 双声道的输入设备为例：

```bash
audio_demo record test.wav --duration 5 --rate 48000 --channels 2 --device 2
```

上例使用 HX-KZ03 USB 音频设备，输入索引为 `2`。设备索引、采样率和声道数应按本机 `audio_demo list` 与 ALSA 查询结果调整；这些参数由声卡能力决定，不是所有 K1 设备的固定配置。

预期日志包含：

```text
Recording 5s to test.wav...
Config: 48000Hz, 2ch, device=2
Opened: 48000Hz, 2 channels, int16
Saved ... bytes to test.wav
```

连接的 USB 摄像头音频输入仅提供单声道时，可按实际能力使用单声道参数，例如：

```bash
audio_demo record test_mono.wav --duration 2 --rate 16000 --channels 1 --device 0
```

### 3.3 播放

播放上一步录制的 WAV 文件：

```bash
audio_demo play ./test.wav -c 2 -d 1
```

上例中的设备 `1` 为板载 `snd-es8326` 输出设备。若选择的输出设备只支持单声道，播放双声道 WAV 时需将目标声道数改为 `1`。以下以索引为 `0` 的单声道输出设备为例：

```bash
audio_demo play ./test.wav -c 1 -d 0
```

`audio_demo play` 可按指定目标采样率及声道数转换 WAV 音频，再将数据送入播放设备。设备索引和目标参数应按 `audio_demo list` 与设备能力调整。

### 3.4 Python 示例

完成 §2 的 Python 包安装或路径配置后，运行 Python 示例脚本：

```bash
cd /root/spacemit_robot/components/multimedia/audio/python/examples
python3 audio_demo.py list
python3 audio_demo.py record test_stereo_48k.wav \
    --duration 2 --rate 48000 --channels 2 --device 2
python3 audio_demo.py play test_stereo_48k.wav \
    --rate 48000 --channels 2 --device 1
```

上例使用 HX-KZ03 输入和板载 `snd-es8326` 输出，设备编号及音频参数按本机枚举结果调整。Python 命令行示例支持 WAV 播放时的重采样和声道转换；Python API 的 `AudioPlayer.play_file()` 则按 WAV 文件本身的格式打开设备，不会自动转换，详见 §4.3。

## 4. 应用开发

本章说明如何在 C++ 和 Python 应用中集成 audio 组件。C++ 命名空间为 `SpacemitAudio::`；Python 包名为 `spacemit_audio`。完整接口以 `components/multimedia/audio/include/` 下的头文件为准。音频回调运行于 PortAudio 内部线程，回调中应只做轻量操作，并将数据交由业务线程处理。

### 4.1 接口说明

audio 组件的主要接口分布在三个头文件：`audio_base.hpp`（采集、播放和全局配置）、`audio_duplex.hpp`（全双工）及 `audio_resampler.hpp`（重采样，位于全局命名空间）。

#### 4.1.1 常用数据结构

| 类型 | 说明 |
| --- | --- |
| `SpacemitAudio::AudioConfig` | 全局默认配置，包含采样率、声道数、采集块字节数和输入/输出设备索引；设备索引 `-1` 表示使用系统默认设备。 |
| `SpacemitAudio::AudioCapture::Callback` | 录音回调 `void(const uint8_t* data, size_t size)`；`data` 为 PCM16 little-endian 字节流。 |
| `SpacemitAudio::AudioDuplex::Callback` | 全双工回调 `void(const float* input, float* output, size_t frames, int channels)`；输入和输出为范围 `[-1.0, 1.0]` 的 float PCM。 |
| `Resampler::Config` | 重采样配置，包含输入/输出采样率、声道数和重采样方法。 |
| `ResampleMethod` | `LINEAR_*` 方法始终可用；`SRC_*` 方法需在构建时启用 libsamplerate。 |

#### 4.1.2 全局配置

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `Init(AudioConfig)` / `Init(int...)` | 设置全局默认配置。参数 `-1` 表示保留当前值。 | `AudioConfig` 或采样率、声道数、采集块大小及设备索引。 | 无。 |
| `GetConfig()` | 获取当前全局配置。 | 无。 | `AudioConfig`。 |

#### 4.1.3 采集与播放

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `AudioCapture(device_index=-1)` | 创建采集器；`-1` 使用系统默认输入设备。 | 输入设备索引。 | 采集器实例。 |
| `AudioCapture::SetCallback(cb)` | 注册录音回调，应在 `Start()` 前调用。 | `std::function<void(const uint8_t*, size_t)>`。 | 无。 |
| `AudioCapture::Start(sample_rate=-1, channels=-1, chunk_size=-1)` | 启动录音；`-1` 使用全局配置。`chunk_size` 单位为字节。 | 采样率、声道数、每次回调字节数。 | `bool`。 |
| `AudioCapture::Stop()` / `Close()` / `IsRunning()` | 停止采集、关闭设备和查询状态。 | 无。 | `void` / `bool`。 |
| `AudioCapture::ListDevices()` | 枚举输入设备。 | 无。 | `(索引, 名称)` 列表。 |
| `AudioPlayer(device_index=-1)` | 创建播放器；`-1` 使用系统默认输出设备。 | 输出设备索引。 | 播放器实例。 |
| `AudioPlayer::Start(sample_rate=-1, channels=-1)` | 启动 PCM 播放流。 | 采样率、声道数。 | `bool`。 |
| `AudioPlayer::Write(data)` | 写入 PCM16 little-endian 数据。 | 字节数组或指针与字节数。 | `bool`。 |
| `AudioPlayer::PlayFile(file_path)` | 阻塞播放 WAV 文件。 | WAV 文件路径。 | `bool`。 |
| `AudioPlayer::Stop()` / `Close()` / `IsRunning()` / `ListDevices()` | 停止、关闭、查询状态或枚举输出设备。 | 无。 | 依接口返回 `void`、`bool` 或设备列表。 |

#### 4.1.4 全双工

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `AudioDuplex(input_device=-1, output_device=-1)` | 构造全双工对象，可分别指定输入、输出设备。 | 输入和输出设备索引。 | 全双工实例。 |
| `AudioDuplex::SetCallback(cb)` | 注册同步输入/输出回调，应在 `Start()` 前调用。 | 输入 float PCM、输出 buffer、帧数和声道数回调。 | 无。 |
| `AudioDuplex::Start(sample_rate=48000, channels=1, frames_per_buffer=480)` | 启动全双工流；480 帧对应 48kHz 下 10ms。默认值是 API 默认配置，不代表所有设备均支持。 | 采样率、声道数、每次回调帧数。 | `bool`。 |
| `AudioDuplex::Stop()` / `Close()` / `IsRunning()` | 停止、释放资源或查询状态。 | 无。 | `void` / `bool`。 |
| `ListInputDevices()` / `ListOutputDevices()` | 分别枚举全双工输入和输出设备。 | 无。 | `(索引, 名称)` 列表。 |

#### 4.1.5 重采样

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `Resampler(Config)` | 创建重采样器。 | 输入/输出采样率、声道数和重采样方法。 | `Resampler` 实例。 |
| `initialize()` | 初始化重采样器。 | 无。 | `bool`。 |
| `process(input)` | 对完整数据块进行一次性重采样。 | float PCM 数据。 | float PCM 数据。 |
| `processStreaming(input, end_of_input)` | 分块流式重采样；最后一块将 `end_of_input` 设为 `true`。 | float PCM 数据及是否为最后一块。 | float PCM 数据。 |
| `reset()` | 清空流式处理状态，供下一段数据使用。 | 无。 | `void`。 |
| `getRatio()` / `isUpsampling()` / `isDownsampling()` / `getConfig()` | 查询比例、方向和当前配置。 | 无。 | 对应属性。 |

### 4.2 C++ 调用示例

K1 SDK 构建安装的 audio 库为静态库 `libspacemit_audio.a` 和 `libaudio_resampler.a`，头文件位于 `output/staging/include`。以下 CMake 片段展示基本查找和链接方式：

```cmake
find_path(AUDIO_INCLUDE_DIR NAMES audio_base.hpp
    PATHS ${CMAKE_INSTALL_PREFIX}/include NO_DEFAULT_PATH)
find_library(AUDIO_LIB NAMES spacemit_audio
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_library(RESAMPLER_LIB NAMES audio_resampler
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_library(PORTAUDIO_LIB NAMES portaudio)
find_library(SAMPLERATE_LIB NAMES samplerate)
find_library(ALSA_LIB NAMES asound)
find_package(Threads REQUIRED)

add_executable(my_audio_app main.cpp)
target_compile_features(my_audio_app PRIVATE cxx_std_17)
target_include_directories(my_audio_app PRIVATE ${AUDIO_INCLUDE_DIR})
target_link_libraries(my_audio_app PRIVATE
    ${AUDIO_LIB} ${PORTAUDIO_LIB} ${ALSA_LIB} Threads::Threads)
# 使用 Resampler 时，增加：
# target_link_libraries(my_audio_app PRIVATE ${RESAMPLER_LIB})
# 构建启用了 libsamplerate 时，也链接：
# target_link_libraries(my_audio_app PRIVATE ${SAMPLERATE_LIB})
```

#### 4.2.1 设备枚举与选择

先枚举当前系统的输入、输出设备，再根据设备支持情况选择设备索引、采样率和声道数：

```cpp
#include <iostream>
#include <utility>
#include "audio_base.hpp"

int main() {
    std::cout << "输入设备:" << std::endl;
    for (const auto& [index, name] : SpacemitAudio::AudioCapture::ListDevices())
        std::cout << "  [" << index << "] " << name << std::endl;

    std::cout << "输出设备:" << std::endl;
    for (const auto& [index, name] : SpacemitAudio::AudioPlayer::ListDevices())
        std::cout << "  [" << index << "] " << name << std::endl;
    return 0;
}
```

#### 4.2.2 录音回调

采集回调只执行轻量操作，例如统计数据量或将 PCM 数据放入线程安全队列；不要在 PortAudio 回调线程中运行耗时推理。

```cpp
#include <atomic>
#include <chrono>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <thread>
#include "audio_base.hpp"

int main() {
    std::atomic<size_t> received_bytes{0};
    SpacemitAudio::AudioCapture capture(-1);  // 也可指定已枚举的输入设备索引
    capture.SetCallback([&](const uint8_t*, size_t size) {
        received_bytes.fetch_add(size, std::memory_order_relaxed);
    });

    if (!capture.Start(16000, 1, 3200)) return 1;
    std::this_thread::sleep_for(std::chrono::seconds(2));
    capture.Stop();
    capture.Close();
    std::cout << "captured " << received_bytes.load() << " bytes of PCM16\n";
    return 0;
}
```

`16000Hz` 单声道是接口示例参数。运行前先枚举设备，并按 §5 查询 ALSA 硬件参数，确认输入设备支持相应配置，再调整设备索引和音频参数。

#### 4.2.3 播放 PCM 与 WAV

已有 PCM16 字节流可直接写入播放器；播放 WAV 文件时，`PlayFile()` 会阻塞到播放结束：

```cpp
#include <cstdint>
#include <string>
#include <vector>
#include "audio_base.hpp"

bool PlayPcm(const std::vector<uint8_t>& pcm16, int sample_rate, int output_device) {
    SpacemitAudio::AudioPlayer player(output_device);
    if (!player.Start(sample_rate, 1)) return false;
    const bool written = player.Write(pcm16);
    player.Stop();
    player.Close();
    return written;
}

bool PlayWav(const std::string& path, int output_device) {
    SpacemitAudio::AudioPlayer player(output_device);
    return player.PlayFile(path);
}
```

`PlayFile()` 按 WAV 文件自身的采样率和声道数打开输出设备，不会自动重采样或转换声道。若设备不支持该格式，可先用 `audio_demo play` 转换，或在应用中用 `Resampler` 转换 PCM 后再播放。

#### 4.2.4 全双工音频

全双工回调同步接收输入样本并填写输出 buffer，可用于需要输入/输出同步数据的音频应用。回调中的示例输出静音：

```cpp
#include <cstddef>
#include "audio_duplex.hpp"

int main() {
    SpacemitAudio::AudioDuplex duplex(-1, -1);
    duplex.SetCallback([](const float* input, float* output,
                          size_t frames, int channels) {
        // 将 input 交给音频处理逻辑；此处输出静音作为接口示例。
        (void)input;
        for (size_t i = 0; i < frames * static_cast<size_t>(channels); ++i)
            output[i] = 0.0f;
    });

    if (!duplex.Start(48000, 2, 480)) return 1;
    // 在业务线程执行应用逻辑。
    duplex.Stop();
    duplex.Close();
    return 0;
}
```

`48000Hz` 双声道是示例配置。使用 HX-KZ03 输入和板载 `snd-es8326` 输出时，可按枚举结果将构造参数改为 `AudioDuplex(2, 1)`；部署时应确保输入、输出设备均支持指定格式。`AudioDuplex` 提供同步音频流，回声消除需在应用中另行接入 AEC 算法。

#### 4.2.5 重采样

`Resampler` 支持完整数据块的一次性转换和分块流式转换。以下示例将单声道 float PCM 从 22050Hz 转为 48000Hz：

```cpp
#include <vector>
#include "audio_resampler.hpp"

std::vector<float> ResampleTo48k(const std::vector<float>& input_22k) {
    Resampler::Config config;
    config.input_sample_rate = 22050;
    config.output_sample_rate = 48000;
    config.channels = 1;
    config.method = ResampleMethod::LINEAR_UPSAMPLE;

    Resampler resampler(config);
    if (!resampler.initialize()) return {};
    return resampler.process(input_22k);
}
```

持续输入音频时，可使用 `processStreaming()` 逐块处理，并在最后一块将 `end_of_input` 设为 `true`。应根据实际输入、输出采样率和声道数设置 `Resampler::Config`。

### 4.3 Python 示例

Python 包名为 `spacemit_audio`，安装和路径配置见 §2。Python 绑定公开 `AudioCapture`、`AudioPlayer`、`init` 和 `get_config`；不包含 `AudioDuplex` 与 `Resampler`，全双工和独立重采样请使用 C++ API。

```python
import spacemit_audio

print(spacemit_audio.get_config())
print("输入设备:", spacemit_audio.AudioCapture.list_devices())
print("输出设备:", spacemit_audio.AudioPlayer.list_devices())
```

#### 4.3.1 录音

下面示例从已枚举的输入设备采集 PCM16。默认使用单声道摄像头音频设备的参数；若使用 HX-KZ03 等双声道设备，应按设备实际能力改为 48000Hz、2 声道和相应输入索引。

```python
import time
from spacemit_audio import AudioCapture, init

sample_rate = 16000
channels = 1
input_device = 0  # 请用 AudioCapture.list_devices() 检查当前设备索引
chunks = []

init(sample_rate=sample_rate, channels=channels, chunk_size=3200,
     capture_device=input_device)
with AudioCapture(input_device) as capture:
    capture.set_callback(lambda data: chunks.append(data))
    if not capture.start(sample_rate=sample_rate, channels=channels,
                         chunk_size=3200):
        raise RuntimeError("capture start failed")
    time.sleep(2)
    capture.stop()

print(f"captured {sum(len(chunk) for chunk in chunks)} bytes of PCM16")
```

`AudioCapture` 回调收到的 `data` 是 PCM16 little-endian `bytes`。本例 `chunk_size=3200` 表示每次回调的字节数，不是采样点数。

#### 4.3.2 播放

播放 PCM 数据时，需使用与数据采样率、声道数及输出设备匹配的参数：

```python
from spacemit_audio import AudioPlayer

pcm16_bytes = bytes(48000 * 2 * 2)  # 1 秒 48kHz 双声道静音；实际应用替换为 PCM16 音频数据
with AudioPlayer(1) as player:  # 先检查 AudioPlayer.list_devices()
    if not player.start(48000, 2):
        raise RuntimeError("player start failed")
    if not player.write(pcm16_bytes):
        raise RuntimeError("PCM write failed")
    player.stop()
```

播放 WAV 文件时，将文件路径指向 §3.4 录制的 `test_stereo_48k.wav`（相对路径以当前工作目录为准）：

```python
from spacemit_audio import AudioPlayer, init

output_device = 1  # 请根据本机输出设备列表调整
init(player_device=output_device)
with AudioPlayer(output_device) as player:
    if not player.play_file("test_stereo_48k.wav"):
        raise RuntimeError("WAV playback failed")
```

`play_file()` 按 WAV 文件自身的采样率和声道数打开设备，不会自动重采样或改变声道数。若 WAV 格式不受设备支持，请使用 Python 示例脚本 `audio_demo.py play`，该脚本包含采样率重采样和声道转换逻辑。

#### 4.3.3 C++ 与 Python 接口对照

| C++（`SpacemitAudio::`） | Python（`spacemit_audio`） | 说明 |
| --- | --- | --- |
| `Init(...)` / `GetConfig()` | `init(...)` / `get_config()` | Python 使用关键字参数；`get_config()` 返回字典。 |
| `AudioCapture`、`SetCallback`、`Start/Stop/Close` | `AudioCapture`、`set_callback`、`start/stop/close` | Python `AudioCapture` 支持上下文管理器；生命周期函数均为方法。 |
| `AudioCapture::ListDevices()` | `AudioCapture.list_devices()` | 返回 `(索引, 名称)` 元组组成的列表。 |
| `AudioPlayer`、`Start/Write/PlayFile/Stop/Close` | `AudioPlayer`、`start/write/play_file/stop/close` | Python `AudioPlayer` 支持上下文管理器。 |
| `AudioDuplex` | 未公开 | 使用 C++ API。 |
| `Resampler` | 未公开 | 使用 C++ API 或自行选择 Python 音频处理库。 |

## 5. 调试指南

调试时先分别检查设备枚举、录音和播放，再确认采样率及声道数：

```bash
audio_demo list
arecord -l
aplay -l
```

可用以下命令查询 ALSA 输入设备的硬件参数，并短时采集到 `/dev/null`：

```bash
arecord -D hw:2,0 --dump-hw-params -f S16_LE -r 48000 -c 2 \
    -d 1 -t raw /dev/null
```

其中 `hw:2,0` 是 ALSA 的声卡号和设备号，应按 `arecord -l` 的结果替换；它与 `audio_demo list` 的 PortAudio 索引属于不同编号体系，不能直接混用。设备编号可能随外接 USB 声卡变化。录音结果可先保存为 WAV，再通过支持该 WAV 格式的输出设备回放，并检查是否存在静音、削波或声道异常。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Requested 2 channels but device only has 1` | 选中的输入或输出设备只支持单声道。 | 选择支持双声道的设备，或将 `--channels` / 播放声道数改为 `1`。 |
| `Invalid sample rate` | 设备不支持当前采样率。 | 用 `arecord --dump-hw-params` 或 `audio_demo list` 检查设备能力，并选择受支持的采样率。 |
| Python `import spacemit_audio` 失败 | 未在当前 Python 环境安装匹配的包，或搜索路径没有包含 SDK staging。 | 按 §2 激活虚拟环境并安装匹配的 wheel；使用 staging 扩展时检查 `PYTHONPATH` 和 Python 版本。 |
| C++/Python `play_file()` 打开 WAV 失败 | WAV 的采样率或声道数不受输出设备支持；接口不会自动转换。 | 使用 `audio_demo play` 或 Python `audio_demo.py play` 转换格式，或在应用中先重采样。 |
| 播放声音速度或时长异常 | 播放参数与 PCM 数据实际采样率不一致。 | 检查 WAV 头或 PCM 数据来源，按目标设备要求转换后再播放。 |
