# 多媒体 · audio_process

## 1. 模块概述

`audio_process` 当前包含 DOA（Direction of Arrival，声源定位）组件，位于 `components/multimedia/audio_process/doa`。组件基于 GCC-PHAT（Generalized Cross-Correlation with Phase Transform）对麦克风音频进行时延估计，输出声源角度、TDOA 和置信度。

双声道 `SoundLocator` 的输出角度范围为 `[0°, 180°]`，其中 `90°` 表示垂直于麦克风连线的方向（常用作正前方）。组件也提供 `MultiSoundLocator`，可用于 3 个及以上麦克风的平面阵列定位，输出 `[0°, 360°)` 范围的方位角。双声道和多声道使用不同的坐标约定，应用集成时应根据实际阵列选择对应接口。

算法链路：

```text
音频输入 -> Hann 窗口 -> FFT -> 互功率谱 -> PHAT 加权
    -> 频域上采样 -> IFFT -> 峰值搜索 -> 抛物线插值 -> TDOA -> DOA
```

主要目录：

| 路径 | 说明 |
| --- | --- |
| `components/multimedia/audio_process/doa/include/doa_service.h` | C++ 对外 API。 |
| `components/multimedia/audio_process/doa/src/` | GCC-PHAT 和多声道定位实现。 |
| `components/multimedia/audio_process/doa/examples/ssl_demo.cpp` | C++ 示例，产物为 `ssl_demo`。 |
| `components/multimedia/audio_process/doa/python/` | Python 包 `spacemit_audio_process` 和示例。 |

双声道 `SoundLocator` 通过两个通道的互相关估计 TDOA，再根据麦克风间距、声速和通道方向换算 DOA。左右通道的物理位置、采样率、通道顺序和 `mic_distance` 必须与配置一致；若实际通道方向与应用坐标定义相反，可以在示例中使用 `--flip` 输出 `180 - doa`。

`SoundLocator` 没有前后向消歧能力，适合双麦克风的一维角度估计。需要完整 360° 方位感知时使用 `MultiSoundLocator`，并将 `microphones` 中的阵列位置按输入通道顺序配置。多声道实时应用应设置 `max_avg_seconds`，或周期性调用 `Reset()`，避免默认的无限历史窗口持续增长。

SDK 源码获取和基础编译环境配置参考 [1.7 构建编译](../../01-快速开始/1.7-构建编译.md)。实时采集模式还需要先构建 [6.3.2 audio](6.3.2-audio.md)。完成 SDK 初始化后，回到本文继续执行“构建编译”。

DOA 是纯音频算法组件，不需要模型文件。系统缺少依赖时先安装：

```bash
sudo apt install build-essential cmake pkg-config libfftw3-dev \
    pybind11-dev python3-build
```

在 SDK 根目录加载构建环境，选择 K1 target，然后构建 audio 和 DOA 组件：

```bash
cd /root/spacemit_robot
source build/envsetup.sh
lunch k1-muse-pipro-ai-cubpet

cd components/multimedia/audio
mm
cd ../audio_process/doa

```

构建完成后，`ssl_demo` 安装到 `output/staging/bin`，C++ 库为 `libsound_locator.a`，头文件安装到 `output/staging/include`。执行 `mm -py` 后，DOA 的 Python wheel 输出到 `output/wheels/components_multimedia_audio_process_doa/`。

选择本地 wheel 安装方式时，可在系统 Python 环境中构建 wheel；直接安装发布包时可跳过此步骤。若已激活虚拟环境，先执行 `deactivate`：

也可在 SDK 根目录执行 `m -py` 构建所选 target 的 Python wheel。

`m -py` / `mm -py` 用于构建 wheel，应在系统 Python 环境中执行；不要在 `~/.comm-env` 中执行。`~/.comm-env` 只用于后面的安装和运行 Python 示例。

## 3. 示例使用

### 3.1 合成信号精度测试

双声道 C++ 示例：

```bash
cd /root/spacemit_robot
export PATH="$PWD/output/staging/bin:$PATH"
ssl_demo -t -d 0.058
```

参数 `-d 0.058` 表示麦克风间距为 0.058 m，应替换为实际测量值。该模式生成多个角度的合成双声道信号并输出估计角度、误差、置信度和通过情况。

如果硬件通道方向与应用坐标相反，可测试翻转结果：

```bash
ssl_demo -t -d 0.058 --flip
```

Python 版本：

```bash
cd /root/spacemit_robot/components/multimedia/audio_process/doa/python/examples
python ssl_demo.py -t -d 0.058
python ssl_demo.py -t -d 0.058 --flip
```

3 个及以上麦克风使用多声道定位器，例如三麦克风等边阵列：

```bash
cd /root/spacemit_robot
ssl_demo -c 3 -t -d 0.058 --angle 60
```

多声道角度为阵列坐标系的 `[0°, 360°)` 方位角，不能使用双声道的 `--flip` 选项；需要调整坐标系时使用应用配置中的 `azimuth_offset_deg`。

然后运行 C++ 离线测向：

`stereo.wav` 是示例文件名，请替换为实际存在的 WAV 路径；不要在命令行中直接输入 `<stereo.wav>`，尖括号是文档占位符，不是文件名。

## 4. 应用开发

本章介绍如何在 C++ 和 Python 应用中集成 DOA 组件。双声道入口是 `SpacemitAudio::SoundLocator`，Python 入口是 `spacemit_audio_process.SoundLocator`；3 个及以上麦克风使用 `MultiSoundLocator`。完整接口以 `components/multimedia/audio_process/doa/include/doa_service.h` 和安装后的 `output/staging/include/doa_service.h` 为准。

### 4.1 接口说明

#### 4.1.1 常用数据结构

| 类型 | 说明 |
| --- | --- |
| `SoundLocatorConfig` | 双声道 GCC-PHAT 配置。`mic_distance` 必须与实际麦克风间距一致。 |
| `SoundLocator` | 双声道定位主类，提供 `Initialize`、`Reset`、`Process` 和结果查询接口。 |
| `MultiSoundLocatorConfig` | 3 个及以上麦克风的平面阵列配置，包含采样率、阵列位置、平均窗口及质量门限。 |
| `MultiSoundLocator` | 多声道定位主类，输出 `[0°, 360°)` 方位角。 |
| `MicrophonePosition` | 阵列坐标中的麦克风位置，通道索引必须与 `microphones` 数组索引一致。 |

`SoundLocatorConfig` 字段：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `sample_rate` | 16000 | 输入音频采样率，单位 Hz。 |
| `mic_distance` | 0.058 | 双麦克风间距，单位 m；必须改为实际硬件值。 |
| `sound_speed` | 343.0 | 声速，单位 m/s。 |
| `fft_size` | 0 | FFT 长度；`0` 表示使用 `2 * frame_size`。 |
| `frame_size` | 512 | 每帧采样数。 |
| `avg_frames` | 4 | 累积帧数；增大可平滑结果，但会增加响应延迟。 |
| `confidence_threshold` | 0.1 | 结果有效性阈值，低于该值时 `IsValid()` 返回 false。 |
| `upsample_factor` | 0 | TDOA 上采样倍率；`0` 表示自动选择约 4 μs 的时延分辨率。 |
| `use_fftw_measure` | false | 是否使用 `FFTW_MEASURE` 优化 FFT 计划；会增加初始化时间。 |

#### 4.1.2 引擎初始化

| 接口 | 说明 | 返回值 |
| --- | --- | --- |
| `SoundLocator(SoundLocatorConfig)` | 构造双声道定位器，不会自动创建 FFT 计划。 | 定位器实例。 |
| `Initialize()` | 分配 FFT 计划和内部缓冲；第一次 `Process()` 前必须调用一次。 | `bool`。 |
| `Reset()` | 清空多帧累积和缓存结果，保留已创建的 FFT 计划。 | 无。 |
| `GetConfig()` | 查询当前配置。 | `const SoundLocatorConfig&`。 |
| `GetMaxDelaySamples()` | 根据麦克风间距和声速计算物理最大时延采样数。 | `int`。 |

#### 4.1.3 处理 API

| 接口 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `Process(const float* interleaved, size_t num_frames)` | 处理交错双声道 float `[L0, R0, L1, R1, ...]`。 | 交错样本指针；双声道采样帧数。 | `bool`，true 表示已产出新结果。 |
| `Process(const float* ch0, const float* ch1, size_t num_frames)` | 处理两个独立 float 通道。 | 两个通道指针；每通道采样数。 | 同上。 |
| `Process(const int16_t* interleaved, size_t num_frames)` | 处理交错双声道 PCM16。 | 交错样本指针；双声道采样帧数。 | 同上。 |

`Process()` 在累积够 `avg_frames` 个处理帧后产生结果。可一次送入整段 PCM，也可按 `frame_size` 分块传入。只有 `IsValid()` 为 true 时才应将角度用于后续决策。

#### 4.1.4 结果查询

| 接口 | 说明 | 返回值 |
| --- | --- | --- |
| `GetDOA()` | 最近一次累积窗口的角度；`90°` 为垂直阵列方向，`0°` 为 ch1 侧，`180°` 为 ch0 侧。 | `float`，单位度，范围 `[0, 180]`。 |
| `GetTDOA()` | 最近一次累积窗口的时延差。 | `float`，单位秒。 |
| `GetConfidence()` | GCC 归一化峰值置信度，理想信号约为 1。 | `float`。 |
| `IsValid()` | 置信度是否达到 `confidence_threshold`。 | `bool`。 |
| `GetAverageDOA()` | 自上次 `Reset()` 以来有效结果的主方向加权估计，在 TDOA 空间聚合。 | `float`，单位度；无有效结果时返回 90。 |
| `GetResultCount()` | 自上次 `Reset()` 以来的有效结果批次数。 | `int`。 |

多声道定位使用 `MultiSoundLocatorConfig.microphones` 描述阵列，通道 `i` 对应 `microphones[i]`。结果通过 `GetResult()`、`GetAzimuth()`、`GetConfidence()`、`IsValid()`、`GetAverageAzimuth()` 和 `GetResultCount()` 查询。多声道平均窗口 `max_avg_seconds` 默认为 0，实时应用应设置有限窗口或定期 `Reset()`。

### 4.2 C++ 调用示例

K1 SDK 默认构建安装静态库 `libsound_locator.a`。头文件和库位于 `output/staging/include` 与 `output/staging/lib`。下列 CMake 片段展示 K1 的基本链接方式：

```cmake
find_path(DOA_INCLUDE_DIR NAMES doa_service.h
    PATHS ${CMAKE_INSTALL_PREFIX}/include NO_DEFAULT_PATH)
find_library(DOA_LIB NAMES sound_locator
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_library(FFTW3F_LIB NAMES fftw3f)

if(NOT DOA_LIB OR NOT DOA_INCLUDE_DIR OR NOT FFTW3F_LIB)
    message(FATAL_ERROR "DOA library or FFTW3F not found")
endif()

add_executable(my_doa_app main.cpp)
target_compile_features(my_doa_app PRIVATE cxx_std_17)
target_include_directories(my_doa_app PRIVATE ${DOA_INCLUDE_DIR})
target_link_libraries(my_doa_app PRIVATE ${DOA_LIB} ${FFTW3F_LIB} pthread m)
```

配置独立应用时，将 `CMAKE_INSTALL_PREFIX` 指定为 SDK 的 `output/staging` 路径。SDK 组件可在 `package.xml` 中声明 `<depend>audio_process</depend>`；实时应用还需声明 `<depend>audio</depend>`。静态库的 FFTW、线程和数学库依赖必须一并链接。

#### 4.2.1 离线 WAV 测向

适用场景：使用录制的双声道 WAV 检查通道顺序、麦克风间距和算法参数。

调用步骤：

1. 读取 WAV 的采样率、声道数和 PCM16 数据。
2. 设置 `SoundLocatorConfig`，将 `mic_distance` 设置为实际测量值。
3. 构造 `SoundLocator` 并调用 `Initialize()`。
4. 将交错 PCM16 按 `num_frames` 传给 `Process()`，然后读取 `GetDOA()`、`GetConfidence()` 和 `IsValid()`。

```cpp
#include <cstdint>
#include <iostream>
#include <vector>
#include "doa_service.h"

void LocateOnce(const std::vector<int16_t>& interleaved_stereo,
                int sample_rate, float mic_distance) {
    SpacemitAudio::SoundLocatorConfig cfg;
    cfg.sample_rate = sample_rate;
    cfg.mic_distance = mic_distance;
    cfg.frame_size = 512;
    cfg.avg_frames = 4;

    SpacemitAudio::SoundLocator locator(cfg);
    if (!locator.Initialize()) {
        std::cerr << "DOA initialization failed\n";
        return;
    }

    if (interleaved_stereo.empty() || interleaved_stereo.size() % 2 != 0) return;
    const size_t num_frames = interleaved_stereo.size() / 2;
    if (locator.Process(interleaved_stereo.data(), num_frames) &&
        locator.IsValid()) {
        std::cout << "DOA: " << locator.GetDOA() << " deg"
                  << "  TDOA: " << locator.GetTDOA() * 1e6 << " us"
                  << "  confidence: " << locator.GetConfidence() << '\n';
    }
}
```

`Process()` 的 `num_frames` 表示双声道采样帧数，而不是交错数组中的 `int16_t` 元素数。完整的 WAV 读取、命令行解析和 `--flip` 处理可参考 `components/multimedia/audio_process/doa/examples/ssl_demo.cpp`。

#### 4.2.2 实时回调流式测向

适用场景：将 `AudioCapture` 的双声道 PCM16 数据接入机器人朝向控制、波束形成或语音交互应用。

1. 将 `AudioCapture` 配置为双声道采集。
2. 在音频回调中只复制数据并放入队列，避免在 PortAudio 回调线程中执行 FFT 或阻塞操作。
3. 在业务线程中取出 PCM 数据，按双声道帧数调用 `Process()`，再读取结果。
4. 根据业务需要周期性调用 `Reset()`，控制平均窗口长度。

```cpp
#include <chrono>
#include <condition_variable>
#include <cstdint>
#include <cstring>
#include <deque>
#include <iostream>
#include <mutex>
#include <thread>
#include <utility>
#include <vector>
#include "audio_base.hpp"
#include "doa_service.h"

int main() {
    SpacemitAudio::SoundLocatorConfig cfg;
    cfg.sample_rate = 48000;
    cfg.mic_distance = 0.058f;  // 替换为实测麦克风间距
    cfg.frame_size = 512;
    cfg.avg_frames = 4;

    SpacemitAudio::SoundLocator locator(cfg);
    if (!locator.Initialize()) return 1;

    std::mutex queue_mutex;
    std::condition_variable queue_ready;
    std::deque<std::vector<int16_t>> pcm_queue;
    bool accepting_audio = true;

    SpacemitAudio::AudioCapture capture(2);  // 按 audio_demo list 修改设备索引
    capture.SetCallback([&](const uint8_t* data, size_t size) {
        if (data == nullptr || size < 2 * sizeof(int16_t) ||
            size % (2 * sizeof(int16_t)) != 0) {
            return;
        }
        std::vector<int16_t> chunk(size / sizeof(int16_t));
        std::memcpy(chunk.data(), data, size);
        {
            std::unique_lock<std::mutex> lock(queue_mutex, std::try_to_lock);
            if (!lock.owns_lock() || !accepting_audio) return;
            constexpr size_t kMaxQueuedChunks = 8;
            if (pcm_queue.size() >= kMaxQueuedChunks) {
                pcm_queue.pop_front();  // 丢弃最旧块，避免队列无限增长
            }
            pcm_queue.push_back(std::move(chunk));
        }
        queue_ready.notify_one();
    });

    const size_t chunk_size = 512 * 2 * sizeof(int16_t);
    if (!capture.Start(cfg.sample_rate, 2, chunk_size)) {
        capture.Close();
        return 1;
    }

    for (int second = 0; second < 30; ++second) {
        const auto deadline = std::chrono::steady_clock::now() +
                              std::chrono::seconds(1);
        while (std::chrono::steady_clock::now() < deadline) {
            std::vector<int16_t> chunk;
            {
                std::unique_lock<std::mutex> lock(queue_mutex);
                queue_ready.wait_until(lock, deadline,
                    [&] { return !pcm_queue.empty(); });
                if (pcm_queue.empty()) break;
                chunk = std::move(pcm_queue.front());
                pcm_queue.pop_front();
            }
            const size_t num_frames = chunk.size() / 2;
            locator.Process(chunk.data(), num_frames);
        }

        if (locator.GetResultCount() > 0) {
            std::cout << "[" << second << "s] avg DOA = "
                      << locator.GetAverageDOA() << " deg"
                      << "  results=" << locator.GetResultCount() << '\n';
        }
        locator.Reset();
    }

    {
        std::lock_guard<std::mutex> lock(queue_mutex);
        accepting_audio = false;
    }
    capture.Stop();
    capture.Close();
    return 0;
}
```

示例中的设备 `2` 对应 HX-KZ03 的枚举索引；部署到其他设备时，先运行 `audio_demo list` 确认输入设备索引及通道能力。`Process()`、结果查询与 `Reset()` 均在业务线程执行，避免同时访问同一个定位器。

实时应用在 §4.2 的 CMake 片段后追加 audio 依赖，使用 audio 组件安装的 PortAudio 静态库：

```cmake
find_path(AUDIO_INCLUDE_DIR NAMES audio_base.hpp
    PATHS ${CMAKE_INSTALL_PREFIX}/include NO_DEFAULT_PATH)
find_library(AUDIO_LIB NAMES spacemit_audio
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_library(PORTAUDIO_LIB NAMES libportaudio.a
    PATHS ${CMAKE_INSTALL_PREFIX}/lib NO_DEFAULT_PATH)
find_library(ALSA_LIB NAMES asound)
if(NOT AUDIO_INCLUDE_DIR OR NOT AUDIO_LIB OR NOT PORTAUDIO_LIB OR NOT ALSA_LIB)

```


#### 4.2.3 自定义置信度过滤

噪声、混响或多个声源会降低置信度。应用可以提高 `confidence_threshold`，并结合 `IsValid()`、`GetResultCount()` 和平均角度做过滤：

```cpp
SpacemitAudio::SoundLocatorConfig cfg;
cfg.sample_rate = 48000;
cfg.mic_distance = 0.058f;
cfg.frame_size = 512;
cfg.avg_frames = 8;
cfg.confidence_threshold = 0.3f;

SpacemitAudio::SoundLocator locator(cfg);
if (!locator.Initialize()) return 1;

// 持续调用 Process() 后：
if (locator.GetResultCount() >= 4 && locator.IsValid()) {
    const float doa = locator.GetAverageDOA();
    std::cout << "sound direction: " << doa << " deg\n";
}
```

麦克风间距小于 5 cm 时，可根据实际阵列增大 `upsample_factor`；`avg_frames` 越大，输出越平滑但响应越慢。参数应使用实际声学环境进行标定。

### 4.3 Python 示例

Python 包名为 `spacemit_audio_process`，安装方式见 §2。导入后使用 `SoundLocatorConfig` 配置双声道定位器；`process()` 和 `process_int16()` 接受一维交错数组，长度必须为偶数；`process_separate()` 接受两个等长的一维通道数组。

#### 4.3.1 离线测向

以下示例从双声道 PCM16 WAV 读取数据：

```python
import wave
import numpy as np
from spacemit_audio_process import SoundLocator, SoundLocatorConfig

with wave.open("stereo.wav", "rb") as wav_file:
    if wav_file.getnchannels() != 2 or wav_file.getsampwidth() != 2:
        raise ValueError("expected stereo PCM16 WAV")

    config = SoundLocatorConfig()
    config.sample_rate = wav_file.getframerate()
    config.mic_distance = 0.058  # 替换为实际麦克风间距
    config.frame_size = 512
    config.avg_frames = 4

    locator = SoundLocator(config)
    if not locator.initialize():
        raise RuntimeError("DOA initialization failed")

    pcm16 = np.frombuffer(
        wav_file.readframes(wav_file.getnframes()), dtype=np.int16
    )
    locator.process_int16(pcm16)
    if locator.is_valid:
        print(f"DOA={locator.doa:.1f}°, "
              f"TDOA={locator.tdoa * 1e6:.1f} us, "
              f"confidence={locator.confidence:.3f}")
    else:
        print("No valid DOA result")
```

`SoundLocator` 的 `__enter__` 不会自动执行 `initialize()`，因此即使使用 `with` 语法也必须显式调用 `initialize()`；退出上下文时会调用 `reset()`。

#### 4.3.2 上下文管理器与实时滑窗

Python live 模式使用 `spacemit_audio` 的 `AudioCapture`。回调只将音频字节放入有界队列，业务线程再转换成 NumPy PCM16 并送入定位器，避免在音频回调线程中进行计算。

```python
import queue
import time
import numpy as np
import spacemit_audio
from spacemit_audio_process import SoundLocator, SoundLocatorConfig

config = SoundLocatorConfig()
config.sample_rate = 48000
config.mic_distance = 0.058  # 替换为实测麦克风间距
config.frame_size = 512
config.avg_frames = 4

chunk_size = config.frame_size * 2 * 2  # frame * 2 channels * int16 bytes
pcm_queue = queue.Queue(maxsize=8)

with SoundLocator(config) as locator:
    if not locator.initialize():  # __enter__ 不会自动初始化
        raise RuntimeError("DOA initialization failed")
    spacemit_audio.init(
        sample_rate=config.sample_rate,
        channels=2,
        chunk_size=chunk_size,
        capture_device=2,
        player_device=-1,
    )
    capture = spacemit_audio.AudioCapture(2)

    def on_audio(data: bytes):
        try:
            pcm_queue.put_nowait(data)
        except queue.Full:
            # 队列满时丢弃最旧数据，保持实时处理的时效性。
            try:
                pcm_queue.get_nowait()
            except queue.Empty:
                pass
            try:
                pcm_queue.put_nowait(data)
            except queue.Full:
                pass

    capture.set_callback(on_audio)
    if not capture.start(
        sample_rate=config.sample_rate,
        channels=2,
        chunk_size=chunk_size,
    ):
        capture.close()
        raise RuntimeError("failed to start audio capture")

    try:
        for second in range(30):
            deadline = time.monotonic() + 1.0
            while time.monotonic() < deadline:
                timeout = max(0.0, deadline - time.monotonic())
                try:
                    data = pcm_queue.get(timeout=timeout)
                except queue.Empty:
                    break
                pcm = np.frombuffer(data, dtype=np.int16)
                frames = len(pcm) // 2
                if frames > 0:
                    locator.process_int16(pcm[:frames * 2])

            if locator.result_count > 0:
                print(
                    f"[{second}s] avg DOA={locator.average_doa:.1f}° "
                    f"results={locator.result_count}"
                )
            locator.reset()
    finally:
        capture.stop()
        capture.close()
```

`spacemit_audio.init()`、`AudioCapture.start()` 和 `SoundLocator.initialize()` 都需要显式调用。示例中的设备索引 `2` 为 HX-KZ03 的枚举索引，其他硬件应按 `audio_demo list` 结果修改。`with SoundLocator(...)` 退出时调用 `reset()`；`AudioCapture` 仍需显式 `stop()` 和 `close()`。

#### 4.3.3 C++ 与 Python 接口对照

| C++（`SpacemitAudio::`） | Python（`spacemit_audio_process.`） | 说明 |
| --- | --- | --- |
| `SoundLocatorConfig` | `SoundLocatorConfig()` | Python 配置字段与 C++ 同名。 |
| `SoundLocator(cfg)` + `Initialize()` | `SoundLocator(cfg)` + `initialize()` | Python 上下文管理器不会自动初始化。 |
| `Process(const float*, n)` | `process(float32_array)` | 交错双声道 float 数组。 |
| `Process(const int16_t*, n)` | `process_int16(int16_array)` | 交错双声道 PCM16 数组。 |
| `Process(const float*, const float*, n)` | `process_separate(ch0, ch1)` | 两个等长的一维 float 数组。 |
| `GetDOA()` / `GetTDOA()` / `GetConfidence()` / `IsValid()` | `doa` / `tdoa` / `confidence` / `is_valid` | Python 使用只读属性。 |
| `GetAverageDOA()` / `GetResultCount()` | `average_doa` / `result_count` | `Reset()` 后重新累计。 |
| `GetMaxDelaySamples()` / `GetConfig()` | `max_delay_samples` / `config` | 查询物理时延上限和配置。 |
| `Reset()` | `reset()` | 清空累积状态。 |

3 个及以上通道可使用 Python 的 `MultiSoundLocator`、`MultiSoundLocatorConfig` 和 `MicrophonePosition`。输入可以是形状为 `(frames, channels)` 的二维数组，也可以是传入 `n_channels` 的一维交错数组；`process_channels()` 接受多个等长的一维 float 通道数组。`MultiSoundLocator` 的 `result`、`azimuth`、`confidence`、`is_valid`、`average_azimuth` 和 `result_count` 以属性形式暴露。多声道长时间采集时，应设置有限的 `max_avg_seconds` 或周期性 `reset()`。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 实时模式提示设备只有 1 个输入通道 | 当前输入设备为单声道 | 使用支持双声道的设备，并按设备能力设置采样率和声道数；K1 验证使用设备 2、48000 Hz。 |
| 角度是期望值的补角 | 左右声道物理顺序与算法假设相反 | 示例使用 `--flip`；集成应用中交换两个通道或按坐标定义输出 `180 - doa`。 |
| 一直没有有效结果 | 输入不是双声道、信号太弱、`mic_distance` 不正确或置信度门限过高 | 检查 WAV 头、输入声道数、实际麦克风间距和 `confidence_threshold`，先运行合成测试。 |
| 0° / 180° 附近误差较大 | 麦克风间距配置不准，或通道时延不匹配 | 精确测量 `mic_distance` 并检查通道同步；端火方向对间距误差较敏感。 |
| 结果抖动 | 噪声或混响影响 | 增大 `avg_frames`，或在业务侧对输出做时间平滑。 |
| Python 导入失败 | 未激活虚拟环境，或缺少 Python 包 | 激活 `~/.comm-env`，按 §2 安装 `spacemit_audio_process` 和 NumPy；live 模式还需 `spacemit_audio`。 |
| 多声道长时间运行内存持续增加 | `max_avg_seconds=0` 使用无限历史窗口 | 将 `max_avg_seconds` 设置为有限值，或周期性调用 `Reset()`。 |
| C++ 应用链接失败 | K1 使用静态 `libsound_locator.a`，但未链接 FFTW、线程或数学库 | 在 CMake 中同时链接 `sound_locator`、`fftw3f`、`pthread` 和 `m`；实时模式还需 audio、PortAudio 和 ALSA 依赖。 |
