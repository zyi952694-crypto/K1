# 多媒体 · MPP

## 1. 模块概述

- 主要功能：MPP（Media Processing Platform）是 SPACEMIT 媒体处理平台，提供视频编解码、视频输入输出、图像处理等核心能力，支持 H.264/H.265 编解码、JPEG 编解码、视频采集等功能
- 规格或特性：
  - 视频编码：支持 H.264/H.265/JPEG 编码
  - 视频解码：支持 H.264/H.265/JPEG 解码
  - 视频输入（VI/UVC）：支持 MIPI CSI、USB UVC 等接口
  - 图像处理（V2D）：支持格式转换、缩放、旋转等
  - 封装/解封装：支持 MP4 等容器和 RTSP 流处理
- 相关目录结构：

```text
mpp/
├── include/              # 对外头文件
│   ├── venc/             # 视频编码 API
│   ├── vdec/             # 视频解码 API
│   ├── vi/               # 视频输入 API
│   ├── uvc/              # USB 摄像头 API
│   ├── v2d/              # 图像处理 API
│   └── sys/              # 系统管理 API
├── mpi/                  # MPI 实现层
│   ├── venc/             # 编码器实现
│   ├── vdec/             # 解码器实现
│   ├── vi/               # 视频输入实现
│   └── ...
├── al/                   # 抽象层（模块插件）
├── utils/                # 工具库
├── sample/               # 示例程序
├── test/                 # 测试程序
└── CMakeLists.txt        # 构建配置
```

## 2. 环境准备

### 前置条件

- 运行环境：Linux 内核、CMake ≥ 3.16、gcc/g++ 编译器（支持 C11/C++14）
- 依赖与外部资源：
  - 硬件编解码器驱动（内核模块）
  - `v4l-utils`：提供摄像头枚举工具 `v4l2-ctl`，缺少时执行 `sudo apt install v4l-utils`
  - 可选 FFmpeg：使用其中的 `ffplay` 查看输出文件，需要可用的图形显示环境
- 环境变量与初始化：通过 SDK 编译需先执行 `source build/envsetup.sh` 并 `lunch <target>`
- 硬件与连接：SPACEMIT K1 开发板、USB UVC 摄像头；查看图像时需连接显示器或使用可用的图形桌面
- 工具与权限：访问 `/dev/video*` 等设备节点需相应权限

### 构建编译

- 获取代码：

  SDK 源码获取和基础编译环境配置参考 [1.6-构建编译](../../01-快速开始/1.6-构建编译.md)。完成 SDK 初始化后，回到本文继续执行

  后续命令以 `/root/spacemit_robot` 为 SDK 根目录；如安装在其他位置，请替换对应路径。

- 本模块编译：

```bash
cd /root/spacemit_robot
```

- 产物：

  - 测试程序：`output/build/cmake/pkgs/components_multimedia_mpp/test/` 目录下的 `test_venc`、`test_vdec` 等

## 3. 示例使用（从 0 跑通）

### 3.1 USB 摄像头采集与解码

**前置**：已编译 MPP，USB 摄像头已连接

**步骤 1**：确认摄像头设备

```bash
ls /dev/video*
v4l2-ctl --list-devices
```

预期现象：显示视频设备节点及对应设备名称。根据 USB 摄像头名称确认其采集节点，不要仅按节点编号选择设备。

以下以 USB 摄像头采集节点 `/dev/video20` 为例。设备节点由驱动和枚举顺序决定，请按实际输出替换；`/dev/video0` 也可能是视频编解码节点，不能直接视为摄像头采集节点。

**步骤 2**：运行 UVC 采集解码示例

```bash
cd /root/spacemit_robot
cd output/build/cmake/pkgs/components_multimedia_mpp/sample
# 指定 UVC 设备节点（步骤 1 中确认的节点）和输出目录
./sample_uvc_vdec /dev/video20 ./nv12_output
```

参数说明（命令格式：`./sample_uvc_vdec [选项] [devNode] [outDir]`）：

| 类型 | 参数 | 说明 |
| --- | --- | --- |
| 选项 | `--bind` | 使用 SYS_Bind 模式（UVC→VDEC 自动传输码流）；缺省为手动模式（`UVC_GetFrame` → `VDEC_SendStream`） |
| 选项 | `-h`、`--help` | 显示帮助信息 |
| 位置参数 | `devNode` | UVC 设备节点，缺省 `/dev/video0`；应根据实际摄像头节点指定 |
| 位置参数 | `outDir` | 输出目录，缺省 `./nv12_output` |

> 注意：`--bind` 等选项为可选项，且必须位于位置参数（`devNode`、`outDir`）之前。程序按位置顺序解析参数，一旦遇到位置参数即停止识别选项，因此 `--bind` 若写在设备节点之后会被误当作位置参数。

用法示例：

```bash
# 仅当摄像头采集节点确实为默认的 /dev/video0 时使用
./sample_uvc_vdec                                      # 手动模式，使用默认设备与目录
./sample_uvc_vdec --bind                               # bind 模式，使用默认设备与目录

# 指定实际摄像头采集节点，以 /dev/video20 为例
./sample_uvc_vdec /dev/video20 ./nv12_output            # 手动模式，自定义设备与目录
./sample_uvc_vdec --bind /dev/video20 ./nv12_output     # bind 模式，自定义设备与目录
```

预期现象：程序采集 USB 摄像头的 MJPEG 视频流，解码并保存 20 帧 NV12 图像，输出包含：

```text
[INFO] Saved 20 / 20 frames
=== Sample finished (20 frames saved) ===
```

输出目录中生成 `frame_0000_1280x720.nv12` 等文件；手动模式还会保存 `uvc_0000.mjpeg` 等输入图像。示例将图像保存到文件，不自动弹出预览窗口。

### 3.2 视频编码示例（文件到文件）

使用 `test_venc` 将 YUV 原始帧编码为 H.264 码流。

**前置**：见 §2

**步骤 1**：进入测试程序目录

```bash
cd /root/spacemit_robot
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**步骤 2**：运行编码测试

```bash
./test_venc --test format \
    -i ../../../../../../components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv \
    -W 1920 -H 1080 -c h264 -n 1 -o ./enc_out
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `--test format` | 执行指定格式的编码测试 |
| `-i ../../../../../../components/multimedia/mpp/test/assets/vi_phy0_last_frame.yuv` | 输入 YUV 文件路径，格式为紧密排列的 NV12 原始帧 |
| `-W 1920` | 图像宽度 |
| `-H 1080` | 图像高度 |
| `-o ./enc_out` | 输出文件名前缀，程序追加编码格式扩展名，生成 `enc_out.h264` |
| `-c h264` | 编码格式（支持 `h264`、`h265`、`mjpeg`） |
| `-n 1` | 编码帧数 |

当前 SDK 使用 `test_venc --test format`，程序名称及参数形式与 `test_venc_file` 不同。输出参数使用前缀 `./enc_out`，无需再添加 `.h264`。

预期现象：

```text
[format] h264 1920x1080 1 frame(s) (file input)
[format] h264: 1 stream(s), 1 key frame(s)
[PASS] format suite
[DONE] all selected suites passed
```

编码完成后在当前目录生成 `enc_out.h264` 文件，可使用 `ffplay enc_out.h264` 验证。

### 3.3 视频解码示例（文件到文件）

使用 `test_vdec` 将压缩码流解码为 YUV 原始帧。

**前置**：见 §2

**步骤 1**：进入测试程序目录

```bash
cd /root/spacemit_robot
cd output/build/cmake/pkgs/components_multimedia_mpp/test
```

**步骤 2**：运行解码测试（以 MJPEG 为例）

```bash
./test_vdec --test format \
    -i ../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg \
    -W 1920 -H 1080 -c mjpeg -n 1 -o ./dec_out_nv12.yuv
```

参数说明：

| 参数 | 含义 |
| --- | --- |
| `--test format` | 执行指定格式的解码测试 |
| `-i ../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg` | 输入码流文件路径 |
| `-W 1920` | 图像宽度提示 |
| `-H 1080` | 图像高度提示 |
| `-o ./dec_out_nv12.yuv` | 输出 YUV 文件路径，默认格式为 NV12 |
| `-c mjpeg` | 解码格式（支持 `h264`、`h265`、`mjpeg`） |
| `-n 1` | 最多写出 1 帧解码图像 |

当前 SDK 使用 `test_vdec --test format`，程序名称及参数形式与 `test_vdec_file` 不同。

预期现象：

```text
[decode] ../../../../../../components/multimedia/mpp/test/assets/1920x1080.jpg decoded_frames=1 last 1920x1080
[PASS] format suite (1 case(s))
```

解码完成后在当前目录生成 `dec_out_nv12.yuv` 文件，可使用以下命令验证：

```bash
ffplay -f rawvideo -pix_fmt nv12 -s 1920x1080 dec_out_nv12.yuv
```

## 4. 应用开发

- **对外 API 或接口形态**：

  - 头文件：`include/venc/venc_api.h`、`include/vdec/vdec_api.h`、`include/uvc/uvc_api.h`、`include/vi/vi_api.h`、`include/v2d/v2d_api.h` 和 `include/sys/` 下的系统管理接口。
  - 库名：`libmpp.so`。
  - 主要 API：
    - 编码：`VENC_Init()`、`VENC_CreateChn()`、`VENC_EnableChn()`、`VENC_SendFrame()`、`VENC_GetStream()`、`VENC_ReleaseStream()`、`VENC_DisableChn()`、`VENC_DestroyChn()`、`VENC_Exit()`。
    - 解码：`VDEC_Init()`、`VDEC_CreateChn()`、`VDEC_EnableChn()`、`VDEC_SendStream()`、`VDEC_GetFrame()`、`VDEC_ReleaseFrame()`、`VDEC_DisableChn()`、`VDEC_DestroyChn()`、`VDEC_Exit()`。
    - 视频输入：VI 模块 API，包括 `VI_GetChnFrame()`、`VI_ReleaseChnFrame()`；USB 摄像头使用 UVC 模块的 `UVC_GetFrame()`、`UVC_ReleaseFrame()` 等接口。
    - 图像处理：V2D 模块 API，包括 `V2D_BeginJob()`、`V2D_ConvertFrame()`、`V2D_EndJob()` 等接口。

  当前 SDK 使用上述通道接口；应用应按对应头文件调用，不使用旧的 `venc_ctx_*`、`vdec_ctx_*` 接口名称。

- **调用方式与注意点**：

  - 初始化顺序：先调用 `SYS_Init()`、`VB_Init()`，再初始化对应模块，配置设备或创建通道，最后启用数据流。
  - 并发管理：避免在其他线程仍使用设备或通道时执行销毁操作；停止数据处理线程后再进行资源清理。
  - 内存管理：使用 MPP 的 buffer 接口管理帧数据，每次成功获取帧或码流后，必须调用对应的 release 接口。
  - 资源释放：参考对应示例的清理顺序，停止传输并解除绑定，释放持有的帧和码流，关闭并销毁设备、通道，最后退出模块及 VB、SYS。
  - 硬件加速：通过平台编解码插件调用硬件能力，需要正确安装驱动和插件。
  - 编译链接：头文件安装在 `output/staging/include`，基础类型头文件位于 `output/staging/include/sys`，下游工程应同时加入这两个包含目录，并链接 `output/staging/lib` 中的 `libmpp.so`。

- **参考 demo 或示例路径**：`components/multimedia/mpp/sample/sample_uvc_vdec.c`、`components/multimedia/mpp/test/test_venc.c`、`components/multimedia/mpp/test/test_vdec.c`。

## 5. 调试指南

- 内核日志：`dmesg | grep -E "vpu|codec|MPP"` 查看硬件编解码器日志
- 设备节点：`ls -l /dev/video*` 确认视频设备，使用 `v4l2-ctl --list-devices` 区分摄像头和编解码节点
- 摄像头格式：`v4l2-ctl -d /dev/video20 --list-formats-ext` 查看支持的格式和分辨率，设备节点按实际情况替换
- 性能分析：使用 `time` 命令测量程序总耗时；该耗时包含初始化和清理，不等同于单帧硬件处理延迟
- 帧率统计：使用连续多帧输入，区分初始化、预热和稳定处理阶段，按实际完成的帧数及对应耗时计算帧率

## 6. 常见问题

| 现象           | 可能原因                 | 处理                                     |
| -------------- | ------------------------ | ---------------------------------------- |
| 编码初始化失败 | 硬件编码器插件未加载     | 检查 `libv4l2_linlonv5v7_codec2.so` 是否存在及其依赖是否完整 |
| 解码花屏       | 码流格式不支持或损坏     | 确认码流格式，使用标准测试码流           |
| 帧率低         | CPU 负载高或内存带宽不足 | 优化代码，减少内存拷贝                   |
| 设备节点不存在 | 摄像头未连接或驱动未加载 | 检查硬件连接，加载驱动模块               |
| `test_venc_file` 或 `test_vdec_file` 提示“没有那个文件或目录” | 程序名称与当前 SDK 构建产物不一致 | 使用 §3.2、§3.3 中的 `test_venc --test format`、`test_vdec --test format` |
| `/dev/video0 is not a video capture device` | 所选节点不是摄像头采集节点 | 使用 `v4l2-ctl --list-devices` 确认 USB 摄像头节点并替换参数 |
| UVC 手动模式退出时出现 `release rejected` | buffer 引用释放阶段出现异常，具体原因仍需排查 | 检查保存帧数、返回码和输出文件；保留完整日志，可尝试 `--bind` 模式。已保存图像不代表该清理问题已解决 |
| 解码时打印 `[MPP-ERROR] ... find_v4l2_decoder ... v4l2_capability...` | 编解码插件在查询设备能力时输出错误级别日志 | 结合后续初始化结果、解码帧数、`PASS` 及输出文件判断；该日志单独出现不能认定解码失败 |
