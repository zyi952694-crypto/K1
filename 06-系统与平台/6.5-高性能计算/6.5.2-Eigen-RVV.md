# Eigen RVV

## Eigen 简介

[Eigen](https://eigen.tuxfamily.org) 是一个高性能的 C++ 模板库，专用于线性代数运算，涵盖矩阵、向量、数值求解及相关算法。它被广泛应用于机器人、计算机视觉、数值仿真等领域，是 ROS、OpenCV、PCL 等主流框架的核心依赖之一。

**主要特点：**

- **纯头文件**：无需编译，直接 `#include` 即可使用
- **高性能**：通过表达式模板（expression templates）消除临时变量，自动向量化（SIMD）
- **功能丰富**：支持稠密矩阵、稀疏矩阵、几何变换（旋转矩阵、四元数）、线性求解器等
- **跨平台**：支持 x86、ARM、RISC-V 等主流架构

## RVV 加速

RVV（RISC-V Vector Extension）是 RISC-V 架构的向量扩展指令集，可对矩阵运算进行 SIMD 加速。K1 搭载 8 核 SpacemiT X60 处理器，支持 RVV 1.0。

针对 K1 平台，我们提供了专为 RVV 优化的定制 Eigen 库 `eigen-spacemit`，相比系统默认的 Eigen 有显著差异：

| 对比项 | 系统 Eigen（`libeigen3-dev`） | eigen-spacemit |
|:-:|:-:|:-:|
| 安装路径 | `/usr/include/eigen3` | `/opt/eigen-spacemit` |
| RVV 加速 | 未启用 | 针对 RVV 1.0 优化 |
| 适用平台 | 通用（x86/ARM/RISC-V） | 支持 SpacemiT RISC-V 平台 |
| 安装方式 | `apt install libeigen3-dev` | `apt install eigen-spacemit` |

在 K1 上进行高性能线性代数运算（如点云处理、SLAM、卡尔曼滤波）时，推荐优先使用 `eigen-spacemit` 以充分发挥 RVV 硬件能力。

## 使用示例

以下示例对比系统 Eigen 与 `eigen-spacemit` 在 512×512 矩阵乘法上的性能差异。

**安装必要依赖**

```
sudo apt update
sudo apt install eigen-spacemit libeigen3-dev cmake make g++-14 util-linux
```

本示例使用 GCC 14 编译。若系统默认编译器为 GCC 13，需在 CMake 配置时显式指定 `g++-14`，以支持 `-mrvv-vector-bits=zvl`；无需更改系统默认编译器。

**目录结构：**

```
eigen_bench/
├── CMakeLists.txt
└── bench.cpp
```

创建工作目录，将下方代码分别保存为 `CMakeLists.txt` 和 `bench.cpp`：

```bash
mkdir -p ~/eigen_bench
cd ~/eigen_bench
```

**CMakeLists.txt：**

```cmake
cmake_minimum_required(VERSION 3.16)
project(eigen_bench LANGUAGES CXX)

# OpenMP 让 Eigen 支持的单个算子（主要是大矩阵乘法）可以使用多线程。
option(EIGEN_BENCH_ENABLE_OPENMP "Enable OpenMP so Eigen can parallelize supported operators" ON)

# RVV 编译参数。
set(RVV_MARCH "rv64gcv_zvl256b" CACHE STRING "RISC-V architecture flags for RVV builds")
set(RVV_MABI  "lp64d"           CACHE STRING "RISC-V ABI flags for RVV builds")

# 系统 Eigen 对照组保持无 RVV，需显式指定标量目标架构和 ABI。
set(SCALAR_MARCH "rv64gc" CACHE STRING "RISC-V architecture flags for scalar non-RVV builds")
set(SCALAR_MABI  "lp64d"  CACHE STRING "RISC-V ABI flags for scalar non-RVV builds")

if(EIGEN_BENCH_ENABLE_OPENMP)
  find_package(OpenMP)
endif()


# 统一创建 benchmark 目标：传入不同 Eigen include 路径即可对比不同实现。
function(add_bench target eigen_include)
  add_executable(${target} bench.cpp)
  target_include_directories(${target} PRIVATE "${eigen_include}")
  target_compile_options(${target} PRIVATE -O3 -DNDEBUG -std=c++17)
  if(EIGEN_BENCH_ENABLE_OPENMP AND OpenMP_CXX_FOUND)
    target_link_libraries(${target} PRIVATE OpenMP::OpenMP_CXX)
  endif()
endfunction()

# SpacemiT Eigen（RVV 加速）
add_bench(bench_spacemit /opt/eigen-spacemit/include/eigen3)
target_compile_options(bench_spacemit PRIVATE -march=${RVV_MARCH} -mabi=${RVV_MABI} -mrvv-vector-bits=zvl)
target_compile_definitions(bench_spacemit PRIVATE EIGEN_RISCV64_USE_RVV10)

# 系统 Eigen（无 RVV）
add_bench(bench_system /usr/include/eigen3)
target_compile_options(bench_system PRIVATE -march=${SCALAR_MARCH} -mabi=${SCALAR_MABI})
```

**bench.cpp：**

```cpp
#include <Eigen/Dense>
#include <chrono>
#include <cstdlib>
#include <iostream>
#include <stdexcept>
#include <string>

namespace {

int parsePositiveInt(const char* value, const std::string& name) {
    const int parsed = std::stoi(value);
    if (parsed <= 0) {
        throw std::runtime_error(name + " must be positive");
    }
    return parsed;
}

std::string envOrUnset(const char* name) {
    const char* value = std::getenv(name);
    return value ? value : "not_set";
}

}  // namespace

int main(int argc, char** argv) {
    try {
    const int N = argc > 1 ? parsePositiveInt(argv[1], "matrix_size") : 512;
    const int iters = argc > 2 ? parsePositiveInt(argv[2], "iterations") : 10;
    const char* threads_env = std::getenv("EIGEN_BENCH_THREADS");
    const int threads = argc > 3 ? parsePositiveInt(argv[3], "threads") : (threads_env ? parsePositiveInt(threads_env, "EIGEN_BENCH_THREADS") : 8);
    Eigen::setNbThreads(threads);

    Eigen::MatrixXf A = Eigen::MatrixXf::Random(N, N);
    Eigen::MatrixXf B = Eigen::MatrixXf::Random(N, N);
    Eigen::MatrixXf C(N, N);

    C.noalias() = A * B; // warmup

    auto t0 = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < iters; ++i)
        C.noalias() = A * B;
    auto t1 = std::chrono::high_resolution_clock::now();

    double ms = std::chrono::duration<double, std::milli>(t1 - t0).count() / iters;
    std::cout << "Eigen version: " << EIGEN_WORLD_VERSION << '.' << EIGEN_MAJOR_VERSION << '.' << EIGEN_MINOR_VERSION << '\n';
    std::cout << "SimdInstructionSetsInUse(): " << Eigen::SimdInstructionSetsInUse() << '\n';
#ifdef EIGEN_HAS_OPENMP
    std::cout << "EIGEN_HAS_OPENMP: defined\n";
#else
    std::cout << "EIGEN_HAS_OPENMP: not_defined\n";
#endif
    std::cout << "matrix_size: " << N << '\n';
    std::cout << "iterations: " << iters << '\n';
    std::cout << "requested_threads: " << threads << '\n';
    std::cout << "Eigen nbThreads: " << Eigen::nbThreads() << '\n';
    std::cout << "OMP_NUM_THREADS: " << envOrUnset("OMP_NUM_THREADS") << '\n';
    std::cout << "EIGEN_BENCH_THREADS: " << envOrUnset("EIGEN_BENCH_THREADS") << '\n';
    std::cout << N << "x" << N << " matmul avg: " << ms << " ms\n";
    return 0;
    } catch (const std::exception& error) {
        std::cerr << "error: " << error.what() << '\n';
        return 1;
    }
}
```

**编译与运行：**

```bash
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++-14
make -j$(nproc)

./bench_system    # 系统 Eigen
./bench_spacemit  # SpacemiT Eigen（RVV）
```

使用相同的输入尺寸、迭代次数和线程数比较两套库：

**单核对比**

```bash
taskset -c 0 ./bench_system 512 10 1
taskset -c 0 ./bench_spacemit 512 10 1
```

| 512×512 float32 矩阵乘法 | 平均耗时（ms） |
| --- | ---: |
| 系统 Eigen | 268.793 |
| eigen-spacemit | 75.040 |

**八核对比**

```bash
taskset -c 0-7 ./bench_system 512 10 8
taskset -c 0-7 ./bench_spacemit 512 10 8
```

| 512×512 float32 矩阵乘法 | 平均耗时（ms） |
| --- | ---: |
| 系统 Eigen | 37.573 |
| eigen-spacemit | 11.467 |

可以看出，使用 RVV 优化的 `eigen-spacemit` 后，512×512 单精度矩阵乘法的平均耗时明显降低：单核由 **268.793 ms 降至 75.040 ms**，八核由 **37.573 ms 降至 11.467 ms**。

以上为 K1 参考结果，实际耗时随系统负载变化。`eigen-spacemit 5.0.1-1bb5` 的 `SimdInstructionSetsInUse()` 尚未包含 RVV 分支，因此该字段可能显示 `None`；不能据此判断 RVV 未启用。原示例采用旧版 Eigen 的版本宏拼接方式，在该包上显示 `3.5.0`，软件包提供的实际 Eigen 版本为 `5.0.1`。

## 使用 openblas-spacemit 作为后端

Eigen 默认使用自身的模板实现完成矩阵运算，而 [OpenBLAS](https://www.openblas.net/) 是一个经过高度优化的 BLAS（Basic Linear Algebra Subprograms）数值库。通过在编译时添加 `-DEIGEN_USE_BLAS` 宏，Eigen 会将底层的矩阵乘法（`gemm`）等关键运算委托给 OpenBLAS 执行，从而利用其针对特定硬件深度调优的实现。

`openblas-spacemit` 是专为 SpacemiT K1 平台定制的 OpenBLAS 版本，充分利用了 RVV 1.0 向量扩展及平台特性。与单独使用 `eigen-spacemit`（RVV 向量化）相比，通过 `openblas-spacemit` 后端可进一步提升大规模矩阵乘法性能。

**安装必要依赖**

```
sudo apt install openblas-spacemit
```

**编译与运行**

仍使用上一节的 `bench.cpp`，回到源文件所在目录编译：

```
cd ~/eigen_bench
export LD_LIBRARY_PATH="/opt/openblas-spacemit/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
g++-14 -O3 -DNDEBUG -std=c++17 \
	-fopenmp \
    -march=rv64gcv_zvl256b -mabi=lp64d -mrvv-vector-bits=zvl \
    -DEIGEN_RISCV64_USE_RVV10 -DEIGEN_USE_BLAS \
    -I"/opt/eigen-spacemit/include/eigen3" \
    "bench.cpp" \
    "/opt/openblas-spacemit/lib/libopenblas.so" -lpthread \
    -o /tmp/eigen_bench_blas
```

```
/tmp/eigen_bench_blas
```

**单核性能：**

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
    taskset -c 0 /tmp/eigen_bench_blas 512 10 1
```

| 512×512 float32 矩阵乘法 | 平均耗时（ms） |
| --- | ---: |
| eigen-spacemit | 75.040 |
| eigen-spacemit + openblas-spacemit | 27.823 |

**八核性能：**

```bash
OPENBLAS_NUM_THREADS=8 OMP_NUM_THREADS=8 \
    taskset -c 0-7 /tmp/eigen_bench_blas 512 10 8
```

| 512×512 float32 矩阵乘法 | 平均耗时（ms） |
| --- | ---: |
| eigen-spacemit | 11.467 |
| eigen-spacemit + openblas-spacemit | 6.364 |

使用 `openblas-spacemit` 作为 Eigen 后端，矩阵乘法性能进一步提升：上述单核测试的平均耗时由 **75.040 ms 降至 27.823 ms**，八核由 **11.467 ms 降至 6.364 ms**。

启用 BLAS 后，矩阵乘法的线程由 OpenBLAS 管理，需设置 `OPENBLAS_NUM_THREADS`。此时 `Eigen::nbThreads()` 可能显示 `1`，该值不代表 OpenBLAS 的实际线程数。

## 更多性能测试数据

**测试环境**

- K1 Muse Pi Pro，SpacemiT RISC-V X60 CPU（8 核，最高频率配置为 1.6 GHz）。
- Bianbu 2.3.5 操作系统，Linux 6.6.63。
- 内存：8 GB。
- GCC 14.2；系统 Eigen 3.4.0、eigen-spacemit 5.0.1、openblas-spacemit 0.3.32。
- CPU 调频策略为 performance，实际频率随温度和负载变化。

**多核测试说明**

- 使用 CMake 构建时，需要先查找 OpenMP，再通过 `target_link_libraries(${target_name} PRIVATE OpenMP::OpenMP_CXX)` 为测试目标启用 OpenMP；附录套件使用 `g++-14` 直接编译，通过 `-fopenmp` 启用 OpenMP。
- 多核测试代码使用 `Eigen::setNbThreads(threads)` 设置 Eigen 线程数，`threads` 与测试时限制的核数一致。附录套件同时设置 OpenMP 线程数，启用 BLAS 时另通过 `openblas_set_num_threads(threads)` 设置 OpenBLAS 线程数。
- 以下测试使用 `taskset -c` 限制 CPU，单核、四核、八核对应 CPU 0、0–3、0–7，线程数分别为 1、4、8。线程设置不代表每个算子都使用全部线程。

**性能下降情况说明**

后续表格中，`speedup` 小于 1 或 `improvement` 为负数，表示对比方案在该项测试中的性能低于基准方案。K1 的下降项需要结合以下场景判断：

- **小规模几何运算**：四元数输入为 4×1，叉积输入为 3×1，四元数转旋转矩阵的输出为 3×3，计算规模较小，固定开销对耗时的影响更明显。套件采用每次迭代执行 1024 次操作后折算单次耗时的方式。例如，八线程 float32 四元数转旋转矩阵的系统 Eigen 与 `eigen-spacemit` 对比速度比为 0.98x；这类结果不能用于推断大矩阵运算的性能。
- **低计算密度或访存主导算子**：如 `Identity()`、`trace()`、复制等操作，收益受内存访问和具体实现影响，不能保证启用 RVV 后都会加速。例如，八线程 float32 `matrix_identity` 的系统 Eigen 与 `eigen-spacemit` 对比速度比约为 0.50x，该下降幅度不宜简单归为测试抖动。
- **使用 BLAS 后端时未委托给 BLAS 的算子**：启用 `EIGEN_USE_BLAS` 不会将所有 Eigen 操作交给 BLAS。数组逐元素运算、几何操作及 `setIdentity()` 等不会因此直接获得 BLAS 加速；两种构建间出现差异，也不能直接认定是 BLAS 调用开销导致。
- **多核配置下的算子差异**：增加线程数或启用 BLAS 并不保证每个算子都有收益。例如，八线程 float64 `matrix_gemv` 启用 BLAS 后，平均耗时由 1.895 ms 增至 3.199 ms，配对速度比约为 0.59x，而相同配置下的矩阵乘法仍有提升。具体原因需进一步分析调用路径和线程行为，不能仅凭计时表确定。

性能下降项应结合算子类型、输入规模、数据类型与标准差一起判断。实际应用中，可优先评估矩阵乘法等计算密集型任务的收益；对于小规模或访存主导操作，应根据端到端业务耗时选择实现和线程数。

系统与厂商 Eigen 的版本和实现不同，结果反映两个构建在 K1 上的整体差异。附录使用随附的独立套件，具体输入、估算操作数和校验方式见资源包；小型几何操作采用批量计时。

## eigen-spacemit VS libeigen3-dev

- 使用 `taskset -c` 限制可用 CPU，线程数与限制的核数一致。
- 每轮测试先预热 10 次，再计时 50 次取平均值；独立重复 10 轮，计算各项指标的均值和标准差。几何小算子的每次迭代包含 1024 次操作，结果折算为单次耗时。
- `mean` 表示 10 轮测试的均值，`sd` 为样本标准差，反映轮次间的波动。
- 每轮按 `speedup = 基准耗时 / 对比耗时` 计算速度比，再统计 10 轮的均值和标准差；`improvement = (speedup − 1) × 100%`。后续 BLAS 后端对比采用相同统计方法。
