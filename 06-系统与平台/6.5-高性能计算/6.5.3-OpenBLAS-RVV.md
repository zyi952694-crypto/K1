# OpenBLAS RVV

OpenBLAS 可加速矩阵和向量计算。本节在 K1 上使用同一份代码对比系统库与 SpacemiT 优化库，并检查计算结果。

## OpenBLAS 简介

[OpenBLAS](https://www.openblas.net/) 是一个开源的 BLAS（Basic Linear Algebra Subprograms）和部分 LAPACK 实现，提供矩阵乘法、向量运算、线性方程求解、矩阵分解等基础数值计算能力。OpenBLAS 被广泛用于 NumPy、SciPy、Eigen、OpenCV、机器学习推理框架以及机器人算法中的线性代数加速场景。

K1 的 SpacemiT X60 核心支持 RVV 1.0。使用面向 X60 优化的 OpenBLAS，可以通过相同接口调用向量化实现。

## RVV 加速

K1 系统中可对比两套 OpenBLAS：

| 对比项 | 系统 OpenBLAS（`libopenblas-pthread-dev`） | SpacemiT OpenBLAS（`openblas-spacemit`） |
| :-: | :-: | :-: |
| 版本 | OpenBLAS 0.3.26 | OpenBLAS 0.3.32 |
| 安装方式 | `sudo apt install libopenblas-pthread-dev` | `sudo apt install openblas-spacemit` |
| 头文件路径 | `/usr/include/riscv64-linux-gnu/openblas-pthread` | `/opt/openblas-spacemit/include` |
| 库文件路径 | `/usr/lib/riscv64-linux-gnu/openblas-pthread` | `/opt/openblas-spacemit/lib` |
| 目标核心 | `RISCV64_GENERIC` | `x60` |
| 优化方向 | 通用 riscv64 OpenBLAS pthread 实现 | 面向 SpacemiT X60 的 RVV 优化实现 |
| 典型用途 | 兼容系统默认 BLAS/LAPACK 依赖 | 在 K1 上进行高性能矩阵计算和算法加速 |

本文后续主要通过相同的 BLAS 接口（如 `cblas_sgemm` / `cblas_dgemm`）对比 `libopenblas-pthread-dev` 与 `openblas-spacemit` 的性能差异。测试时仅切换头文件与链接库路径，并通过 `OPENBLAS_NUM_THREADS`、`taskset` 等方式控制线程数和 CPU 亲和性，从而观察 RVV 优化库在 K1 平台上的加速效果。



以下参考数据使用 `libopenblas-pthread-dev 0.3.26+ds-1`、`openblas-spacemit 0.3.32-1bb4`。两库的版本、目标核心和实现均不同，以下结果表示这两套已安装库在 K1 上的整体差异。

**blas_sgemm_check.cpp**

```cpp
// Test the installed BLAS ABI library by calling cblas_sgemm.
// This validates that the target BLAS library can be linked and used.

#include <algorithm>
#include <chrono>
#include <cmath>
#include <cstdlib>
#include <iomanip>
#include <iostream>
#include <string>
#include <vector>

#include <cblas.h>

namespace {

float value_for(int row, int col, int rows) {
  return static_cast<float>(((row + 1) * 17 + (col + 1) * 31 + rows) % 101) / 101.0f;
}

void fill_col_major(std::vector<float>& matrix, int rows, int cols) {
  for (int col = 0; col < cols; ++col) {
    for (int row = 0; row < rows; ++row) {
      matrix[row + col * rows] = value_for(row, col, rows);
    }
  }
}

std::vector<float> reference_gemm(const std::vector<float>& a, const std::vector<float>& b,
                                  int m, int n, int k, float alpha, float beta) {
  std::vector<float> c(static_cast<size_t>(m) * n, 1.0f);
  for (int col = 0; col < n; ++col) {
    for (int row = 0; row < m; ++row) {
      float acc = 0.0f;
      for (int inner = 0; inner < k; ++inner) {
        acc += a[row + inner * m] * b[inner + col * k];
      }
      c[row + col * m] = alpha * acc + beta * c[row + col * m];
    }
  }
  return c;
}

double max_abs_error(const std::vector<float>& x, const std::vector<float>& y) {
  double err = 0.0;
  for (size_t i = 0; i < x.size(); ++i) {
    err = std::max(err, std::abs(static_cast<double>(x[i]) - static_cast<double>(y[i])));
  }
  return err;
}

double checksum(const std::vector<float>& x) {
  double sum = 0.0;
  for (float v : x) sum += v;
  return sum;
}

}  // namespace

int main(int argc, char** argv) {
  int m = 512;
  int n = 512;
  int k = 512;
  int repeats = 20;

  if (argc > 1) m = std::atoi(argv[1]);
  if (argc > 2) n = std::atoi(argv[2]);
  if (argc > 3) k = std::atoi(argv[3]);
  if (argc > 4) repeats = std::atoi(argv[4]);

  if (m <= 0 || n <= 0 || k <= 0 || repeats <= 0) {
    std::cerr << "usage: " << argv[0] << " [m n k repeats]\n";
    return 2;
  }

  std::vector<float> a(static_cast<size_t>(m) * k);
  std::vector<float> b(static_cast<size_t>(k) * n);
  std::vector<float> c(static_cast<size_t>(m) * n, 1.0f);

  fill_col_major(a, m, k);
  fill_col_major(b, k, n);

  float alpha = 1.25f;
  float beta = 0.5f;
  int lda = m;
  int ldb = k;
  int ldc = m;

  const auto expected = reference_gemm(a, b, m, n, k, alpha, beta);

  cblas_sgemm(CblasColMajor, CblasNoTrans, CblasNoTrans, m, n, k, alpha, a.data(), lda, b.data(), ldb,
              beta, c.data(), ldc);

  const double err = max_abs_error(c, expected);
  const double tolerance = 1e-3 * static_cast<double>(k);

  std::cout << std::fixed << std::setprecision(6);
  std::cout << "BLAS symbol: cblas_sgemm\n";
  std::cout << "Problem: m=" << m << ", n=" << n << ", k=" << k << ", repeats=" << repeats << '\n';
  std::cout << "Correctness max_abs_error=" << err << ", tolerance=" << tolerance << '\n';
  std::cout << "Checksum=" << checksum(c) << '\n';

  if (err > tolerance) {
    std::cerr << "BLAS cblas_sgemm result: FAIL - result mismatch\n";
    return 1;
  }

  std::fill(c.begin(), c.end(), 1.0f);
  const auto start = std::chrono::steady_clock::now();
  for (int r = 0; r < repeats; ++r) {
    cblas_sgemm(CblasColMajor, CblasNoTrans, CblasNoTrans, m, n, k, alpha, a.data(), lda, b.data(), ldb,
                beta, c.data(), ldc);
  }
  const auto end = std::chrono::steady_clock::now();
  const double seconds = std::chrono::duration<double>(end - start).count();
  const double avg_seconds = seconds / repeats;
  const double gflops = (2.0 * m * n * k * repeats) / seconds / 1.0e9;

  std::cout << "Time seconds=" << seconds << '\n';
  std::cout << "Average time per SGEMM seconds=" << avg_seconds << '\n';
  std::cout << "Approx GFLOP/s=" << gflops << '\n';
  std::cout << "BLAS cblas_sgemm result: PASS - linked OpenBLAS and computed correctly.\n";
  return 0;
}
```

## 更多性能测试数据

以下参考数据使用前述 K1 环境，向量长度为 262144，矩阵大小为 512×512。

- 使用 `taskset -c` 限制可用 CPU：单核为 CPU 0，八核为 CPU 0–7；`OPENBLAS_NUM_THREADS` 与 `OMP_NUM_THREADS` 分别设置为 1 或 8。
- 每轮测试先预热 10 次，再连续执行 50 次取平均耗时；独立重复 10 轮，计算各项指标的均值和标准差。
- `mean` 表示 10 轮测试的均值，`sd` 为样本标准差，反映轮次间的波动。

[示例资源包](./assets/openblas-k1-examples.zip)提供全部 28 个算子的测试源码和 CSV 统计脚本 `summarize.py`，详细参数见包内 README。下载后，在 ZIP 所在目录执行：

```bash
unzip openblas-k1-examples.zip -d ~
cd ~/openblas-k1-examples/appendix
cmake -S . -B build_system -DCMAKE_BUILD_TYPE=Release
cmake --build build_system
cmake -S . -B build_spacemit -DCMAKE_BUILD_TYPE=Release -DOpenBLAS_DIR=/opt/openblas-spacemit/lib/cmake/openblas
cmake --build build_spacemit

# 单核，每个可执行程序都输出 28 个算子的 10 轮 CSV 数据
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 taskset -c 0 ./build_system/blas_suite 10 10 50
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 taskset -c 0 ./build_spacemit/blas_suite 10 10 50

# 八核
OPENBLAS_NUM_THREADS=8 OMP_NUM_THREADS=8 taskset -c 0-7 ./build_system/blas_suite 10 10 50
OPENBLAS_NUM_THREADS=8 OMP_NUM_THREADS=8 taskset -c 0-7 ./build_spacemit/blas_suite 10 10 50
```

两套库在单核、八核条件下均通过全部算子的正确性检查：37 规模完整校验；实际规模下 Level1/2 全量校验，Level3 固定抽查 64 个输出，参考结果由独立标量循环计算。校验独立比较一次调用，计时结束检查输出有限性。`speedup` 为系统库耗时除以 SpacemiT 库耗时，`improvement=(speedup-1)×100%`，均按相同轮次配对统计；COPY 的 `avg_gflops` 表示名义元素处理速率。

八核测试限制在 CPU 0–7，OpenBLAS 线程上限为 8，具体线程利用由库实现决定。两库版本和目标核心不同，结果表示当前二进制库的整体差异。性能受输入规模、缓存、实际频率及系统温控影响；以下数据保留系统默认温控与调频行为。

### 测试结果简要说明

- **BLAS Level-3（矩阵与矩阵运算）**：单核 SGEMM 平均耗时从 177.49 ms 降至 28.21 ms，加速比 6.29x；八核从 29.01 ms 降至 7.49 ms，加速比 3.88x。DGEMM 单核与八核的加速比分别为 2.11x、1.83x。
- **BLAS Level-1（向量运算）**：不同算子、精度和线程条件的收益各异。例如 SCOPY 单核与八核分别为 1.39x、1.54x。应用选型应结合自身的数据规模与算子占比。
- **BLAS Level-2（矩阵与向量运算）**：SGEMV 单核与八核的加速比分别为 3.78x、0.58x，DGEMV 分别为 2.35x、0.58x。两者单核均有提升，但八核均低于系统库；三角与带状算子的变化见下表。

表中 `speedup` 小于 1 或 `improvement` 为负数表示对比方案性能低于基准方案。上述八核 SGEMV、DGEMV 的结果说明，矩阵乘法的加速收益不能直接推广到矩阵与向量运算；应结合算子类型、输入规模、线程数和标准差判断。表中计时结果不能单独确定下降是否由内存带宽、线程调度或具体实现导致。

在上述 K1 测试条件下，`openblas-spacemit` 对 SGEMM、DGEMM 等矩阵乘法有明显加速效果。实际应用可优先评估这类计算密集型任务，并根据端到端耗时选择库和线程配置。
