# 重构说明与任务清单

## 1. 目标与边界

本次建立 `wj_dev` 的 K1 文档框架，供实习生继续逐页核对 SDK 和硬件行为。原第 1、2、3 节保留正文，原第 4、5 节合并为第 4 节“AI与算法”，原第 6 节调整为第 5 节“机器人开发”，原第 7 节保留正文并连续编号为第 6 节。

第 4 节的 4.1—4.7 和第 5 节的 5.1—5.6 对齐 K3；保留的 K1 扩展主题放在各章后部。K3 第 1、2、3、6、7 节没有整体套入 K1。

目录采用 K3 的数字前缀、中文名称、连字符、`index.md`、`sidebar_position` 和 `slug` 形式。链接随文件移动更新。网站上线前需要在网站项目配置重定向，本仓库仅提供迁移表。

## 2. 来源与覆盖原则

上游固定到 [docs-ros 5b94e7e](https://github.com/spacemit-com/docs-ros/tree/5b94e7e61e3be4bf00981fd74b7c9eba7595f4e1)，本仓库固定到 [K1 7e4cb6a](https://github.com/zyi952694-crypto/K1/tree/7e4cb6ac24b71c661db658fba6e2adb6e27a7d50)。逐页来源、哈希和目标位置见 [迁移对照](迁移对照.md) 与 [迁移清单](migration-map.json)。

1. 原第 1、2、3、7 节按本次约定保留正文；格式、编号和失效的文档锚点可修复。
2. 已有 K1 适配稿优先保留。本次保留实习生已验证重构的 ASR、TTS、VAD、声纹和目标检测 5 篇内容；仅修正元数据、导航格式和一处本机截图引用。
3. 同一能力有新旧说明时，先核对 SDK 代码、K1 target、依赖和接口。仅在 K1 兼容性成立后，用最新的正确内容覆盖旧说明；不能只按文件日期替换。
4. 在确认保留的章节范围内，K1 可运行但 K3 未提供的接口、模型和设备说明继续保留。不同接口分别注明软件环境，不把原有 Python/RDK 接口改写成新 SDK 接口。
5. K3 独有或尚未验证的能力，只保留目录及来源链接，不复制 K3 命令并声称 K1 支持。

按确认后的范围删除旧语音 Python 接口、模型开发与部署、预备知识章节；AI 框架集成、ROS2 视觉库及人机交互继续保留。旧 SLAM 文档同时覆盖 gmapping、slam_toolbox、cartographer，因此集中保留在“SLAM 建图”，对应 K3 分类页链接到其算法小节。

## 3. 实习生后续任务

| 顺序 | 工作 | 验收材料 |
| --- | --- | --- |
| 1 | 固定 K1 镜像、SDK 提交和 target；记录组件与依赖版本。 | K1 环境清单。 |
| 2 | 复核已有语音、目标检测 5 篇组件适配稿，并补齐目标检测实测结果图。 | 构建日志、运行日志、图片、命令与接口核对结果。 |
| 3 | 按待确认页面清单逐项检查 K3 SDK 的 K1 兼容代码。 | 每页明确“可直接复用 / 需适配 / K1 保留 / 不适用”，并附代码位置。 |
| 4 | 对兼容部分同步最新内容，保留 K1 特有参数和实现。 | 按页面拆分的可审阅变更、来源提交和差异说明。 |
| 5 | 回归 K1 原有工作流，检查本地链接、图片、导航和路由迁移。 | 文档检查通过；适用的本地与板端回归记录。 |

对“待确认”页面，应先记录组件路径、目标配置、系统依赖和 K1 差异，再填写构建、运行和验证结果。确认不适用时写明原因，避免将空白页当作已支持能力。
